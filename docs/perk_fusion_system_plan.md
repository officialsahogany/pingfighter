# 퍽 융합(Perk Fusion) 시스템 디자인 플랜

상태: 설계 확정(구현 전). 2026-07-09 Codex 설계 리뷰(5 findings) 반영본.
구현은 별도 `perk_fusion` 서브시스템으로 자른다 — 카탈로그에 융합 퍽
하나 추가하는 방식 금지 (리뷰 결론 수용).

관련 문서: `docs/character_skill_perk_checklist.md` (§4.4 텍스트 감사,
§4.5 모달 감사, §5 유효레벨), `docs/godot_runtime_traps.md` (연쇄 모달
입력가드, 퍽 모달 복귀 램프, 스탯 패널 row budget, per-frame 확률 롤),
`docs/dash_token_ringcore_slot_redesign_plan.md` (슬롯카운트 브리지).

## 1. 컨셉 요약

- 만렙(=base level가 max_level 도달) 퍽 2개 보유 시, 퍽 선택지에
  "융합" 카드가 확률 등장.
- 융합 선택 → 재료 2개 선택 → 확정 → 화면 중앙 융합 연출 → 결과 리빌.
- 결과는 3분기 랜덤:
  1. **융합 성공** — 두 퍽 능력치 그대로 합산.
  2. **부작용** — 합산은 되나 일부 옵션이 -10~-30% 감소(랜덤 1~2개),
     낮은 확률로 옵션 1개 삭제.
  3. **부산물** — 합산 + 융합 전용 특수 능력 1~3개 부여.
- 모든 결과에서 융합체는 남는다. **순손실 결과는 존재하지 않는다**
  (부작용도 "합산 + 슬롯 환급 - 일부 감소" = 융합 전보다 대체로 이득).
- 융합체는 슬롯 1칸만 점유 (2→1, 슬롯 1칸 환급).

시작 확률(밸런스 패스 대상, §10): 성공 55% / 부작용 25% / 부산물 20%.
부작용 내부 분배: 옵션 감소 80% / 옵션 삭제 20%.

## 2. 융합 후보 판정 + `fusion_class` 분류 (리뷰 Finding #2)

후보 판정 기준: **base level == max_level**. 초월자의 관 / 현자의 반지
등 유효레벨 버프는 후보 판정에 포함하지 않는다 (유효레벨 5는 후보 아님).

모든 카탈로그 엔트리는 `fusion_class`로 분류된다. 명시 필드 우선,
없으면 파생 규칙으로 결정하고, 카탈로그 전 엔트리가 분류되는지
스모크로 봉인한다.

| fusion_class | 파생 규칙 | 융합 후보 | 부작용 적용 |
|---|---|---|---|
| `numeric_passive` | max_level ≥ 2 수치 퍽 (기본값) | O | 감소 O / 삭제 O(다옵션일 때만) |
| `boolean_unique` | max_level == 1, 비신화, 비해금 (무중력화 등) | O | **면제** (감소·삭제 모두 불가) |
| `mythic_system` | `tree == "mythic"` (`effective_level_exempt`) | O | **면제** |
| `unlock` | 해금 퍽 (`unlock_*`, 스킬 슬롯 점유) | **X** | - |
| `instant` | `INSTANT_PERKS` (일회성) | **X** | - |
| `system_choice` | 링코어 강화 / 강화칩 / 확장(`common_expansion`) 등 슬롯·시스템 축 | **X** | - |

부작용 규칙 세부:

- 감소/삭제 대상 옵션은 **부작용 적용 가능(`numeric_passive`) 옵션
  풀에서만** 추첨한다. 신화·boolean 쪽 재료의 옵션은 건드리지 않는다.
- 재료 양쪽 모두 면제 분류라 부작용 적용 가능 옵션이 0개인 경우
  (신화×신화, 신화×무중력화 등), 부작용 결과는 **성공으로 대체**하고
  결과 로그에 "안정 융합"으로 표기한다.
- 삭제는 해당 재료 퍽의 옵션이 2개 이상 남을 때만 허용 — 삭제 후에도
  최소 1옵션은 반드시 보존한다.
- 감소 배율은 옵션별 독립 롤(-10~-30%), 소수점은 기존 수치 표기
  규칙에 맞춰 반올림.
- 삭제된 옵션은 데이터에서 제거하지 않고 `deleted` 마킹만 한다
  (툴팁에 취소선 "흉터" 표기, §7).

리뷰 지적 수용 근거: 신화 max_level 1 효과는 수치가 아니라 시스템
권한(부활 확률, 슬롯 +1, 유효레벨 +2)인 경우가 많아 "-30%"의 의미가
정의되지 않는다. 개별 신화마다 감소 의미를 정의하는 것은 v1 스코프
초과 → 일괄 면제가 안전하다.

## 3. 저장 모델: 원본 유지 + 융합 오버레이 레코드 (리뷰 Finding #1)

**결정: 원본 퍽 2개를 `runtime_skill_levels`에 그대로 유지하고,
별도 오너 모듈 `perk_fusion_state`가 융합 레코드를 오버레이로 보유한다.**

`fusion:A:B` 합성 ID로 원본을 대체하는 안은 기각한다. 근거:

- 효과 소비자 전원이 `runtime_skill_levels.get(perk_id)` /
  `get_runtime_skill_level()` 기반 — 합성 ID는 모든 소비자에 융합
  해석 로직을 강제한다 (수십 곳 침습 수정).
- 초월자의 관 유효레벨 +2가 원본 유지 모델에서는 **무수정으로 계속
  동작**한다 (융합 재료도 퍽별 레벨을 유지하므로).
- 만렙 퍽은 선택지 풀에서 이미 자연 제외되므로 풀 로직도 무수정.
- 세이브 rename 방어(파사드 리네임 방어 스모크 선례)와의 정합성.

융합 레코드 스키마(직렬화 단위):

```
{
  "fusion_id": "fusion_0",            # run 내 증가 인덱스
  "sources": ["lightweight", "luck"], # 재료 퍽 id 2개 (정렬 고정)
  "outcome": "success" | "side_effect" | "byproduct" | "stable",
  "option_penalties": { "lightweight": { "<option_key>": 0.8 } },
  "deleted_options": { "luck": ["<option_key>"] },
  "byproducts": ["overload_circuit", "static_field"],
}
```

레이어별 소비 규칙:

- **효과 값**: 페널티/삭제는 공용 값 헬퍼 경로(효과 수치를 공급하는
  `perk_conversion_values` / `get_effective_*` 계열)의 **단일 게이트웨이
  훅 1곳**에서 적용한다. 값 헬퍼를 우회해 상수를 직접 읽는 소비자는
  기존 체크리스트 위반이므로 구현 시 함께 교정한다 (ad-hoc 상수 재타이핑
  금지 규칙).
- **UI/슬롯**: 슬롯·TAB/ESC 그리드는 융합 레코드를 먼저 읽어, 재료
  2개를 융합체 1엔트리로 접어서 표시한다. 재료 퍽의 개별 표시는 숨긴다.
- **슬롯 점유 카운트**: `점유 = 보유 퍽 점유 합 - 융합 레코드 수`
  (레코드당 2→1 압축 = -1). 슬롯카운트 브리지(확장 퍽 / 링코어 예약
  경로)와의 정합 감사 필수.
- **세이브/로드**: 레코드는 자체 섹션으로 직렬화. 로드 시 sources의
  퍽 id 존재를 재검증하고, 없는 id가 있으면 레코드를 해체(원본 유지,
  레코드만 폐기)하는 자가 치유 경로를 둔다.
- **디버그 지급**: 재료 2개를 만렙 지급 + 레코드 생성 헬퍼 1개로 구성.
- **연쇄 융합 금지(v1)**: 융합체(레코드에 포함된 재료)는 재차 융합
  후보가 되지 않는다. 레코드는 항상 평평한 pair를 유지한다.

owner-field 스키마 트랩: 융합 상태를 owner에 sync하는 키가 생기면
`BattleSceneState.DEFAULT_VALUES` 선언 필수 (silent no-op 트랩).

## 4. 결과 롤 규칙

- 롤은 **확정 버튼 시점에 1회** 실행하고, 레코드를 즉시 커밋한 뒤
  연출을 재생한다. 연출은 결과를 알고 재생되는 표현일 뿐이며, 연출이
  중단(포커스 상실, 강제 종료)돼도 결과는 이미 저장돼 있다.
- per-frame 확률 롤 트랩 해당 없음(원샷 롤)이지만, 확률형 **부산물**의
  런타임 발동은 per-opportunity 롤 규칙(rolled-this-opportunity 락)을
  따른다.
- 표기 확률과 실제 롤 확률은 같은 상수를 읽는다 (표기-실제 분리 금지).

## 5. 부산물 풀 + 캡/중복 규칙 (리뷰 Finding #5)

설계 원칙: 기존 퍽은 단일 축 강화, 부산물은 **축과 축을 잇는 다리**
(크로스 시스템 트리거). 부여 개수: 1~3개 랜덤.

**중복 규칙(전역): 부산물 롤은 이미 보유한 부산물(모든 융합 레코드
합산)을 풀에서 제외하고 추첨한다.** 동일 부산물의 합산/최대값 문제를
원천 제거한다. 반복 트리거형 부산물은 캡 필드가 필수다.

일반 풀 (수치는 밸런스 패스 대상):

| id(가칭) | 이름 | 효과 | 캡 |
|---|---|---|---|
| `overload_circuit` | 과부하 회로 | 대쉬 사용 후 첫 타구 공속 +15% | 대쉬당 1회 (자연 캡) |
| `reverb` | 잔향 | 스킬 사용 후 3초 이동속도 +25% | 재발동 시 갱신(비중첩) |
| `golden_trajectory` | 황금 궤적 | 공 벽 반사마다 골드 +2 | **라운드당 상한** (예: +40) |
| `overflow` | 오버플로우 | 게이지 만충 시 초과 획득분 50% 골드 전환 | 라운드당 상한 |
| `static_field` | 정전기장 | 실점 직후 4초 보스 이속 -30% (`boss_slow_tiers.WEAK`) | 실점당 1회 (자연 캡) |
| `magnet_burst` | 자석 방출 | 액티브 아이템 사용 시 필드 스타포인트 즉시 흡수 | 사용당 1회 (자연 캡) |
| `recycle_protocol` | 재활용 프로토콜 | 실점 시 25% 확률 대쉬 토큰 전량 회복 | 실점당 1롤 (자연 캡) |
| `lingpet_resonance` | 링펫 공명 | 링펫 스킬 발동 시 게이지 +10 | 발동당 1회, 라운드당 상한 |
| `weather_adapt` | 날씨 적응 | 날씨 이벤트 중 이속·게이지 획득 +20% | 이벤트 지속 한정 (자연 캡) |

희귀 풀 (3개 부여 롤에서 1자리 확률 배정):

| id(가칭) | 이름 | 효과 | 비고 |
|---|---|---|---|
| `core_stabilize` | 융합핵 안정화 | 이 융합체 능력치는 이후 모든 감소·삭제 면역 | 방어 메타 |
| `limit_break` | 한계 돌파 | 이 융합체의 재료 퍽 2개에 유효레벨 +1 | 초월자의 관과 합산 (§5 유효레벨 체크리스트 준수) |
| `dual_catalyst` | 이중 촉매 | 다음 융합의 부산물 확률 +15% | 융합 연쇄 체이스 |
| `mutation_factor` | 변이 인자 | 융합체 옵션 1개가 스테이지마다 ±20% 재롤 | 재롤도 값 게이트웨이 경유 |
| `twin_roulette` | 쌍둥이 룰렛 | 라운드 시작 시 10% 확률 무작위 액티브 아이템 지급 | **스테이지당 최대 1회 지급** |

## 6. UI 플로우 상태 전이표 (리뷰 Finding #3)

전체 플로우는 **기존 퍽 선택 모달 세션 내부**에서 처리한다. 별도 공
정지 액터를 만들지 않는다 — 공 정지/복귀 램프는 기존 퍽 모달의 것을
그대로 쓰고, 복귀 안전 램프(상승 즉시 해제 규칙 포함,
`runtime_perk_resume_safety_release_smoke` 봉인)는 **플로우 전체가
끝난 뒤 1회만** 발화한다.

| 상태 | 화면 | 진입 | 이탈 |
|---|---|---|---|
| S0 | 퍽 선택지 3택 (융합 카드 포함) | 기존 퍽 모달 오픈 | 융합 카드 선택 → S1 / 일반 퍽 선택 → 기존 플로우 |
| S1 | 재료 선택 그리드 (만렙 후보만, 2개 선택) | S0 | 2개 선택 → S2 / **취소 → S0 완전 복귀** |
| S2 | 미리보기 + 확정 (합산 미리보기, 3분기 확률 표기) | S1 | 확정 → 롤+레코드 커밋 → S3 / 뒤로 → S1 |
| S3 | 융합 연출 (화면 중앙, 스킵 가능) | S2 | 연출 종료·스킵 → S4 |
| S4 | 결과 리빌 (성공/부작용/부산물 로그 + 융합체 카드) | S3 | 확인 → 모달 세션 종료 → 기존 복귀 램프 |

취소 불변식 (모두 스모크 대상):

- S1/S2 취소·뒤로는 **완전 no-op**: 레코드·레벨·소유권·스타포인트·
  보상 카운트·pending choice 모두 불변 (canceled slot-full swap
  no-op 선례와 동일 규칙).
- 취소 후 S0의 3택은 **소모되지 않고 그대로 재표시**된다 (융합 카드
  포함). 융합 카드가 선택지에서 소모되는 시점은 S2 확정뿐이다.
- 연쇄 모달 전환 프레임의 입력 이월 금지 — 연쇄 모달 입력가드
  (런타임 퍽 모듈화 Blocker#1) 패턴을 S0→S1→S2→S3→S4 전 전환에 적용.
- S3 진입 시점에 레코드는 이미 커밋됨 → S3/S4에서의 어떤 중단도
  결과를 잃지 않는다.
- 대기 중인 퍽 선택이 큐에 더 있는 경우(연속 레벨업), 융합 플로우
  종료 후 다음 선택지가 기존 큐 규칙대로 이어진다 (복귀 램프는 마지막
  선택 뒤에만 arm — 기존 규칙 유지).

융합 카드 등장 규칙: 만렙 페어(후보 2개 이상) 존재 시 선택지 롤에서
확률 등장(시작값 35%, 밸런스 패스 대상). force-include 아님. 통찰 /
메긴교르드의 추가 선택지와 자연 중첩 허용.

## 7. 툴팁 / 아이콘 정책 (리뷰 Finding #4)

**표시 정책: 요약 1줄 + 상세 2단 (스크롤·접기 없음).**

- 그리드/슬롯 셀: 합성 아이콘 + "융합체" 태그 + 요약 1줄
  ("경량화×행운 · 부산물 2").
- hover 툴팁: 퍽 툴팁 2단 분리 구조 재사용 —
  - 왼쪽(detail): 융합 결과 로그. 최대 3줄 (결과 분기 1줄 + 부작용/
    부산물 요약 2줄).
  - 오른쪽(stats): 재료 퍽별 섹션 헤더 + 옵션 레인 나열. 페널티 레인은
    빨간 수정치(원래값→현재값), 삭제 레인은 취소선(흉터), 부산물
    레인은 금색.
- **렌더 검증 기준 픽스처: 최악 조합 고정** — 다옵션 퍽 최대 레인
  (부메랑장인 5레인) × 다옵션 퍽(벽돌장인 3레인) + 부산물 3개 + 삭제
  1개 + 긴 조합 이름. 이 픽스처가 TAB / ESC / 승리 화면 / 선택 카드
  4경로 전부에서 잘림 없이 렌더되는 것을 스모크 + 픽셀 QA로 봉인한다
  (스탯 패널 row budget 트랩 / 공유 라인 버짓 클립 트랩 준수).
  줄 수가 넘치면 레인 압축(같은 퍽의 레인을 쉼표 연결)으로 대응하되,
  **조용한 드랍은 금지**한다.
- 텍스트 감사는 체크리스트 §4.4의 7경로 전부 + 비한국어 로케일
  (detail==stats 붕괴 가드 선례) 포함.

아이콘:

- **선택지 카드용 융합 아이콘 5종**: "뭉쳐진" 모티프 정적 아이콘,
  imagegen(리포 정책상 비-시트 = Gemini 경로) 생성. 융합은 발동형
  이벤트지만 `instant_*` 8프레임 시트 규칙 대상이 아닌 **정적 아이콘**
  으로 명시 확정. 카드 노출 시 5종 중 랜덤/순환.
- **융합체 결과 아이콘**: 재료 2개의 아이콘을 런타임 합성 (대각 분할
  + 융합 프레임 오버레이). N² 사전 생성 금지. 합성 결과는 `(size,
  active)` 캐시 규칙 준수 (핫패스 재합성 금지).

## 8. 슬라이스 분할 + 스모크 계획

| 슬라이스 | 내용 | 씰(스모크) |
|---|---|---|
| S1 | `fusion_class` 분류 + 후보 판정 + 레코드 스키마 + 세이브/로드 | 카탈로그 전 엔트리 분류 완전성 / 로드 자가 치유(없는 id 해체) / 라운드·스테이지 경계 생존 |
| S2 | 선택지 카드 등장 + 재료 선택 모달 + 상태 전이 | 취소 no-op(레벨·레코드·pending 불변) / 3택 비소모 재표시 / 입력가드 |
| S3 | 결과 롤 + 값 게이트웨이 훅(감소/삭제) + 슬롯 압축 카운트 | 페널티 반영 OUTCOME(게임플레이 수치) / 면제 분류 무손상 / 부작용 0-대상 시 성공 대체 / 슬롯 -1 |
| S4 | 부산물 런타임 배선 (풀·캡·중복 제외) | 캡 도달 후 미발동 / 중복 제외 롤 / per-opportunity 락 |
| S5 | 툴팁/아이콘/연출 | 최악 픽스처 렌더 봉인 + 픽셀 QA / 아이콘 합성 캐시 |

각 슬라이스는 반증검증(in-place 토글로 스모크 RED 재현) 필수.
S3 스모크는 플래그가 아니라 **실제 수치 결과**를 단언한다 (force-inject
스모크가 라이브 상호작용 회귀를 가리는 트랩 준수 — 후보 판정 →
카드 등장 → 확정까지 실 트리거 레그 1개 포함).
