## 0. 현행 `[확인]`

- **수련장·파계승·상점**은 `draw_tower_node_card()` 공용 카드 드로어를
  이미 쓴다(`f4adbea3b`). 카드 그리드까지는 왔다.
- **수호의 샘터**를 포함한 나머지 노드가 같은 계약을 쓰는지 확인하라.
- 사용자 판정은 "**아직 부족하다**"이다. 카드가 있다는 것과 게임형 UI 라는
  것은 다르다.

## 1. ★S1. 현행 감사와 설계 — 먼저, 구현 금지

- 노드 모달 **전 종류를 표로 뽑아라.** 각각 무엇을 쓰는지 파일:줄로 지명하라.
  - 공용 카드 드로어를 쓰는가, 글자 행인가
  - 마우스로 되는가, 키보드 전용인가
  - 호버 피드백이 있는가
  - 아트가 있는가
- ★**마우스 조작 가능 여부가 핵심이다.** 사용자가 명시했다. 현재 어느 노드가
  마우스로 안 되는지 전수 확인하라.
- **부족한 점을 구체적으로 지명하라.** "허접하다"를 그대로 옮기지 말고
  무엇이 없어서 그렇게 읽히는지 항목화하라.
- ★**설계안을 제시하고 멈춰라.** 대형 UI 개편은 승인 없이 착수하면
  통째로 반려될 위험이 크다.

## 2. 설계에 담을 것

- **카드 호버 연출.** 정지 카드가 "허접해" 보이는 가장 큰 원인이다.
  수련 카드 능력치 프리뷰(`b6742acd0`)가 선례다. 그 결을 확장하라.
- **선택·구매 피드백.** 눌렀을 때 무엇이 일어났는지 읽혀야 한다.
- **재화 표시.** 구매 후 잔액이 어떻게 변하는지 그 자리에서 보여라.
- **노드별 정체성.** 상점·수련장·파계승·샘터가 같은 껍데기면 장소감이 없다.
  비전투 배경 4종이 이미 있다(`2944e9326`). 모달이 그것과 이어지는가.
- ★**마우스 우선.** 클릭·호버로 전부 되게 하고 키보드는 보조로 남겨라.

## 3. 계약

- ★**공용 드로어를 갈라 놓지 마라.** 네 화면이 같은 드로어를 쓰는 것이
  `f4adbea3b` 의 성과다. 개선도 공용으로 하라.
- ★**GRT-022**: `build_layout` 은 그리기와 히트테스트 양쪽을 먹인다.
  요소를 더하면 `get_card_rects` 계열에도 같은 플래그를 흘려라.
  **반증은 카드 중심점이 아니라 상단 모서리로 재라.**
- ★**GRT-021**: 설명이 길면 드로어가 조용히 행을 버린다. 최장 문구에서
  실제 append 된 행 수를 단언하라.
- ★**GRT-043**: 호버 연출은 호버 중에만 돈다. 평시 드로 비용이 늘면 안 된다.
- ★**GRT-058**: 물리차단 모달의 개폐 계약을 지켜라. 새 진입점은 형제 모달의
  훅을 자동 상속하지 않는다.
- 모달이 **플레이필드를 침범하지 마라.**
- 한국어 카피에 엠대시(—) 금지. 신규 문구는 7 로케일 등재.
- 아트가 필요하면 `.claude/skills/ui-hud-generation/SKILL.md` 를 읽고
  **후보 제시 후 멈춰라.** 절차 도형으로 대체하지 마라.
