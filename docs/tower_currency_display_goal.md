## 0. Fable이 미리 확인한 현행 `[확인]`

### 0-1. 재화 표시면은 최소 넷이다

| 표시면 | 위치 | 현행 |
|---|---|---|
| 노드 모달 잔액 뱃지 | `tower_ascent_flow_renderer.gd:1267,1273` | 무혼·골드 뱃지 2개 |
| 뱃지 드로어 | 같은 파일 `:1312` `_draw_balance_badge` | `Color(PAPER_DEEP, 0.62)` **채운 사각형** |
| 보상 픽 잔액 | `tower_reward_pick_state.gd:259,351,535` | 텍스트 |
| 결산 요약 | `tower_ascent_settlement_state.gd:151` | ★**하드코딩** |

**단일 검색어로 다 찾았다고 단정하지 마라.** `gold`, `골드`, `muhon`, `무혼`,
`balance`, `currency`를 교차하고 `.tscn`·`.tres`도 훑어라.

### 0-2. 결산 요약이 다국어를 우회한다 `[확인]`

`tower_ascent_settlement_state.gd:151`이 이렇다.

```gdscript
rows.append("무혼 %d · 골드 %d" % [muhon, gold])
```

카탈로그를 타지 않는다. 한국어 외 언어에서 이 줄만 한글로 남는다.
**이번 작업에서 카탈로그 경로로 옮겨라.**

### 0-3. "골드"가 두 종류다 ★범위 결정

- **탑 런 재화** `gold` — 이번 대상이다.
- **퍽 골드 / 무공 골드** — 별개 재화다.
  `character_info_overlay_header_presenter.gd:39`가 "무공 골드"를 만들고
  `language_settings.gd:957~977`이 6개 언어로 번역한다.

**이번 범위는 탑 런 재화뿐이다.** 퍽 골드까지 금화로 바꾸면 서로 다른 두
재화가 같은 이름이 된다.

다만 `character_info_overlay_header_presenter.gd:144` 주석은 그 표시줄이
**의도적으로 제거됐다**고 적고 있는데 `:39`는 아직 문자열을 만든다.
**실제 플레이어 노출 여부를 확인하고 보고서에 적어라.** 노출되지 않으면
그대로 두고, 노출되면 별도 항목으로 보고만 하라. 고치지 마라.

## 2. 슬라이스별 계약

### S1. 표시면 전수 조사

코드를 고치기 전에 **재화가 화면에 그려지는 모든 지점**을 파일:줄로 나열하라.
§0-1의 넷은 시작점일 뿐이다. 보상 픽, 상점, 수호의 샘터, 수련장, 파계승,
결산, 노드 모달, 지도 오버레이를 각각 확인하라.

조사 결과를 보고서 표로 남기고, 그 표가 S2~S4의 작업 목록이 된다.

### S2. "골드" → "금화"

- 정본은 `tower_ascent_node_modal_localization.gd`의 `TEXT_BY_LOCALE`이다.
  `KEY_BALANCE_GOLD`, `KEY_COST_GOLD`, `KEY_INSUFFICIENT_GOLD` 세 키를
  **모든 로케일 블록에서** 갱신하라. 한국어만 바꾸고 끝내지 마라.
- 한국어는 `금화`. 다른 언어는 기존 번역을 유지하되 한국어 표기 변경에
  맞춰 자연스러운지 확인하라(영어 `Gold`는 그대로가 맞다).
- **`tower_ascent_settlement_state.gd:151`의 하드코딩을 카탈로그 경로로
  옮겨라.** 새 키를 만들고 모든 로케일에 등재한다.
- ⚠ **내부 식별자 `gold`는 호환 식별자다. 절대 바꾸지 마라.** 저장 키,
  딕셔너리 키, 함수명, 상수명 전부 유지한다. 표시 문자열만 바꾼다.
- ⚠ 한국어 카피에 엠대시(—)를 쓰지 마라. 멈춤은 마침표나 쉼표다.

### S3. 잔액 레이아웃 정리

사용자 요구는 **가로 정렬 + 둘러싼 테두리 박스 제거**다.

- `_draw_balance_badge`(`:1312`)의 `Color(PAPER_DEEP, 0.62)` 채움 사각형이
  그 "박스"다. 제거하거나 훨씬 약한 표현으로 바꿔라.
- 아이콘과 수치가 한 줄로 붙는 형태로 간다. 무혼 뱃지(190,242,176,38)와
  골드 뱃지(394,242,176,38)의 좌표·폭을 재산출하라.
- ★**GRT-022**: 이 뱃지가 클릭 대상이거나 히트테스트에 쓰인다면 그린 자리와
  클릭 자리가 갈라진다. 소비자를 먼저 확인하고, 반증은 **뱃지 상단 모서리**로
  재라. 중심점으로 재면 밀림이 통과한다.
- 배경을 없애면 대비가 떨어질 수 있다. **어두운 배경 위와 밝은 배경 위**
  양쪽에서 픽셀로 가독성을 확인하라.
- 재화 아이콘이 필요하면 **기존 자산을 먼저 찾아라.** 없으면 신규 생성 대신
  보고하고 멈춰라. 이번 목표는 아트 생성이 아니다.

### S4. 보상 화면 무혼 표시 확대

사용자 요구: `무혼 아이콘 : 7개` 형태로 폰트를 키워 가독성을 높인다.

- 대상은 **보스 클리어 후 보상 화면**의 보유 무혼 표시다.
  `tower_reward_pick_state.gd` 계열이 유력하나 S1 조사로 확정하라.
- 폰트 크기를 키울 때 ★**GRT-021**을 확인하라. 행 예산을 넘기면 드로어가
  조용히 행을 버린다. 늘린 크기에서 실제 append된 행 수를 단언하라.
- 스케일 파생값이 있으면 리터럴을 새 리터럴로 바꾸지 말고 기준값에서
  파생시켜라(GRT-054).

### S5. 용어 금지 씰

`godot/tests/ingame_paddle_term_ban_smoke.gd`가 선례다. 같은 형태로
**탑 표시면에 `골드`가 다시 등장하면 RED**가 되는 씰을 만들어라.

- 대상은 플레이어 노출 문자열이다. 내부 식별자 `gold`는 제외해야 한다.
  그 구분을 씰이 정확히 하는지 반증 레그로 확인하라.
- 퍽 골드/무공 골드는 별개 재화이므로 금지 대상에서 제외한다. 그 예외를
  씰에 명시하라.

## 3. 규율

- 슬라이스마다 헝크 분리 커밋 1개. 각 슬라이스는 **단독으로 씰 GREEN**이어야
  한다.

  `godot/tools/run_pre_push_checks.ps1` **두 리터럴 목록에 동시 등재**한다.
  ⚠ **실패하는 씰을 그 목록에 넣지 마라.** 필수 통과 목록이다.
- 통과 판정은 배치 종단선 `All Godot smoke tests passed.` + `SCRIPT ERROR` 0건.
- 로그 백업 선행. 표준 래퍼 `-AllowDuringPlay`. 푸시 금지.
- ★**통합하지 마라.** 브랜치에 두고 보고한 뒤 지시를 기다려라.
