## 1. 한 줄 정체성

세린이 상대 진영으로 담을 넘어 잠입해, **자기 바닥을 비워둔 채** 보스 옆에서
한 수를 노리고 즉시 빠져나오는 도박형 초식.

기존 바이퍼 초식과의 차별점은 **체류 중 플레이어가 조작권을 갖는다**는 것이다.
다른 초식은 전부 발동 즉시 스크립트대로 끝난다.

### 1.1. 독영절맥(`nerve_strike`)과의 개념 중첩 — 인지하고 진행

`nerve_strike`는 이미 "상대의 배후로 빠르게 날아가 등 뒤에서 베어 혼란 부여"다.
"보스 뒤로 가서 벤다"는 그림이 겹친다. 다만 아래로 구분된다:

| | 독영절맥 | 월담야습 |
|---|---|---|
| 진입 조건 | 블레이드 계열 후 착지 전(콤보 종속) | 단독 발동 |
| 조작 | 없음(원샷 스크립트) | 체류 중 좌우 이동 + 분기 선택 |
| CC | 혼란 | 둔화 2단계 / 스턴+넉백 |
| 리스크 | 없음 | 체류 중 바닥 무방비 |

구분은 충분하다고 판단해 진행한다. 다만 **연출 언어는 반드시 갈라야 한다** —
독영절맥이 "등 뒤 순간이동 참격"이면 월담야습은 "담을 넘는 잠행 → 체류 → 이탈"의
호흡이 보여야 하고, 이펙트 색/모션이 겹치면 플레이어가 같은 기술로 읽는다.

## 2. 상태 머신

```
IDLE
 └─(RMB, 진입 게이트 통과, 기력 180 일괄 차감)→ INFILTRATE_IN
      │   진입 X 저장 / 도약 트윈 / 트윈 시작 프레임부터 무충돌
      └→ INFILTRATING  [보스 Y 고정 / 좌우 이동만 / 무충돌 / 반투명 / 공 이동배율 0.5]
           ├─(LMB, 추가 소모 없음)→ SLASH(스윙 시트) → BLADE_FLIGHT(검기 비행·판정) → RETURN
           ├─(RMB, 추가 소모 없음)→ FUSE (0.7초, 좌우 이동 유지) → BLAST → 판정 → RETURN
           ├─(공 소유/프리즈 신규 개시)→ RETURN (빈손)
           └─(실점)→ 라운드 리셋이 강제 RETURN
                └→ RETURN → 정상 공격은 공 도달 예상 X / 강제귀환은 저장한 진입 X로 하강 → IDLE
                              [쿨 40초 기산 시작]
```

### 2.1. INFILTRATE_IN / RETURN 파라미터

rev1은 "짧은 도약"으로만 적어 구현 불가였다.

**확정:**
- 도착 X = **진입 X 그대로**(수평 이동 없음), 무충돌 개시 = **트윈 시작 프레임**.
- 정상 참격·폭발 뒤 귀환 X = **귀환 시작 프레임에서 계산한 공의 플레이어 충돌선
  도달 예상 X에 패들 중심 정렬**(rev10 사용자 확정). 공 속도와 좌우 벽 반사, 공 크기를
  반영한다. 귀환 중 공을 계속 추적하면 포물선이 꺾이므로 목표는 한 번만 스냅샷하고,
  패들 전체가 플레이필드 안에 남도록 좌우 경계를 clamp한다.
- 공 소유·프리즈 등 상태 기반 **강제귀환 X는 저장한 진입 X**를 유지한다. 공 좌표가
  없을 때도 같은 진입 X로 폴백해 안전 복귀 계약을 보존한다.
- 귀환 트윈 중 무충돌 유지, 해제는 **착지 프레임** + `player_collision_cooldown` 재무장.

**미확정:** 진입/귀환 트윈 시간(권고 0.18~0.25초), 궤적(권고: 담을 넘는 포물선 —
이름과 일치).

### 2.2. 시간 상한을 두지 않는 근거와 그 구멍

사용자 결정: **밸런스 목적의 지속 상한은 두지 않는다.** 늑장을 부리면 공을 못 막고
실점하므로 자연 처벌이 성립한다는 논리이며 타당하다.

단, 이 저장소에는 **"공이 반드시 내려온다"가 성립하지 않는 창**이 있다:

- `skip_ball_motion_step`을 세우는 모듈 **25개** — stage3 쿠로미 먹기, stage5 홍련
  인페르노, stage6 테트리서, stage7 아카무, stage8 미노타우로스, 포세이돈 캡처,
  혼천흑창 블랙홀, 링펫 스킬 다수, 스매셔 고스트샷/휠 등.
- `ball_vel`을 0으로 만드는 프리즈 액터 — 스톱워치, 스마트폰, 야차맨, 오딘의 눈,
  뿔딸기 변신, 퍽 모달 재개 램프.
- 서브 대기 구간.

**해결 = 시간이 아니라 상태로 막는다.** rev1의 "8초 페일세이프"는 폐기한다
(사용자가 확정한 "상한 없음"과 정면으로 모순되고, 승인받지도 않은 수치였다).

- **(a) 진입 게이트** — `ball_unavailable`이면 **진입 차단**(기력 미소모, 쿨 미기산).
- **(b) 체류 중 신규 개시 시 즉시 빈손 귀환** — 진입은 정상이었는데 체류 중 보스가
  공 소유 스킬을 쓰거나 프리즈가 걸리면 **그 프레임에 귀환**. 이러면 시간 상한 없이도
  무위험 체류가 원천 차단된다.
- **(c) 모달 일시정지 창에서 타이머 동결** — `battle_frame_flow_controller`에는
  `update_ball`을 건너뛰고 `update_effects`만 도는 구간이 있다: **신화 획득 시네마틱
  `:97`, 판도라, 스코어보드**. 상태 머신을 **볼 패스에서만 틱**하거나, 이펙트 패스면
  모달 중 FUSE·스윙·검기 타이머를 동결한다. 혼천흑창이 이 트랩으로 영구 소프트락이 났다.

  ⚠️**사이코볼 히트스톱(`:80`)과 쿠로미 각성(`:70`)은 이 목록에서 제외한다.**
  같은 "update_ball 스킵" 형태지만 UI 모달이 아니라 **게임플레이 홀드**라,
  타이머 동결 대상이 아니라 **(b) 강제귀환 대상**이다. 둘을 섞으면 잠입이 히트스톱
  동안 동결된 채 살아남아 히트스톱 종료 후 아무 일 없이 이어진다.

#### `ball_unavailable` 판정 — `ball_vel ≈ 0`은 정본이 아니다

`ball_update_controller.gd:34~49`에는 `ball_active` 검사보다 **먼저** 도는 조기 반환이
다섯 갈래 있고, **속도를 0으로 만드는 것은 그중 하나뿐**이다:

| 분기 | 위치 | `ball_vel` |
|---|---|---|
| stage3 사이코볼 히트스톱 | `:34` | **유지** |
| 파워 스매싱 프리즈 | `:37` | **유지** |
| 바이퍼 DMK / 독영절맥 프리즈 | `:41` | **유지** |
| 스톱워치 / 퍽 모달 재개 프리즈 | `:44` | ZERO |
| `ball_active == false` | `:48` | — |

따라서 rev2의 "`ball_vel` 크기가 사실상 0" 테스트는 **프리즈 4종 중 3종을 놓친다.**
`ball_active` + 서브 대기 + `skip_ball_motion_step`(공 소유) + 명시 프리즈 플래그를
묶은 **공통 `ball_unavailable` 술어**를 만들고 진입 게이트와 강제귀환이 **같은 술어**를
읽는다. 새 프리즈가 추가되면 이 술어 한 곳만 늘린다.

#### 강제귀환 관측 지점 — **두 곳**이 필요하다

프레임 순서는 `update_player_control(:102)` → `update_boss_ai` → 공 업데이트다.
보스 AI나 공 소유 모듈이 **그 프레임에** 홀드를 시작하면 플레이어 제어에서만 검사할
경우 놓친다. 그래서 관측을 공 패스로 내리는데, **조기 반환 직전 하나만으로는
부족하다.**

**관측점 A — 공 패스 조기 반환 직전.** 진입 시점부터 이미 서 있던 조건과, 이전
프레임에 커밋된 홀드를 잡는다.

**관측점 B — `step_motion()` 직후(보스 패들 후처리로 새 프리즈가 커밋된 뒤).**
A만 두면 **영구 누락**이 생긴다. 사이코볼 히트스톱의 실경로:

| 순서 | 위치 | 상태 |
|---|---|---|
| 1 | `ball_update_controller.gd:34` 히트스톱 검사 | 아직 **false** → 통과 |
| 2 | `step_motion()` 보스 패들 반사 → `paddle_bounce_boss_post_hit_handler.gd:67` | |
| 3 | `stage3_boss_skill_state.register_boss_hit(:98)` → `_activate_overdrive` | **여기서 켜짐** |
| 4 | 다음 프레임 `battle_frame_flow_controller.gd:80` | `update_ball` **자체를 건너뜀** |
| 5 | 히트스톱 종료 | `ball_unavailable` 다시 false |

발동 프레임엔 검사를 이미 지났고, 다음 프레임엔 공 패스가 호출되지 않으며, 끝난
뒤엔 조건이 사라진다 — 한 프레임 늦는 게 아니라 **관측 창이 존재하지 않는다.**

**일반 규칙:** (a) `step_motion()`의 보스 후처리에서 커밋될 수 있고 (b) 커밋 후
바깥 프레임 플로가 `update_ball`을 건너뛰게 만드는 상태는 전부 A에게 보이지 않는다.
확인된 사례 = 사이코볼 히트스톱. **쿠로미 각성**(`:70~78`)도 같은 형태로
`update_ball`을 건너뛰므로 커밋 경로를 감사할 것. 새 보스 스킬이 이 형태를 띠면
관측점 B에 자동으로 걸리도록 B는 **특정 플래그가 아니라 공통 `ball_unavailable`
술어**를 읽어야 한다.

⚠️**B의 술어는 라이브 상태를 읽어야 한다.** 업데이트 시작 시점에 만들어진
`frame_context` 복사본을 읽으면 커밋이 그 복사본에 반영되지 않아 B가 A와 똑같이
장님이 된다. 기존 판정도 정확히 그 형태다 —
`ball_update_controller._is_stage3_psychoball_hitstop_active(:172)`는 `context`의
불리언이 아니라 **`deps`의 상태 객체에서 `is_psychoball_hitstop_active()`를 직접
호출**한다. B도 같은 방식으로 커밋 후 라이브 `deps`/state를 조회할 것.
씰 7(e)가 이 실수까지 RED로 잡는다.

**관측 책임 분담 확인** — stage3 사이코볼의 나머지 두 개시 경로는 이미 덮인다:
- 점수 이벤트 경로 `maybe_start()`(`stage3_boss_skill_state.gd:112`) → §4.5 라운드
  정규화 계약이 담당
- 일반 보스 갱신 `maybe_start()`(`stage3_boss_skill_update_coordinator.gd:55`) →
  보스 AI 뒤에 공 업데이트가 이어지므로 **관측점 A**가 담당

#### 강제귀환 시 기력 계약 (rev11 단일 차감)

월담야습은 진입이 성립하는 순간 기력 180을 한 번만 소모한다. INFILTRATING,
SLASH / BLADE_FLIGHT, FUSE 어느 단계에서 강제귀환해도 추가 차감이나 환불은 없다.
어느 경우든 쿨 40초는 정상 기산한다.

### 3.1. 발동 시 180 일괄 차감 — rev11

진입 게이트는 기력 180 이상을 요구하고, 진입이 커밋되는 순간 180을 한 번만
차감한다. 그 결과 남은 기력이 0이어도 체류 중 참격과 폭발을 모두 선택할 수 있다.

| 발동 시점 기력 | 진입 | 사용 가능 분기 |
|---|---|---|
| ~179 | **차단** | — |
| 180~ | 허용, 즉시 180 차감 | 참격 / 폭발 모두 |

- 오브 HUD 비용과 스킬 데이터는 실제 발동 차감액인 **180**을 표시한다.
- 컨트롤 힌트는 참격·폭발에 **추가 소모 없음**을 명시한다.
- 강제귀환, 헛참, 폭발 FUSE 중 취소 모두 추가 차감이나 환불을 만들지 않는다.

### 3.2. 폭발 딜레이 중 이동을 유지하는 이유

보스 일반 최대속도는 6.3px/frame이다. 0.7초(42프레임)면 **최대 약 265px** — 화면
폭 760px의 3분의 1이다. 시전 경직을 걸면 보스가 ±50px 범위를 쉽게 빠져나간다.
참격 후 즉시 귀환이라 "둔화 걸고 폭발" 콤보도 불가능하므로, 경직안은
분기 자체를 죽은 선택지로 만든다.

이동을 유지하면 **0.7초 동안 심지에 불을 붙인 채 도망치는 보스를 쫓아 붙는** 그림이
되고, 그동안 자기 바닥은 계속 비어 있다. 이게 이 초식의 하이라이트다.

## 4. 반드시 지켜야 할 런타임 계약

### 4.1. 무충돌의 범위 — 패들 바운스만, 바닥 세이브는 살린다

체류 중 패들이 보스 Y에 있으면서 충돌이 살아 있으면 게임이 부서진다 — 보스가 친 공을
발사 직후 즉시 되받아치거나(보스 반응 불가) 보스 서브를 몸으로 막는다. **진입 트윈
시작부터 귀환 착지까지 무충돌**이며, 착지 프레임에 `player_collision_cooldown`
**재무장 필수**. 빠뜨리면 복귀 즉시 비정상 각도로 튄다.

**단, 끄는 것은 플레이어 패들 바운스 하나뿐이다.** 사용자 확정: 체류 중에도
홀리베리어·링펫 가드 등 **바닥 세이브는 정상 작동한다.**

- 이 초식은 공을 소유하지 않으므로(`skip_ball_motion_step`을 세우지 않음)
  `step_motion()`이 정상 실행되고, 패들 검사 **뒤에도** `check_holy_barrier` /
  `check_horn_strawberry_field` / 브릭월 / 월계수 잎 방패 / 역경의 갑주까지 진행한다.
  즉 "작동"이 기본값이고, 위험은 무충돌을 **넓게** 구현했을 때 이 계층까지 죽는 것이다.
- 씰로 봉인한다(§7-11). 홍련 인페르노 × 홀리베리어 손실이 정확히 이 계층이
  통째로 건너뛰어져 생긴 사고다.

#### 게이트 위치는 기본 플레이어 패들 rect **하나**

`_resolve_player_collision_result()`(`ball_motion_collision_detector.gd:118`)는 순서대로
세 가지를 본다:

1. 기본 패들 rect (`:121`) ← **여기만 끈다**
2. 토르 방패 rect (`:127`)
3. **바이퍼 쌍영분신 클론 rects** (`:137`)

`check_paddles()` 전체나 `_resolve_player_collision_result()` 전체를 막으면 2·3번이
같이 죽는다. 특히 **3번은 같은 캐릭터(바이퍼)의 초식**이라 가정이 아니라 실제로
동시 성립한다 — 쌍영분신을 깔아두고 월담야습으로 잠입하는 빌드가 자연스럽다.
분신은 플레이어 본체가 아니므로 **체류 중에도 계속 공을 가드해야 한다.**

**동반 확인 — "플레이어가 막을 수 있나" 소비자는 둘이다.** 체류 중 패들 X가 여전히
추적되면 위에 떠 있는 무충돌 패들을 "막을 수 있다"로 오판한다. 그런데 이 질문을 하는
곳이 **서로 다른 계층에 두 곳** 있다:

| 소비자 | 위치 | 역할 |
|---|---|---|
| 링크포트 비상 디스패치 | `lingpet_ring_dash_state.gd:200` `_player_can_block` | 링크포트를 **보낼지** |
| 수호령 몸통 접촉 | `lingpet_egg_runtime.gd:3048` `can_player_block` | 실제로 **튕길지** |

한쪽만 고치면 "링크포트는 발동했는데 접촉이 다시 억제되어 공이 그냥 지나간다"가 된다.
→ 공통 **`player_guard_available = false`** 계약을 두고 두 소비자가 함께 읽는다.
⚠️`player_pos`를 가짜로 옮겨 우회하지 말 것 — 렌더·HUD 앵커·타 스킬이 전부 오염된다.
체류 중 비상지원이 발동하는 것이 정답이다(플레이어가 실제로 못 막는 게 맞으므로).
링크포트 이중수비 사례의 정확한 역방향이다.

### 4.2. 공 감속은 `ball_vel` 크기를 건드리지 않는다 (rev1 정정)

rev1은 "`bounce()` 단일 지점 원속 복원"을 인용했으나 **오적용이었다.** 그 계약들은
수명이 다르다:

- `perk_resume_original_ball_vel` 복원 = "플레이어가 받아친 **그 한 번의 타격**"
- `_restore_void_phantom_suppressed_speed` = "**보스가 가드할 때까지**"의 일회 소비
  (`paddle_bounce_controller.gd:237`)

월담야습의 수명은 "체류 구간"이라 둘 다 아니다. `bounce()`에서 복원하면 체류 중 보스
반사가 있을 때 너무 일찍 풀리고, 반사가 없으면 귀환 후까지 샌다.

**더 심각한 문제**: `get_initial_speed`가 들어오는 크기를 그대로 나가는 크기로 쓰기
때문에(허공환영 주석 `paddle_bounce_controller.gd:240-242`가 명시), 체류 중 보스가
눌린 공을 반사하면 **그 반사가 눌린 채 확정되고 귀환 후 랠리 전체가 영구히 느려진다.**

→ **`ball_vel`의 크기를 아예 수정하지 않는다.** 저장 속도는 원본 그대로 두고,
**이동 스텝 시점에만 0.5 배율**을 곱한다. 그러면 `ball_vel`을 읽는 모든 소비자
(스킬 target/original 시딩, 보스 카운터 복원, 랠리 골드, 반사 계산)가 오염되지 않고,
귀환 시 배율만 떼면 같은 프레임에 원복된다.

- 배율 제거 지점: **모든 RETURN 경로 + 실점 + §4.5 리셋 3경로**, 전부 같은 프레임.
- 확인 필요: 보스 AI 예측이 `ball_vel`을 적분하므로, 배율을 예측에도 먹일지
  (정확) 안 먹일지(보스가 약간 성급) 결정해야 한다. 권고는 **먹인다**.
- 이동 스텝 훅의 정확한 위치는 구현 시 확정(`ball_vel * delta * 60` 스텝 지점).

### 4.3. 스턴·넉백은 공유 status 경로 (rev1 정정)

rev1은 `start_paddle_hit_knockback` + `suppress_paddle_hit_knockback`을 지정했으나
**근거 없는 인용이었다.** 폭발은 패들 타구 이벤트가 아니고, 애초에 체류 중 플레이어
패들은 무충돌이라 같은 프레임에 덮어쓸 일반 패들 넉백 자체가 발생하지 않는다.

**정본 = `status_effect_state.apply_status("boss", "stun", duration_frames, data,
source)`** — 이게 실제 보스 AI 소비 경로다. 넉백을 함께 얹는 캐노니컬 패턴은
`commando_firearm_hit_result_state._apply_runtime_stun_result(:256)`: 히트 프로파일에서
넉백 속도를 산출 → 결과 dict에 실음 → 같은 자리에서 `apply_status`. 이 형태를 따른다.

둔화도 같은 경로를 쓰되 배율 데이터는 `BossSlowTiers.MEDIUM`(0.55)이다
(`TIER_MEDIUM`은 티어 인덱스 2 — 소비자가 요구하는 쪽을 확인해서 넣을 것).
새 둔화 소스는 `_apply_common_boss_slow_effects()` 안에만 추가한다.

### 4.4. 명중 판정은 보스 중심점 X 거리

폭발 ±50px, 검기 최대 사거리 360px 모두 **보스 중심점 기준 X 거리**로 확정한다.
사각형 접촉으로 두면 시각 범위가 보스 rect 가장자리에 스치는 것만으로 CC가 들어간다 —
[`character_skill_perk_checklist.md` §6](character_skill_perk_checklist.md#6-actual-gameplay-effect-wiring)의
hit-primitive 계약이 정확히 이 경우다.

씰에 **경계값 레그**(50 / 51, 360 / 361)와 **rect 가장자리만 닿는 반례**를 반드시
넣는다. 검기는 프레임당 이동량이 커서 **스윕 판정**이 추가로 필요하다 — §10.3.

### 4.5. 상태 정리는 단일 메서드 + 3곳 호출

사용자 결정 "실점 시 잠입 해제 → 다음 라운드 원위치"는 **라운드 종료 경로에만 걸면
샌다.** 매치 포인트에서 잠입 중 실점하면 결과/게임종료 경로로 빠지고, 잠입 상태가
살아서 다음 판 스테이지 1에 반투명 패들이 보스 옆에 뜬다(홍련·친구두더지 전례).

→ 정리 메서드 **하나**(`viper_wall_leap_state.reset()`)를 만들고
**라운드 종료 / 결과·게임종료 / 스테이지 이탈 3곳 전부**에서 호출한다.

정규화: 패들 Y 바닥 복귀, 무충돌 해제, 이동배율 제거, 대쉬 금지 해제, facing·참격 창,
FUSE 타이머, 발동 비용 기록, 렌더 알파, 저장한 진입 X,
**검기 투사체 · 스윙 애니메이션 클럭 · 페이싱 래치**(§10).

### 4.6. 대쉬 금지의 경계 케이스

- 진입 시점에 이미 대쉬 비행 중이면 **진입 차단**(사용자 확정). 대쉬로 도망 못 간다는
  규칙과 일관되고 구현도 단순하다. 기력 미소모·쿨 미기산으로 진입 게이트와 동일 처리.
- 체류 중 대쉬 입력은 **토큰 소모 없이 무시**.
- 링펫 링크포트의 "커밋된 대쉬 투영" 판정은 체류 중 꺼야 한다.

## 5. 입력 채널 — 기존 계약 재사용 + 탑승 소유권 중재 (rev1 전면 정정)

rev1은 "우클릭에 기존 소비자가 없다"고 단정했다. **틀렸다.** 존재하지 않는 키 이름
(`mouse_right_just_pressed`)으로 grep해 얻은 0건을 부정 증거로 쓴 오류다.

### 5.1. 사실관계

| 항목 | 실제 |
|---|---|
| RMB 정본 계약 | **`secondary_action_pressed` / `secondary_action_just_pressed`** (`smasher_input_reader.gd:52-53`) |
| 락 프록시 | `player_skill_lock_input_proxy.gd:61-62`, `stage3_curse_control_input_proxy.gd:79-80`가 이미 이 키를 통과시킨다 |
| 바이퍼 리더 | `viper_input_reader.gd`에 **없음** → 스매셔와 동일하게 신설 |
| 기존 RMB 소비자 | **방망깨비(온이마루) 탑승 토글** — 맨 우클릭 (`lingpet_mount_state.gd:6`) |
| 기존 중재기 | `lingpet_egg_runtime._is_right_click_claimed_by_player_skill(:2933)` — **`smasher_overdrive_state` 하나만 확인** |
| 프레임 순서 | `update_player_control(:102)` → 이후 링펫 갱신. **같은 프레임에 둘 다 발동 가능** |

### 5.2. 해야 할 일

1. `viper_input_reader.gd`에 `secondary_action_*` 신설 — 스매셔 리더와 동일 형태.
   `get_snapshot()`의 **같은-물리-프레임 멱등 계약을 반드시 유지**할 것(코만도 화기
   발사가 에지 소모 트랩으로 죽은 전례).
2. **탑승 소유권 중재 확장** — `_is_right_click_claimed_by_player_skill()`이
   월담야습도 보게 한다. 벽력유성 선례의 판정 기준을 그대로 따라
   **`is_command_armable()` 하나**로 판단한다:
   장착 + 기력(180) + 쿨타임 + 랠리 진행 중 + 입력락 미해당 + 대쉬 미비행 + 미활성.
   무장 가능하면 초식이 우클릭을 소유하고, 그 외(서브 대기 / 쿨 / 기력 부족 / 미장착
   / 타 캐릭터)에는 탑승이 종전대로 가져간다.
   ⚠️`get_cached_instance` **peek 전용** — 매 컴패니언 프레임 경로라 콜드
   인스턴스화가 끼면 첫 호출이 히치가 된다.
3. **LMB 참격**: 바이퍼는 `mouse_left_pressed = primary_pointer_pressed`이고
   `jetpack_pressed`가 같은 소스를 문다(`viper_input_reader.gd:35,47`) — **좌클릭이
   곧 제트팩**이다. 체류 중에만 제트팩 소비를 차단하고 LMB를 참격으로 라우팅한다
   (체류 중엔 Y 고정이라 제트팩이 무의미). 귀환 프레임에 눌린 상태가 제트팩으로
   흘러들지 않게 에지 처리 필요.
4. **오딘의 눈 경쟁**: `mythic_item_odins_eye_runtime:519`가
   `mouse_left_just_pressed`를 `update_mythic_items`에서 플레이어 컨트롤보다 **먼저**
   소비한다. 체류 중에는 참격 우선으로 명시.

### 5.3. 미결

- **모바일**: primary pointer가 터치 ACCEPT 채널이고 우클릭이 없다. 대체 입력 필요.
- **게임패드**: secondary action 매핑 확인 후 배선.

## 10. 참격 연출 확장 (rev6 — 사용자 확정)

기존 참격은 "스윙 판정 즉시 → 즉시 귀환"이었다. rev6부터 **스윙 시트 → 검기 발사 →
검기가 판정 → 검기 소멸 후 귀환**으로 바뀐다. 새 에셋 제작은 없다 — 전부 기존 자산이다.

### 10.1. 페이싱 (체류 중 좌/우 바라보기)

평소 이동과 동일하게, 좌 이동 입력이면 왼쪽을 보고 우 이동 입력이면 오른쪽을 본다.
무입력 프레임은 **마지막 페이싱을 래치**(0으로 리셋 금지 — 정지 상태에서 정면으로
튀면 참격 방향이 사라진다).

| 용도 | 상수 (`battle_viper_sprite_paths.gd`) |
|---|---|
| 좌/우 이동 | `VIPER_PLAYER_WALK_LEFT_SHEET_PATH` / `..._RIGHT_...` |
| 참격 스윙 | `VIPER_PLAYER_ATTACK_LEFT_SHEET_PATH` / `..._RIGHT_...` |

⚠️**미러링 금지.** 좌/우 시트가 각각 실재하므로 UV 스왑 미러 헬퍼를 쓸 이유가 없다
(CLAUDE.md의 "lateral-action sheets face ONE invisible direction" 트랩은 한쪽 시트만
있을 때의 규칙이다).

⚠️**여백 앵커를 반드시 통과시킬 것.** `player_sprite_body_insets.gd`에 시트별 실측
여백이 있고(`left_attack` = `(0.17500, 0.16875)`), 시트마다 값이 다르다. 체류 중에도
`player_sprite_wall_slide.gd` 시각 보정을 태워야 벽 끝에서 캐릭터가 벽에 붙는다.
물리 패들·판정은 불변(무충돌 상태이므로 애초에 영향 없음).

### 10.2. 스윙 시트

프레임 규격은 홀로그램이 이미 쓰는 것을 그대로 재사용한다
(`viper_skill_runtime.gd:132~134`): 프레임 `160x160`, `GRID_COLS = 4`,
`FRAME_COUNT = 8`.

- **임팩트 프레임에서 검기를 스폰**한다. 그 전 프레임에는 판정이 없다(윈드업).
  CLAUDE.md의 "spawn projectiles from the acting limb at the hand-empty frame" 규칙.
- 스폰 위치 = 그 프레임의 **칼 끝 / 손 위치**(전방 오프셋). 캐릭터 중심이 아니다.
- 권고 튜닝: 프레임당 0.032초(8프레임 ≈ 0.26초), 임팩트 = 3프레임째(≈0.1초 윈드업).
  구현자가 실기 확인 후 확정하고 보고한다.

### 10.3. 검기 투사체 — **판정 주체**

기존 `air_blade/` 자산을 재사용한다:
`viper_air_blade_trail_imagegen_v1.png`(비행 본체),
`viper_air_blade_slash_burst_imagegen_v1.png`(발사/명중 버스트).
`silhouette` / `charge_glyph`는 선택.

| 항목 | 값 |
|---|---|
| 방향 | 페이싱 전방만 (후방 판정 0) |
| 속도 | 권고 14px/frame |
| 최대 사거리 | **360px** (플레이어 중심 기준) |
| 소멸 | 명중 / 최대 사거리 도달 / 벽 도달 중 먼저 |
| 명중 판정 | 보스 **중심 X 거리**, §4.4 |
| 다단히트 | **금지** — 1회 명중 후 즉시 소멸 |
| 효과 | 둔화 2단계 `BossSlowTiers.MEDIUM`(0.55) 5초 — 기존과 동일 |

⚠️**스윕 판정 필수.** 프레임당 14px를 이동하므로 "현재 X와 보스 X의 거리"만 보면
얇은 판정폭을 뛰어넘는 터널링이 생긴다. **이전 프레임 X ~ 현재 프레임 X 구간**이
보스 중심 X를 포함하는지로 판정한다. 씰 12(c)가 이걸 봉인한다.

⚠️드로 컬에 주의 — 검기는 보스 Y 레인을 수평 이동하므로 플레이필드 전폭을 지난다.
컬 박스를 캐릭터 주변으로 좁게 잡으면 중간에 사라진다.

### 10.4. 상태 머신 변경

```
SLASH (스윙 시트 재생, 임팩트 프레임에 검기 스폰)
  └→ BLADE_FLIGHT (검기 비행 + 스윕 판정)
       └→ 검기 소멸 → RETURN (그 프레임의 공 X로 하강)
```

- **귀환은 검기 소멸 프레임**이다. 명중하면 즉시 소멸하므로 정확할수록 빨리 귀환한다
  (정확도 보상). 빗나가면 최대 사거리까지 날아가는 동안 바닥이 계속 비어 있다.
- BLADE_FLIGHT 중 §2.2(b) 강제귀환이 걸리면 **검기를 즉시 정리하고 귀환**한다.
  발동 시 나간 180 외에는 참격 단계에서 추가로 차감하거나 환불하지 않는다.
- 검기 · 스윙 클럭 · 페이싱 래치는 §4.5 리셋 3경로에서 함께 정리한다.

### 10.5. 밸런스 메모

사거리가 110px → 360px로 넓어지는 대신, 체류 시간이 **검기 비행 시간(최대 약 0.43초)
만큼 늘어난다.** 즉 "도망간 보스를 저격할 수 있게 되었지만 그만큼 바닥이 더 오래
비어 있다"가 이 교환의 핵심이다. 실기에서 너무 안전하게 느껴지면 **최대 사거리를
줄이는 쪽**을 먼저 보고, 감속 0.5나 쿨 40초는 나중에 건드린다.

### 10.6. 프리웜

참격 시트 2장 + `air_blade` 텍스처를 프리웜 컨트롤러에 등재한다. 핫패스(스윙 임팩트
프레임)에서 콜드 로드가 걸리면 그 프레임이 통째로 히치가 된다
(Godot Hot-Path Lazy Init Trap).

## 11. 폭발 VFX 재작업 (rev8 — 화약 계열로 전환)

> ⚠️ **rev9에서 §12로 대체됨.** "기존 `GrenadeExplosionDrawer` 재사용 / 새 아트 없음"
> 방침은 폐기한다 — 그대로 쓰면 수류탄과 같은 폭발이라 세린이 안 보인다.
> **§11.1(진단)과 §11.4·§11.5(가드)는 여전히 유효**하고, §11.2(재사용 해법)만
> §12로 교체된다.

### 11.1. 왜 바꾸는가

rev7 폭발 VFX는 라이브 확인에서 **"허접하다"** 판정을 받았다. 원인 3가지:

1. **`draw_line` 방사선 12개가 화면을 지배한다.** `draw_line`은 라인 캡이 없어
   무조건 직각(버트) 캡이므로 빛줄기가 아니라 **회색 막대기**로 읽힌다
   (`docs/godot_runtime_traps.md` — "Godot `draw_line`에는 라인 캡이 없다").
2. **방사 대칭이 완벽하다.** 정확히 30° 간격 · 동일 길이 · 동일 두께 12개 →
   폭발이 아니라 **별표(✳) 아이콘**으로 읽힌다.
3. **전용 아트가 0장이다.** 공용 글로우/링 캐시 + 절차적 프리미티브 조합이라
   질량이 없다. 같은 스킬의 검기는 `air_blade` 실제 아트를 쓰므로 두 분기의
   완성도가 눈에 띄게 차이 난다.

색도 문제였다. 폭발이 시안·자색이라 **검기와 색이 겹쳐** 두 분기가 구분되지 않았다.

### 11.2. 해법 — 새 아트 생성 없음, 기존 화약 시스템 재사용

사용자 확정: **화약 계열**로 전환. 그런데 이 저장소엔 이미 화약 폭발이 있다.

**`godot/scripts/effects/grenade_explosion_drawer.gd`** — `static func draw_zone(
canvas, zone: Dictionary, shake_offset)`. 정적 함수라 어느 캔버스 드로 경로에서든
호출 가능하다. 기본 레이어가 이미 화약 그 자체다:

| 레이어 | 내용 |
|---|---|
| 충격파 아크 | `radius + elapsed*6`, 반경 2.5배까지 |
| 화염 링 5겹 | 시간에 따라 **주황(1.0,0.61,0.20) → 적(1.0,0.20,0.04) → 갈색 잔불** |
| 연기 퍼프 3개 | 회갈색(`tone, tone*0.9, tone*0.78`), 위로 상승 |
| 스파크 4개 | 노란 흰빛, 6프레임 |
| 과압 플래시 | 3프레임 백색 코어 |

**스타일 = `explosion_style: "jinroe_tan"`** 을 권장한다:
- 진뢰탄(震雷彈)은 조선 화약 병기라 **환격전 리브랜드 어휘와 정확히 일치**하고,
  세린의 산적-화약 컨셉과도 맞는다.
- `jinroe_tan_impact_stamp_imagegen_v1.png` — **실제 생성된 아트**가 이미 있다.
- 중간 무게다. `airstrike` 스타일은 12 텍스처 레이어 + 버섯구름 + 잔해 청크라
  ±50px 스킬 폭발에는 과하다.

zone dict 스키마:
```gdscript
{
  "position": Vector2,           # 게임 좌표(드로어가 shake를 더한다)
  "radius": float,               # 시각 반경. §11.4 주의
  "max_duration_frames": float,
  "duration_frames": float,      # 남은 프레임
  "explosion_style": "jinroe_tan",
  "active": true,
}
```

프리웜은 `GrenadeExplosionDrawer.prewarm_assets()` 정적 호출로 대체한다
(현재 wall-leap 전용 프리웜 목록에서 폭발용 항목은 제거).

### 11.3. 제거할 것 / 남길 것

**제거:**
- `BLAST_RAY_COUNT = 12` 방사 `draw_line` 전량 ← 별표 원인
- 흰 코어 `draw_circle` (드로어의 과압 플래시가 대체)
- 시안·자색 이중 쇼크웨이브 (검기와 색 충돌)

**남길 것 — 스킬 소유권 표시:**
드로어를 그대로만 쓰면 "수류탄이랑 똑같네"가 된다. 화약 폭발의 **질량·정체성은
드로어가 담당**하고, 그 위에 **얇은 시그니처 액센트 1겹**(세린 청록 링, 낮은 알파)만
남겨 "화약 폭발인데 세린 것"으로 읽히게 한다. 액센트가 주역이 되면 안 된다.

FUSE 텔레그래프(수렴 링)는 유지한다 — 0.7초 딜레이를 예고하는 기능적 UI이고,
청록이라 폭발 본체와 색이 갈려 오히려 대비가 산다.

### 11.4. ⚠️ 시각 반경을 판정 반경으로 착각하지 말 것

드로어 기본 `radius`는 190(수류탄)이고 월담야습 폭발 **판정**은 보스 중심 X 거리
±50px다. 시각 반경은 크게 잡아도 되지만(권고 110~130) **판정은 절대 따라 넓히지
않는다.** `character_skill_perk_checklist.md` §6의 hit-primitive 계약상
시각 원이 보스 rect에 스치는 것만으로 CC가 들어가면 안 된다.
씰 6(`wall_leap_blast_status_smoke`)의 50/51 경계 단언은 **그대로 유지**된다.

### 11.5. 긴 방사선을 다시 만들지 말 것

드로어 자체도 스파크에 `draw_line`을 쓰지만(`:97`) 2px 두께에 짧아서 불티로 읽힌다.
버트 캡이 문제가 되는 건 **길고 굵은** 선이다. 재작업하면서 긴 방사선을 다시
추가하지 마라 — 그게 이번 판정의 직접 원인이다.

## 12. 정상 공격 후 공 도달 예상 X 귀환 (rev10, 2026-08-01 사용자 확정)

- 씰 15 `wall_leap_ball_return_target_smoke`: 폭발 도달 예상 X 스냅샷, 참격 우벽 반사,

## 12. 폭발 VFX — 세린 각색판 (rev9, 사용자 확정)

§11.2의 "드로어 재사용 / 새 아트 없음"을 **대체**한다. 화약 계열은 유지하되
세린 전용으로 각색하고, 전용 아트를 실제로 만든다.

### 12.1. 세린 정체성에서 출발

| 축 | 근거 |
|---|---|
| **산적** | 자산명 `viper_serin_hwangyeok_bandit_*`, 환격전 산적 불법개조 컨셉 |
| **그림자(影)** | 초식이 독영절맥 · 혈영참 · 쌍영분신 · 환영연각 — 影이 정체성 |
| **칼** | 참격 분기가 검기(`air_blade`) |

→ **"산적이 밀조한 화약을, 그림자 속에서, 칼 파편과 함께 터뜨린다."**
일반 화약 폭발과 갈리는 지점이 여기서 전부 나온다.

### 12.2. 각색 4축

**① 도화선 (FUSE 재설계) — 기능적으로도 개선**
현재 FUSE 텔레그래프는 수렴 링이라 SF처럼 읽힌다. **불똥이 타들어가는 도화선**으로
바꾼다. 0.7초 딜레이를 직관적으로 전달하고(남은 심지 길이 = 남은 시간),
산적 화약이라는 정체성을 첫 프레임부터 세운다. 링보다 이쪽이 정보 전달도 낫다.

**② 먹빛 폭연 — 색으로 갈리는 핵심**
일반 화약은 주황 + 회색 연기다. 세린 것은 **중심은 화약답게 주황·금빛, 바깥으로
갈수록 먹빛(흑청)으로 물든다.** 그림자 정체성을 연기에 실어서 "같은 화약인데 다른
사람 것"이 색만으로 성립한다.

**③ 칼날 파편**
산적이 화약통에 쇳조각을 채워 넣었다. 파편이 둥근 불티가 아니라 **날붙이 조각
실루엣**이다. 참격 분기(검기)와 시각적으로 이어져 "이 캐릭터는 칼을 쓴다"가
두 분기 모두에서 읽힌다.

**④ 연막 이탈**
폭발 연기가 세린을 삼키고 그 속에서 사라져 내려간다. 월담야습의 **"폭발 후 즉시
귀환"과 정확히 맞는** 연출이라 기능이 곧 연출이 된다. 귀환 트윈 시작 프레임에
연기 밀도가 최대가 되도록 타이밍을 맞춘다.

### 12.3. 색 설계

| 요소 | 색 | 의도 |
|---|---|---|
| 과압 코어 | 백열 → 금빛 `(1.0, 0.92, 0.62)` | 화약의 뜨거움 |
| 화염 중간 | 주황 `(1.0, 0.55, 0.18)` | 화약 정체성 |
| 연기 바깥 | 먹빛 흑청 `(0.16, 0.14, 0.22)` | 세린의 그림자 |
| 파편 불티 | 자주 `(0.72, 0.34, 1.0)` 소량 | 影 계열 액센트 |

검기는 청보라다. 폭발은 **주황 코어 + 먹빛 외곽**이라 명도·색상이 모두 갈리고,
자주 불티가 두 분기를 같은 캐릭터의 것으로 묶는다.

### 12.4. 3피스 스펙 (정적 텍스처 + 런타임 합성)

[Skill VFX Workflow](skill_vfx_workflow.md)의 모듈러 VFX 레시피를 따른다.
정적 PNG 3장이라 AutoSprite 필수
규칙은 적용되지 않는다(움직이는 시트가 아님) — imagegen 허용.

| # | 이름 | 역할 | 블렌드 | 크기 |
|---|---|---|---|---|
| ① | `serin_blast_smoke_bloom` | 백플레이트 = 질량·깊이 | **MIX** | 1024 |
| ② | `serin_blast_blade_shards` | 파티클 = 칼날 파편 + 불티 | **ADD** | 512 |
| ③ | `serin_blast_shock_ring` | 호 = 충격파 링 | **ADD** | 1024 |

⚠️**블렌드 의도 분리가 핵심이다.** 연기는 실체이므로 MIX여야 한다. 전부 ADD로
깔면 먹빛 연기가 배경을 어둡게만 만들고 질량이 사라진다
(`docs/godot_runtime_traps.md` — "ADD × 어두운 아트 = 발광 0").

도화선 불똥(④)은 **기존 자산 재사용 우선** — `spark1~3.wav` 계열 시각 대응물이나
`ImpactFlareTextureCache.draw_sparkle`로 충분한지 먼저 확인하고, 부족할 때만 생성.

### 12.6. 런타임 합성

- 연기(①)는 **크고 느리게** 팽창하며 알파가 길게 남는다 → 연막 이탈(§12.2-④)
- 파편(②)은 **작고 많고 빠르게** 흩어진다. 각도·속도·수명에 시드 기반 불규칙성.
  `GPUParticles2D` 또는 캔버스 다층 가산
- 링(③)은 **한 번, 빠르게** 확장하고 사라진다
- `WritheEmberMaterial` 프리셋 적용을 검토하되, ⚠️**흰색 텍스처를 그대로 넣으면
  회색으로 죽는다** — draw modulate에 따뜻한 화염색을 넘겨야 한다
- ⚠️화염-혀 텍스처를 좁고 뾰족하게 만들어 전부 같은 방향 정렬하면 **가시밭/스파클러**로
  읽힌다. 파편은 개별 회전 변주 필수

### 12.7. 승계되는 가드 (§11에서 유효)

- **시각 반경(권고 110~130) ≠ 판정 반경(±50px).** 씰 6의 50/51 경계 유지
- **긴 방사 `draw_line` 재추가 금지.** 라인 캡이 없어 사각 막대로 읽힌다
- 라이브 픽셀 QA 필수 — rev7 결함은 상태 스모크 14종 전부 GREEN인 채로 났다

## 13. 도화선 가독성 마무리 (rev10, 사용자 확정)

§12 폭발 본체는 **라이브 캡처로 합격**했다. 유지한다. 이 절은 남은 격차만 닫는다.

### 13.1. 왜 하는가

rev9 라이브 캡처에서 약한 쪽이 뒤집혔다 — 폭발은 텍스처 3피스인데 **도화선만
절차적 선 하나**라 프로덕션 티어가 눈에 띄게 다르다. 구체적으로:

1. 얇고 어두운 주황 선이라 게임플레이 중 안 보인다
2. 화약통이 **빈 다각형 아웃라인** → 와이어프레임 플레이스홀더로 읽힌다
3. 불똥이 점 하나 → 타들어가는 심지의 주인공인데 시선을 못 끈다

도화선은 **0.7초 폭발 텔레그래프**다. 기력은 이미 월담야습 발동 때 180이
일괄 차감되므로 FUSE 자체에는 추가 차감이 없다. 가독성 격차를 닫는 것이 이 절의 목적이다.

### 13.2. 범위 — 이 셋만

| # | 항목 |
|---|---|
| ① | 전용 **4번째 피스** = 화약통 텍스처 |
| ② | 절차적 심지 + 이동 불똥 **가독성 강화** |
| ③ | 칼날 파편 **수명 연장** → 후반 자주 잔불 |

폭발 본체(연기·파편·링 합성)는 **건드리지 않는다.**

### 13.3. ① 4번째 피스 — 화약통

**밀조 화약 주머니** 또는 **비대칭 대나무 화통**. 먹빛 흑청 몸체 + 주황 봉인.
**MIX 합성**(빛이 아니라 실체다).

⚠️금지: 둥근 만화 폭탄, 빈 외곽선, 방사 대칭.

파일: `serin_blast_powder_charge_imagegen_v1.png`
(경로는 기존 3피스와 동일한 `characters/viper/wall_leap_raid/`)

프롬프트:
```
Game VFX prop texture, a bandit's illicit black-powder charge: an asymmetric
bamboo tube or cloth-wrapped powder pouch bound with coarse cord, deep ink-blue
and charcoal body with worn hand-made texture, warm orange wax seal and binding
accents, crude improvised craftsmanship, irregular silhouette, side view,
solid opaque object suitable for MIX blending, centered with generous
transparent margin, alpha bounds must not touch the canvas edge,
no round cartoon bomb, no hollow outline, no radial symmetry, no text, no frame.
```

생성 배경은 기존 3피스와 동일하게 초록 단색 → 크로마키·디스필·알파 경계 정리.

### 13.4. ② 심지 + 불똥

**심지(절차적 유지):**
- **남은 길이 = 남은 시간 계약은 그대로 유지**한다. 정보 전달이 이미 옳다
- 외곽선과 내부 발광을 **굵고 밝게** 강화한다. 현재는 게임플레이 중 안 보인다

**이동 불똥(확대):**
- **백열 코어 + 주황 글로우 + 후행 불티 2~4개**
- 심지의 **연소 선단을 정확히 추적**한다 — 불똥과 심지 끝이 어긋나면
  "타들어간다"는 읽기가 깨진다

### 13.5. ③ 후반 자주 잔불

칼날 파편 자산에는 자주 불티가 **실제로 들어있는데** 합성에서 안 보인다. 초반
주황 화염이 강할 때 ADD로 겹쳐 씻겨나가기 때문이다.

→ **칼날 파편층 수명을 폭연보다 길게** 가져간다. 화염이 죽은 후반부에 자주 불티와
금속 파편이 남아 읽히게 한다. 강도를 올리는 게 아니라 **타이밍으로 푼다.**
"그림자 잔불이 남는다"는 세린다움과 검기(청보라)와의 색 연결이 여기서 성립한다.

### 13.6. 배선 의무

전용 자산 **프리웜 · 플레이필드 클립 · 라운드 종료 정리**를 §12 3피스와 동일하게
처리한다(전용 FX 호스트 `viper_wall_leap_blast_fx_host.gd` 경로 재사용).
**실제 창 렌더 캡처**를 산출물에 포함한다.

### 13.7. 씰

세 항목을 **각각** 검사하고, 각각 **단일 계약 토글 → 예상 RED → 원복 GREEN**까지
제출한다.

| 검사 | 내용 |
|---|---|
| 화약통 텍스처 누락 | 텍스처가 없을 때 조용히 빈 화면이 되지 않음(가시적 degradation 또는 명시 실패) |
| 불똥 가독성 | 불똥 영역 밝은 픽셀 카운트가 임계 이상 |
| 후반 자주 픽셀 | 폭발 **후반 프레임**에서 자주 계열 픽셀 > 0 |

⚠️픽셀 씰 주의 2건:
- **강한 임계로 판정하라.** 약한 임계는 버그 상태와 정상 상태가 같은 값을 내서
  변별력이 0이 된다(VFX 발광 예산 트랩).
- **`SubViewport` 기본 클리어색은 검정이 아니다.** 명시적으로 검정을 설정하지 않으면
  대조군에서 대량 오탐이 난다(풍운천선무 사례 570,000px).
