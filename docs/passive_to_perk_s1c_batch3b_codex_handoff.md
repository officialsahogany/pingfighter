# S1c 배치③b 코덱스 핸드오프 — 위험감지센서 자동대쉬 토큰 재설계

기준 문서: `docs/passive_to_perk_conversion_plan.md` (v3) §4-A sensor 행(★확정
수치) / §7-2. 선행: S1c 배치①②③a PASS (일반퍽 22/26종 전환 완료).
발주: 2026-07-07. Claude 기획 → 사용자 직접 Codex 전달 → Claude 적대 리뷰.

**이번 배치는 순수 게이트 전환이 아니다.** ON(퍽) 경로에 "자동대쉬 전용 토큰"
이라는 신규 상태 메커니즘이 들어간다. 아래 설계 결정 D1~D5는 확정 사항이며,
기존 센서 구현 구조가 이 설계와 근본적으로 충돌하면 **구현하지 말고 중단·보고**.

## 합격 조건

1. 플래그 OFF(기본): 기존 센서 동작 완전 무변화 — 쿨타임(롤 13~20초) 단발
   자동대쉬, 토큰 개념 없음.
2. 플래그 ON: 퍽 레벨 기반 토큰 모델로 완전 대체 —
   Lv.1 토큰 1개/쿨 30초 → Lv.5 토큰 2개/쿨 15초
   (S1b 값 테이블: `auto_dash_token_count` [1,1,2,2,2],
   `auto_dash_cooldown_sec` [30,26,23,19,15]).
3. 양 경로 공통 불변식 유지: **자동대쉬는 게이지와 일반 대쉬 토큰을 소모하지
   않는다** (전용 토큰은 ON 경로의 별도 자원).

## 확정 설계 (D1~D5)

- **D1 재충전 모델 = 순차 재충전.** 전용 토큰은 한 번에 1개씩,
  `auto_dash_cooldown_sec`마다 1개 회복 (기존 일반 대쉬 토큰 재충전 문법
  미러). 토큰별 독립 타이머 아님. 만충 상태에선 재충전 타이머 정지.
- **D2 토큰 메커니즘은 ON 경로 전용.** OFF 경로는 기존 쿨타임 상태를 그대로
  쓴다 — 신규 토큰 상태머신이 OFF 동작에 어떤 영향도 주지 않아야 한다.
- **D3 위험 판정·대쉬 실행 로직은 공유.** 기존 위험 감지와 자동대쉬 실행
  코드는 재사용하고, 분기는 두 곳만:
  - 발동 가능 판정: OFF = 기존 쿨타임 경과 / ON = 전용 토큰 > 0
  - 발동 직후: OFF = 기존 쿨타임 리셋 / ON = 토큰 1 소모 + (재충전 타이머
    미가동이면) 재충전 시작
- **D4 리셋 경계 = 기존 센서 쿨타임과 동일.** 기존 센서 쿨타임 상태가
  리셋되는 경계(라운드 전환/매치 시작/메인메뉴 복귀 등)를 먼저 확인하고,
  전용 토큰·재충전 타이머도 **정확히 같은 경계에서** 같은 방식으로 처리
  (매치 시작 = 만충 권장, 기존 경계가 다르게 동작하면 기존을 따르고 보고).
  레벨 변화(유효레벨 포함)로 max 토큰이 줄면 현재 토큰은 max로 절사.
- **D5 HUD/표시는 범위 밖 (S3).** 토큰 상태는 runtime 내부 필드로 유지.
  owner 키 sync가 꼭 필요해 보이면 구현하지 말고 보고
  (owner-field schema 트랩 — `DEFAULT_VALUES` 미선언 키는 조용히 no-op).

## 범위 (이번 실행)

1. sensor 수치 게터 게이트 전환 (기존 쿨타임 롤 게터는 OFF 전용이 됨;
   ON 경로는 토큰 모델 파라미터를 값 테이블에서 읽음).
2. `is_sensor_effect_active()`류 불리언 게이트 (①②③a 패턴).
3. ON 경로 전용 토큰 상태 (개수/재충전 타이머) + D1~D4 구현.
4. 우회 경로 전수 감사: 센서 장착/쿨타임을 직독하는 소비자 grep,
   전환 vs 유지(UI/스냅샷) 분류 보고.
5. 스모크 신설 + values_smoke fixture 교체 (아래).
