## 2. 조사 항목

### 2-1. 스킬 기능 파리티

원본 두더지왕의 **모든 스킬과 행동**을 원문에서 뽑고 포팅본과 1:1 대조하라.

- 스킬 목록, 발동 조건(확률·쿨다운·HP·점수·랠리), 지속·범위·속도·효과 수치
- 스킬 선택 로직(무작위·순환·조건부)
- 이동 AI와 특수 상태(잠수·굴착·등장 등 두더지 고유 기믹이 있으면 그것)
- 플레이어에게 거는 상태이상과 해제 조건
- ⚠ **수식이 같아도 "그 경로에서 실제로 호출되는가"가 다를 수 있다**(GRT-053).
  원본의 호출부 전체와 포팅본의 호출부를 함께 대조하라. 정의만 있고 아무도
  부르지 않는 함수는 **미포팅으로 분류**한다.
- 원본에만 있고 포팅본에 없는 것, 포팅본에만 있고 원본에 없는 것을 각각 적어라.

### 2-2. 연출 파리티

- 스킬별 시각 연출(파티클·트레일·플래시·화면 흔들림)이 원본과 대응하는가
- 등장·퇴장·피격·사망 연출
- 오디오 큐가 있는가, 원본에 있는데 빠진 것이 있는가
- 보스 스킬 카드/배너 표시가 되는가

### 2-3. 에셋 현황 ★중요

Fable이 사전 확인한 바로 **두더지왕 전용 에셋이 0건**이다
(`assets/` 전체에서 mole 계열 파일 없음). 다음을 확정하라.

- 지금 두더지왕이 화면에 **무엇으로 그려지는가**(절차 도형인지, 다른 보스 시트
  재사용인지, 플레이스홀더인지). `stage2_variant_boss_renderer.gd`를 읽고
  실제 드로 경로를 지명하라.
- 원본에서는 무엇으로 그려졌는가(스프라이트인지 도형인지, 크기와 색).
- **필요한 에셋 목록**을 산출하라. 스킬 카드 아이콘 몇 장, 보스 시트 몇 종
  (걷기·공격·대쉬·턴 중 무엇이 필요한지), SD 캐릭터가 필요한지.
- 형제 보스(청린귀·아라크네)가 어떤 에셋 구성을 갖는지 대조해 기준을 잡아라.

### 2-4. 탑 모드 통합 상태

- `tower_ascent_boss_registry.gd`에서 두더지왕 슬롯의 상태(`ported` 여부,
  standin 매핑)를 확인하라.
- 탑 2층에서 실제로 이 보스와 싸울 수 있는가. 보스 배선(`resolve_battle_encounter`)이
  두더지왕을 제대로 해석하는가.
- **비전초식이 등재되어 있는가.** 아카무는 미등재였다. 두더지왕도 확인하라.
- 지도 노드 아이콘용 아트가 필요한지(§3.1 v1.12: 보스는 항상 고유 아이콘).

### 2-5. 씰 실태

- `stage2_molewang_boss_port_smoke.gd`가 **무엇을 실제로 단언하는가**.
  소스 텍스트 검사인지 행위 검사인지, 프로덕션 경로를 관통하는지.
- **공허 GREEN이 있는지** 확인하라. Fake 픽스처에 키가 없어 라우트가 null로
  빠지는 형태가 이 저장소에서 반복 관측됐다.
- 현재 RED가 있으면 문구별로 적어라.
- CI·pre-push 두 리터럴 목록에 등재되어 있는가.

## 3. 규율

- **읽기 전용.** 파일 수정·생성·커밋·스테이징 금지. 보고서 1개만 작성한다.
- ★**grep 0건을 "없음"의 증거로 쓰지 마라.** 서로 다른 검색어 3개 이상과 다른
  디렉터리로 교차 확인하고, 확인 못 하면 uncertain으로 표시하라.
  (이 저장소에서 grep 오판이 반복 관측됐다. 특히 한글 표시명·내부 id·영문
  로마자가 서로 다른 경우가 많다.)
- 수치는 코드 상수에서 직접 인용하라. 프레임은 초 환산(72Hz)도 병기하라.
- 경로는 저장소 루트 기준 상대경로 + 줄번호로 지명하라.
- 추측과 확인을 구분하라. 원본 파일을 못 찾으면 어디를 어떻게 찾았는지 적어라.
- 표준 래퍼로 씰을 **실행해 보는 것은 허용**한다(`-AllowDuringPlay`).
  로그 백업을 선행하고 고유 로그 경로를 쓴다. 코드는 고치지 마라.

## 4. 보고서 구조

```
## 한 줄 요약
## 두더지왕은 어떤 보스인가 (원본 기준)
## 스킬 표 (원본 / 포팅본 / 상태)
## 미포팅·불일치 목록 (심각도순)
## 연출·오디오 현황
## 에셋 현황과 필요 목록
## 탑 모드 통합 상태
## 씰 실태 (공허 GREEN 포함)
## 아트 브리프 초안
## 수정 착수 시 권장 순서
```

**심각도는 관측 가능한 실패로 지명하라.** "원본과 다르다"만으로는 부족하고
"그래서 플레이어가 무엇을 겪는가"를 적어라. 설계상 의도된 이탈일 수 있으니
기록된 설계 결정이 있는지 먼저 확인하라(GRT-053).

**아트 브리프 초안**은 팔레트·실루엣·크기·투명도 수준으로 적되, 형제 보스의
기존 에셋 규격을 실측해 기준으로 삼아라. 신규 생성은 이번 범위가 아니다.
