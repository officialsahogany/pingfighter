## 2. 확정 사양

**근두운은 방향성을 갖지 않는다.**

- 진행 방향에 따라 형태가 바뀌지 않는다. 말려 올라가는 꼬리를 만들지 않는다.
- 이동 중 표현은 **가벼운 흔들림과 상하 일렁임**이다. 실루엣의 기본 형태는
  유지하고 가장자리가 부드럽게 출렁이는 정도다.
- 방향 비대칭이 없으므로 **좌측 시트를 우측의 미러로 만들어도 안전하다.**
  캐릭터만 뒤집히고 구름은 문제가 생기지 않는다.

**근두운 디자인은 전 모션에서 동일하다.**

- 대기·걷기·대쉬·공격이 같은 구름을 쓴다. 조밀한 나선 근두운 계열이 정본이다
  (현재 `rear_cloud`가 그 계열이다).
- 모션마다 구름이 달라지면 같은 캐릭터로 안 보인다.

## 3. 착수 전 판정 ★먼저 하라

두 경로를 비교하고 **근거와 함께 권고**한 뒤 멈춰라. 사용자 판정 대상이다.

### 경로 A. 베이크 재작화

전 모션 시트를 일관된 구름으로 다시 뽑는다.

- 대상: 대기, 걷기 L/R, 대쉬 L/R, 공격 L/R
- 장점: 런타임 변경 0. 기존 렌더 경로 그대로.
- 단점: 시트가 늘 때마다 같은 문제가 재발한다. 일관성이 아트 규율에만 의존한다.

### 경로 B. 구름을 런타임 레이어로 분리

캐릭터 시트에서 구름을 빼고, 구름은 단일 자산 + 런타임 흔들림으로 그린다.

- 장점: **일관성이 구조로 보장된다.** 새 모션이 추가돼도 구름은 하나다.
  흔들림 강도와 주기를 이동 속도에 연동할 수 있다.
- 단점: 캐릭터 시트를 전부 구름 없이 다시 뽑아야 하고 렌더러가 바뀐다.
  ★**GRT-059**: 셀 여백이 달라지면 앵커 표를 재측정해야 한다.
  ★**GRT-056**: 바닥 근처 VFX는 회전한 쿼드가 클램프를 뚫는다.

**Fable 권고는 경로 B**다. 사용자 요구가 "처음부터 일관성 있게"이고, 오늘
걷기↔대기, 걷기↔공격에서 같은 문제가 두 번 났다. 다만 작업량이 크므로
**판정은 사용자가 한다.**

시간이 부족하면 경로 A로 공격 시트만 계열 정렬하는 축소안도 제시하라.

## 5. 계약

- **흔들림은 이동 중에만.** 정지 시 대기 시트의 일렁임으로 자연스럽게 이어져야
  한다. 전환에서 튀지 않는지 확인하라.
- ★**연출 난수는 게임플레이 RNG를 소비하면 안 된다.** 독립
  `RandomNumberGenerator`를 쓰라.
- ★**GRT-012**: 흔들림은 **실제 이동량**에 연동한다. 의도 상수나 하드코딩이
  아니다. 어제 `3b7aa4c55`가 걷기 프레임을 이동량 구동으로 바꿨으니 같은
  소스를 쓰라.
- 8프레임 시트라면 **고유 프레임을 8장 채워라.** 현행 `rear_cloud`는 5장만
  고유하고 f1·f3·f6이 2틱씩 유지된다. 이동 모션이 성겨 보이는 원인이다.
- 자산 파일명과 경로 상수명은 호환 식별자다. 신규 파일은 기존 명명 규칙을
  따르되 기존 이름을 바꾸지 마라.
- 아트 생성은 승인 뒤에만 승격한다. 후보는 후보로 둔다.

## 7. 검증

- 슬라이스별 씰 + `-Paths` 경고 + 헤드리스 + `git diff --check`.

  - 1:1 배율과 실 게임 배율 양쪽
