## 2. 커밋 순서 규칙

- 트랙 단위 분리 커밋: **모듈 분리 베이스 → 팔자윷 → (필요 시 융합 갱신분)
  → 체질 수련** 순서를 기본으로 하되, 실제 의존이 다르면 의존 순서를 따르고
  근거를 보고서에 기록한다.
- **모든 중간 커밋은 그 자체로 성립하는 트리**여야 한다: 커밋마다 격리
  트리에서 헤드리스 로드 + 해당 트랙 씰 배터리 통과. 미추적 의존 파일을
  참조하는 상태로 커밋을 끊지 않는다. 분리가 불가능해 두 트랙을 한 커밋에
  실어야 하면, 그 사실과 사유를 커밋 메시지와 보고서에 명시한다(조용한
  합승 금지).
- 커밋 메시지는 한국어 제목, 트랙명 명시.

## 3. 검증 규칙

- 트랙별 씰 배터리(테스트 파일명 패턴으로 식별): 모듈 분리 =
  `runtime_perk_*`·`perk_choice_*` 계열, 팔자윷 = `mystic_dice_*` 6종+,
  체질 수련 = `physique_*` + 수련 관련 통합 스모크, 융합 포함 시
  `perk_fusion_*` 계열. 각 배터리는 래퍼 종단선
  (`All Godot smoke tests passed.`)과 exit 0으로만 인정.
- 최종 HEAD에서: 커밋 범위 변경 `.gd` 집중 경고 스캔, 헤드리스 로드,
  `git diff --check`, 페이즈 A·B·C 타워 회귀 세트.
- **씰 RED가 나면 코드를 고치지 말고 중단**한다: 어떤 씰이 어떤 커밋 후보
  트리에서 RED인지 보고서에 기록하고 보고한다. (9일 드리프트로 페이즈 A가
  같은 파일들에 커밋을 얹었으므로 드리프트 RED 가능성이 실재한다.)
- baseline 선재 RED(퍽 전환 파스 에러, lingpet_main_egg_overflow 등)는
  기존 귀속을 유지하고 이번 작전의 게이트로 세지 않는다. 단, 이번 커밋
  폐쇄에 퍽 전환 파일이 포함되어 해당 파스 에러가 이 작전 소관이 되는
  경우에는 예외로 보고서에 명시한다.
- 플레이 중 검증 신정책 준수, 검증 전 로그 백업.
