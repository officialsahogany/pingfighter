## 1. 작업 항목 (각각 독립 커밋 — 단, §2의 헝크 분리 규율 우선)

1. **픽 화면 신설 + 흐름 재배선**: 탑 승리 흐름을
   `하이라이트 리플레이 → 보상 픽 → 경로 서브`로 바꾸고 상자 단계를 제거한다.
   **픽은 탑 플로우의 신규 페이즈가 아니라 현행 승리 전리품 페이즈 자리를 그대로
   대체한다** (감사 §P1-C — 탑 플로우가 활성인 동안 입력 컨트롤러가 모든 입력을
   먼저 소비하므로 탑 페이즈로 만들면 카드 클릭이 무증상으로 사라진다).
   전리품 자리를 쓰면 물리 게이트 등재, 쿨다운 팬아웃, 루프 오디오 정지
   (GRT-034), resume safety, `ball_active` 강제 false, 필드 스폰 차단, 즉시퍽
   제외를 그대로 상속한다. 신규 상태 키를 만들면 즉시
   `BattleSceneState.DEFAULT_VALUES`에 선언한다 (GRT-017).
   픽 커밋은 선행 작업에서 신설된 유일 해소 id 축에 귀속시키고, 카드 지급은
   `reward_bundle`이 아니라 `apply_once`의 effect/rollback 콜백으로 보낸다.
2. **카드 규칙**: 매 화면 완전히 새로운 4장(이월 없음). 구매 시 리롤 없이
   나머지가 남고 무혼 잔고까지 추가 구매 가능. 계속하기로 떠나면 잔여 폐기.
   **배분 순서**: 슬롯 1 = 확정 카드(비전초식) 우선 → 잔여에 저확률 lane(절세
   무공) → 나머지는 기본 풀(무공·수련). 같은 카드 중복 금지. 구매 가능한 재고가
   없으면 그 카드는 등장시키지 않는다. **카드 세트는 화면 진입당 정확히 한 번만
   굴려 캐시한다** (GRT-011 — update/draw 재굴림은 저확률을 확정으로 만든다).
   무혼 환산 계수는 **1.0 고정**이며 환산 작업 자체가 불필요하다(감사 §P1-F).
3. **절세무공 전용 창 은퇴 — 경로 둘 다**: (a) 상자 신화 선택 진입점,
   (b) `runtime_perk_catalog`의 잭팟 단락 return. **(b)는 이미 수련장 무공
   서가로 새고 있다** (감사 §P1-G — 잭팟이 터진 방문에서 절세무공 2종을 20무혼에
   확정 구매 가능). 픽에서만 제거하면 (b)가 살아남으므로 누수 봉인을 범위에
   포함하고, 수련장 씰의 Fake 카탈로그를 잭팟 확률 1.0을 강제한 실 카탈로그
   레그로 보강한다.
4. **비전초식 = 확정 1장 + 런 소멸**: 적격 판정 정본 키는 도착 노드의
   `boss_slot_id`이며 판정 함수를 한 곳으로 통합한다(현재 두 파일 복제 +
   `current_stage`만 봄 → 같은 층 다른 보스를 구분 못 함, 감사 §P1-H).
   회피한 보스의 초식은 후보에서 제외한다.
   **소멸 목록의 오너는 `TowerAscentRunState` 진행 필드**이며 `skipped_boss_ids`와
   동급으로 캐리오버 allowlist에 등재한다(감사 §P1-B — flow owner에 두면 다음
   승리 한 번에 지워져 재등장한다). 커밋 시점은 "카드를 그렸을 때"가 아니라
   "구매 또는 계속하기를 확정했을 때"이며 해금 필터 통과 뒤다.
   부정 레그 씰은 `prepare_vertical_slice_combat`를 **두 번 관통**해야 유효하다.
5. **상자 은퇴 = 탑 레그 교체**(삭제 아님): 플래그 OFF 레거시의 상자 경로, 점수
   비례 수량, `guaranteed_mythic`, 결과화면 정산은 무손상 보존한다. 은퇴 대상은
   줄 번호가 아니라 함수·상수 이름으로 지목한다(감사 §P1-D·§2 목록 참조).
   **사실 정정**: 3% 잭팟의 프로덕션 산출물은 신화 액티브가 아니라 절세무공
   선택 창이므로, 후계는 절세무공 카드 저확률 등장이 담당한다.
   **액티브 아이템 카드는 이번 범위에서 제외한다** — 런 골드 생산자가 없어
   골드 가격 카드는 착지 즉시 영구 비활성이다(감사 §P1-E).
   승리 점수 파생 임계값 소비자는 GRT-054 요령으로 전수 감사한다.
6. **UI**: 기존 선택지 카드 UI를 4장으로 확장 재사용한다. **잔여 카드는 배열에서
   제거하지 말고 소진 플래그로 인덱스를 안정시킨다**(GRT-030 — 배열 축소는 마지막
   카드 구매 후 입력이 죽는다). 구매 후 애니메이션 시간 리셋을 픽 분기에서
   생략한다(현행은 남은 카드가 다시 날아 들어와 "그대로 남는다" 계약을 시각적으로
   부정한다). 가격·잔고 표기는 카드 내부가 아니라 **카드 아래 여백 띠**에 둔다
   (세로 예산 잔여 12px). 신규 레이아웃 입력은 레이아웃 빌더·카드 rect 산출·
   히트테스트 세 곳에 같은 인자로 흘리고 정본 플래그는 update 초입에서 고정하며,
   반증은 카드 중심점이 아니라 **상단 모서리**로 잰다(GRT-022). 픽 화면에서는
   다우징 고글의 카드 +1을 적용하지 않는다. 카피는 `LanguageSettings` 7언어
   등재(엠대시 금지) — 탑 노드 모달 로컬라이저는 한국어 1종뿐이라 재사용하면
   가격줄만 한국어로 남는다.

## 2. 규율

- **헝크 분리 우선**: `stage_clear_result_reward_plan_builder.gd`(18줄),
  `stage_clear_reward_resolver.gd`(190줄)이 미커밋 WIP이다. 두 파일의 diff를 먼저
  스냅샷하고 은퇴 헝크만 `diff → awk → apply --cached`로 분리해 **격리 worktree
  스모크로 증명한 뒤** 커밋한다. 여러 항목이 같은 파일을 공유하므로 파일 단위가
  아니라 헝크 단위 분리 커밋이다.
- 로그 백업 선행. 표준 래퍼 `-AllowDuringPlay`. 푸시 금지.
- 플래그 OFF 레거시(상자·기존 오퍼 창 포함) 무손상 부정 레그 필수.
- **CI 락스텝**: 신규·개정 씰을 `.github/workflows/godot-ci.yml`과
  `godot/tools/run_pre_push_checks.ps1` 두 리터럴 목록에 동시 등재한다.
- **공허 GREEN 금지**: 이번 반경에 이미 3건이 있다(수련장 Fake 카탈로그, 체스트
  계약 손조립 컨텍스트, 프로덕션 호출부 0건인 보상 사본). 같은 형태를 복제하지
  않는다. 각 어서션은 "실패하려면 코드가 어떻게 망가져야 하는가"에 답해야 한다.
- **1차 RED 약 20건 예상**: 알파벳순 앞쪽 하나가 RED면 뒤가 미실행이다. 러너
  종단선을 인용하고, 없으면 "N개 통과"가 아니라 "첫 실패까지만 실행"으로 보고한다.
- **위험 프리미엄 가중 입력**은 리셋 전에 캡처한다(현행은 항상 1층 엔트리 값으로
  굳어 있고 봉인 스모크가 `floor==1`을 단언한다 — 락스텝 개정 대상).
- **F9 강제 클리어**는 탑 플래그를 보지 않고 레거시 결과화면으로 직행해 픽을
  건너뛴다. 디버그·치트 경로를 감사에 포함한다.
- **전환 비용**: 상자 시트 프리웜 제거와 픽 프리웜 추가를 같은 커밋에 묶는다.
  픽 화면 모듈 조회는 전부 캐시 조회(비생성)로 한다(GRT-042). 카드 아트가 없으면
  경로를 예약하지 말고 기존 플레이스홀더를 가리킨다(GRT-004).
- **은퇴 고아**: 천기보도 퍽은 두 레인이 모두 상자 전용이라 탑에서 이미 효과 0이다.
  픽 절세 등장 확률 퍽으로 축소하고 카탈로그 설명·7언어를 개정한다
  (`treasure_map_perk_port_smoke` 락스텝). 절세무공 로스터 정본이 카탈로그 14종
  대 하드코딩 13종으로 갈려 있으니 하나로 정한다.
- **4천왕 완주 1회 픽**은 건틀릿이 승리 사다리에 미배선이므로 훅 자리만 남기고
  실제 구현은 건틀릿 배선 슬라이스로 분리한다는 범위 선언을 보고서에 적는다.
- 검증: 픽 씰(무리롤 소진·다중 구매·잔여 폐기·비전초식 확정 등장과 런 소멸·
  절세 저확률 등장·상자 부재·4장 배분 순서) + 타워 회귀 세트 + `-Paths` 경고 +
  헤드리스 + Vulkan 캡처 2장 이상(픽 4장 화면 / 비전초식 카드 등장 화면) +
  `run_tower_mode.ps1` 실플레이 재현.
- 판정 불가 지점이 나오면 중단·보고.

**완료 선언 조건**: §1의 6항목 구현·검증 + 게이트 blocked/unverified 0건 +
보고서 완성.
