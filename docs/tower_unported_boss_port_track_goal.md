## 1. 보스당 작업 단위 (보스별 독립 커밋 시리즈, 푸시 금지)

두더지왕 → 아라크네 → 테디베어 → 엘리스 순서를 권장하되, 보스 하나를 끝까지
(구현+검증+보고 섹션) 마친 뒤 다음으로 넘어간다. 보스당:

1. **원본 파리티 조사**: 원본 킷(패턴·스킬·수치·타이밍)을 레퍼런스로 기록.
   GRT-053(수식이 같아도 호출 경로가 다르다)·GRT-052(패들 오프셋)·GRT-009(예측
   모델) 등 포팅 트랩 준수. 원본에 없는 신규 스킬·수치 발명 금지 — 파리티
   예외가 필요하면 보고서에 사유를 기록한다.
2. **스테이지 변형 등록**: 두더지왕·아라크네는 스테이지 2, 테디베어·엘리스는
   스테이지 3의 보스 변형으로 등록한다(스테이지 1의 3보스 변형 체계를 선례로).
   기존 간판 보스(청린귀·환묘 연묘)의 현행 동작 무손상 회귀 레그 필수.
3. **자산**: 원본 자산 이관을 우선하고, 신규 생성이 필요하면 스프라이트
   스킬 파이프라인(`.claude/skills/sprite-generation/SKILL.md`) 산출물의 수용
   게이트를 거친다. 수용 전에는 임시 이관 자산으로 런타임을 먼저 세운다.
   에셋 승격은 에디터 무중단 재임포트 경로를 따르고 헤드리스 `--import` 금지.
4. **검증**: 보스별 포커스 스모크(+부정 레그), 변경 파일 경고 스캔, 헤드리스
   로드, 실 스테이지 라우트 관통, windowed/Vulkan 픽셀 캡처. 슬로우 티어 등
   상태 계약은 `scripts/status/boss_slow_tiers.gd` 기준.

## 2. 공용 규율

- 보스당 커밋을 섞지 않는다 (한 커밋에 두 보스 금지). 신규 `.gd`는 `.gd.uid` 동반.
- 공유 파일(스테이지 라우터·카탈로그) 수정 시 선행 WIP 헝크 제외 + 격리
  스테이징 트리 스모크 증명 (페이즈 A·B 방식).
- 도감 보스 키 등재는 `docs/hwangyeokjeon_codex_design.md` §2.3 정본 규칙을
  따르되, 도감 시스템 자체 구현은 비범위.
- 플레이 중 검증 신정책 준수, 검증 전 로그 백업, baseline RED 분리 보고.
- 로컬 커밋만. 푸시 금지. 표면 명칭은 정본 4종 이름만 사용, 신규 명명 금지.

## 3. 보고 형식 (보스당 섹션)

1. 커밋 목록과 파리티 조사 요약 (원본 대비 예외가 있으면 사유)
2. 게이트 결과 (래퍼 종단선)
3. 자산 상태 (이관 / 신규 생성·수용 대기)
4. fixed / deferred / blocked / unverified 구분
5. **통합 인계**: 통합 담당이 교체할 레지스트리 슬롯 id
   (`floor_02_molewang` / `floor_02_arachne` / `floor_03_teddy_bear` /
   `floor_03_alice`)와 연결에 필요한 변형 id

**완료 선언 조건**: 4종 전부 구현·검증되고 필수 게이트 blocked/unverified
0건 + 보고서 완성일 때만. 일부만 끝났으면 완료 처리하지 말고 끝난 보스까지의
상태를 보고서에 기록한 뒤 중단을 보고한다.
