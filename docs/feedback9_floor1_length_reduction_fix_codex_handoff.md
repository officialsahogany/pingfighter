# 지시문 Y1-수정 — 보스 선택 두 행을 한 행으로 합쳐 3스텝으로

- **발행**: 관제탑 2026-08-27. 기준선 = 본 트리 **`a0f8684e2`**.
  **격리 워크트리 + 격리 브랜치.** 본 트리 편집·통합·푸시 금지.
- **선행**: `docs/feedback9_floor1_length_reduction_codex_handoff.md` (Y1 원안)

## ★관제탑 판정 — Y1 원안은 내 오류였다

원안은 "`index 0` 구분 행을 빼면 두 보스 행 사이 구분 행이 살아남는다"고 했다.
**틀렸다.** 1층 관문 자체가 보스다. `index 0` 구분 행은 장식이 아니라
**관문 보스와 첫 보스 선택 행 사이의 간격**이었다.

세션 보고(0/2,000, `phase_0:boss_adjacencies=1`,
`phase_0:boss_spacing_violations=1`)가 정확하다. **중단 판단이 옳았다.**

관제탑이 추가로 확인한 것: `index 2` 를 뺐어도 똑같이 전멸했다.
`_is_optional_extra_boss` 예외는 `tower_ascent_boss_registry.gd:805` 의
v14 기구(넓은 NPC 행의 한 자리를 대체) 전용이고, 1층 확장의
`optional_boss_encounter` 행에는 그 표식이 붙지 않는다. 따라서

```
1층관문(보스) [구분] 보스선택 [구분] 선택보스 [기존3] 2층관문(보스)
```

에서 **구분 행 3개가 전부 하중을 받는다. 현행 5행은 이미 최소다.**
보스 선택 행을 2개로 두는 한 4스텝은 구조적으로 불가능하다.

## ★성립 근거 — 간격 규칙은 행 단위다

`_count_boss_spacing_violations` 는 **행에 보스가 하나라도 있으면 그 행을
"보스 행" 하나로 센다.** 한 행에 보스가 둘이어도 하나다.

따라서 두 보스 선택 행을 **한 행으로 합치면** 필요한 완전 NPC 행이
3개에서 2개로 준다.

```
1층관문(보스) [구분 2레인] [보스선택 3레인] [기존 3레인] 2층관문(보스)
                            └ 보스A / 보스B / 회피
```

= **3행 = 3스텝.** 예외 신설 없이 간격·인접 규칙을 전부 만족한다.

## 사용자 확정 결정

**A안 채택. 보스 선택 두 행을 3레인 한 행으로 합친다.**

## 요구

1. `FLOOR_ONE_EXPANSION_ROW_ROLES` 를 **2행**으로 줄여라.
   구분 행 1개 + 보스 선택 행 1개. 역할 이름은 네가 정하되 기존
   `npc_separator` 관례를 따르라.
2. **새 보스 선택 행은 3레인이다.**
   - 레인 2개 = 1층 로스터 중 **관문이 쓰지 않은 서로 다른 보스 2종**
   - 레인 1개 = **비전투 회피 레인**
   1층 로스터는 `달지`·`각시탈`·`포도대장` 3종이다
   (`tower_ascent_boss_registry.gd:42~44`).
   ⚠**두 레인에 같은 보스가 들어가면 안 된다.** 관문 보스와도 겹치면 안 된다.
3. **`floor_one_boss_choice` 표식은 보스 레인 2개에 유지하라.** 노드 수 2가
   유지되어야 `floor_one_choice_count` 계열 단언이 산다.
4. `_floor_one_optional_encounter_enabled` 는 **확률 분기가 아니게 된다**
   (두 보스가 항상 같은 행에 들어가므로). 함수를 지우든 상시 true 로 남기든
   **피드백2 4항의 목적 — 모든 시드에서 로스터 3종 전원이 지도에 보인다 —
   을 깨지 마라.** 처리 방식을 보고하라.
5. `audition_enabled` 경로는 확장 행을 쓰지 않는다. 회귀시키지 마라.
6. **2층 이상 밀도 불변.** `TEMP_OPTIONAL_ROWS_PER_FLOOR` 계열 금지.

## 바꾸면 안 되는 것

- 층 관문 = 단일 레인 초크포인트 보스.
  `gatekeeper_boss_count == TowerAuditionBuildConfig.STANDARD_CLEAR_FLOOR`
- `_has_floor_one_boss_avoidance_path` 성립. 새 구조의 회피 레인이 이를
  **구조적으로 보장**해야 한다.
- 간격·인접 규칙 자체. **예외를 신설하지 마라.** A안은 예외 없이 성립한다.

| 회피 이슈 발생 시드 | 352 (17.60%) | ? |

⚠**성공률 100% 미만이면 착지 불가다.** 재시도 상한을 올려 덮지 마라.

★**회피 이슈율은 개선되어야 정상이다.** 회피 레인이 행 구조에 박히므로
17.60% 보다 낮아야 한다. **오히려 오르면 설계가 의도대로 안 붙은 것이니
멈추고 보고하라.**

⚠**내보낸 빌드 지도 생성 16.5% 실패** 보류 건이 있다. 이 변경이 그것을
악화시키지 않는지 함께 보라.
