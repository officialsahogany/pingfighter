  exit 1. 2회 연속 실행에서 동일하므로 결정적이다.
- **본 트리에서는 GREEN이다**(관제탑이 HEAD에서 직접 실행:
  `tower_map_scroll_wiring_contract_smoke: PASS=10 / ok`). 따라서 인과는
  이 커밋으로 확정된다.
- 이 씰은 `.github/workflows/godot-ci.yml`과
  `godot/tools/run_pre_push_checks.ps1`에 **양쪽 등재**된 하드 게이트다.
- 추정 기전(관제탑 미확정): segment_floor 2~8 밴드가 2행(정확히 320px =
  네이티브 타일 1장)에서 3행(1.5장)으로 늘어나면서
  `_build_scroll_background`의 밴드 아트 variant 선택이 인접 층 간
  중복을 낸다. `resolve_band_asset_key`의 base 인덱스가 인접 층마다
  2 mod 3씩 어긋나는 구조라 정적 모델로는 재현되지 않았다 —
  **계측해서 정확한 충돌 층 쌍을 특정하라.**

수리 방향은 **먼저 판정**하고 시작하라.

- (a) **제품 수리**: 밴드 높이가 타일 배수가 아니게 된 것이 문제라면,
  variant 선택 인덱스를 행 수 변화에 맞게 재유도해 인접 층 반복을
  없애라. 씰이 요구하는 계약("인접 렌더 층은 한 variant를 반복하지
  않는다")은 그대로 유지된다.
- (b) **씰 재보정**: 3행 밴드에서는 타일 1.5장이라 같은 variant 반복이
  **구조적으로 불가피**하다면, 씰의 계약 자체가 2행 전제 위에 세워진
  것이므로 새 전제로 갱신하라. 이 경우 **왜 불가피한지 수치로 증명**
  하고, 대신 무엇을 보장하는지(예: 연속 3장 반복 금지) 새 단언으로
  대체하라. 단언을 그냥 삭제하는 것은 반려한다.

어느 쪽이든 정확한 충돌 층 쌍과 근거를 보고에 넣어라.
