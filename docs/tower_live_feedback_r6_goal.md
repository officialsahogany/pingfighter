## 1. 카메라 줌인 2배

### 현행 `[확인]`

`tower_ascent_tuning.gd:97` `const TEMP_MAP_CAMERA_ZOOM := 2.15`

줌 인트로가 2.15 에서 2.537 까지 1초(72틱) smoothstep 으로 올린 뒤 워커
추적으로 인계한다.

### 계약

- ★**"지금보다 2배"가 무엇의 2배인지 판정하고 근거를 적어라.**
  기본 줌 2.15 를 4.30 으로 올리는 것인지, 인트로 도달점 2.537 만 올리는
  것인지 갈린다. **Fable 권고는 기본 줌을 4.30 으로 올리고 인트로 도달점도
  같은 비율(5.074)로 따라 올리는 것**이다. 사용자 표현이 "노드 화면에서
  카메라가 줌인 될 때"이므로 지도 화면 전반을 가리킨다.
- ★**클램프를 확인하라.** `tower_ascent_map_camera_model.gd` 가 콘텐츠 rect
  와 패딩으로 오프셋을 제한한다. 줌이 커지면 화면이 콘텐츠보다 커져
  클램프가 뒤집힐 수 있다. 경계에서 지도가 튀지 않는지 보라.
- ★**한 화면에 보이는 행 수가 줄어든다.** 현행 2.15 에서 약 326 월드px,
  즉 행 2개가 보인다. 4.30 이면 약 163px 로 **행 1개**만 보인다.
  경로 선택 시 다음 후보가 화면 밖으로 나가면 플레이가 불가능해진다.
  **선택 가능한 후보가 항상 보이는지 반드시 확인하라.** 안 보이면 중단하고
  보고하라.
- ★**지도 배경 아트가 배선 중이다**(`docs/tower_map_scroll_wiring_goal.md`).
  밴드가 692x320 이며 2.15 배 기준으로 승인됐다. 줌이 바뀌면 밴드 한 장이
  화면을 넘긴다. **그 작업과 충돌하지 않는지 확인하고, 필요하면 순서를
  조율하라.**

## 2. 철심공 시작 카드 노출 ★먼저 판정

### Fable 이 확인한 현행 `[확인]`

**철심공은 퍽이면서 동시에 수련 항목이다. 이름만 겹치고 다른 것이다.**

| 정의 | 위치 | 표시 이름 |
|---|---|---|
| 퍽 | `runtime_perk_catalog.gd:1025` | **철심공** |
| 수련 | `physique_training_catalog.gd:76` | **철심공 수련** (`source_perk_id: bulletproof_hat`) |

시작 카드는 퍽 풀에서 뽑는다. 즉 사용자가 본 것은 **퍽 철심공**이며
**정상 동작일 가능성이 높다.** 수련 카드가 샌 것이 아니다.

### 계약

- ★**S1 에서 먼저 판정하라.** 시작 카드 오퍼 빌더가 실제로 무엇을 뽑았는지
  확인하라. 퍽이면 결함이 아니다. 수련 항목이 섞였으면 결함이다.
- **결함이 아니면 고치지 마라.** 대신 **왜 헷갈리는지**가 진짜 문제다.
- 판정 결과를 보고서 맨 앞에 적어라.

### 결함이 아닌 경우 — 표기 문제로 다룬다

퍽 `철심공` 과 수련 `철심공 수련` 이 같은 화면 계열에 나오면 구분이 안 된다.
같은 계열이 여럿이다.

| 퍽 | 수련 |
|---|---|
| 철심공 | 철심공 수련 |
| 유운보 | 유운보 수련 |
| 순환결 | 순환결 수련 |
| 태허심법 | 태허심법 수련 |

- ★**카드에 종류가 읽히게 하라.** 시작 카드에는 이미 "비급" / "2성" 같은
  부제가 있고 수련 카드에는 "기초 수련" 이 있다. **그 부제가 충분히
  구분되는지 판정하고 근거를 적어라.**
- 부족하면 개선안을 **제시하고 멈춰라.** 문구 변경은 사용자 확정이 필요하다.
- ★**한국어 카피에 엠대시(—) 금지.** 신규 문구는 7 로케일 등재.
- ★**내부 식별자를 바꾸지 마라.** 표시 문구만 다룬다.
