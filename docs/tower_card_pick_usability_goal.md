## 0. Fable이 확인한 원인 `[확인]`

### 0-1. ★P0 시작 카드가 20초 만에 사라지고 아무것도 안 준다

`tower_ascent_tuning.gd:110`

```gdscript
const TEMP_START_CARD_FAILSAFE_TIMEOUT_SEC := 20.0
```

`tower_start_card_state.gd:183-189`가 그 시간이 지나면 이렇게 끝낸다.

```gdscript
_selection_result = {
    "accepted": false,
    "reason": "start_card_failsafe_timeout",
    "skipped": true,
}
_skipped = true
_finish_phase()
```

**획득 없이 프롤로그로 넘어간다.** 사용자는 카드 셋을 읽고 고민하다가 1분쯤
지났고 그대로 잃었다.

실패안전 장치는 소프트락을 막으려는 것이지 **숙고를 처벌하려는 것이 아니다.**
런 시작 카드는 그 런 전체의 빌드 방향을 정하는 화면이라 20초는 처음 보는
플레이어에게 턱없이 짧다.

### 0-2. 흡수 연출이 좌측 필러로 날아간다

`runtime_perk_overlay_renderer.gd:862` `_build_tower_reward_absorbing_rect`가
카드를 30px 들어올린 뒤 목표 지점으로 보낸다
(`TEMP_TOWER_REWARD_ABSORB_LIFT_PX := 30.0`).

사용자 요구는 **하단 중앙으로 끌어오는 느낌**이다. 카드가 내 쪽으로
들어오는 것이 읽혀야 한다.

### 0-3. 카드 설명이 잘린다

`runtime_perk_choice_layout.gd:21-26`

```gdscript
const CARD_DESCRIPTION_TOP_RATIO := 0.595
const CARD_DESCRIPTION_HEIGHT_RATIO := 0.375
```

`_wrap_text_px`가 줄 수 상한을 걸어 로케일·문구 길이와 무관하게 자른다.
긴 설명 카드는 **무슨 기능인지 알 수 없다.**

주석이 가리키는 씰이 있다.
`runtime_perk_choice_stats_band_smoke._verify_worst_case_description_stays_inside_card`

### 0-4. 설명에 수치 강조가 없다

선택 카드 설명이 갈색 단색이라 **수치와 배율이 본문에 묻힌다.**
플레이어가 무엇이 얼마나 오르는지 즉시 못 읽는다.

### 0-5. 초식 툴팁이 카드 화면과 연동되지 않는다

인게임에는 초식 구슬 슬롯 호버 툴팁이 있다
(`smasher_skill_orb_tooltip_renderer.gd`, `skill_orb_tooltip_effect_preview_renderer.gd`).

카드 선택 화면에서 초식 카드에 호버해도 그 툴팁이 뜨지 않는다.
사용자는 **같은 툴팁이 별도 패널로 뜨기를** 원한다.

## 2. 슬라이스별 계약

### S1. 시작 카드 타임아웃 ★P0

**실패안전은 유지하되 콘텐츠를 잃지 않게 하라.**

1. `TEMP_START_CARD_FAILSAFE_TIMEOUT_SEC`를 크게 올려라. **최소 180초**를
   권한다. 정확한 값은 판단해서 정하고 근거를 보고서에 적어라.
2. ★**타임아웃이 걸려도 카드를 주어라.** 지금의 `skipped: true` 경로 대신
   **활성화된 첫 카드를 자동 선택**하는 것이 옳다. 실패안전이 콘텐츠를
   삭제해서는 안 된다.
3. 자동 선택이 발생했음을 플레이어가 알 수 있게 하라. 조용히 고르면 혼란만
   준다. 최소한 흡수 연출은 타야 한다.
4. ⚠ **소프트락 방지라는 원래 목적을 없애지 마라.** 입력이 끊겨도 화면이
   영원히 남으면 안 된다.
5. 승리 보상 카드 화면에도 같은 종류의 타임아웃이 있는지 확인하고, 있으면
   같은 원칙으로 고쳐라. **단일 검색어로 없다고 단정하지 마라.**

**씰**: 타임아웃 경과 후 **획득 결과가 비어 있지 않은지** 단언하라.
현행 동작(빈 결과)을 RED로 잡는 반증 레그를 남겨라.

### S2. 설명 잘림 해소

- 먼저 **어떤 카드가 실제로 잘리는지 전수 조사**하라. 카탈로그를 돌면서
  최장 설명을 뽑고 현재 줄 예산에서 몇 자가 버려지는지 수치로 보고하라.
- 해법 후보를 비교하고 근거로 고르라.
  - 설명 영역 높이·비율 상향
  - 폰트 크기 하향
  - 문구 자체를 짧게 재작성(다국어 동반 필요)
  - 카드 크기 상향
- ★**GRT-021**: 예산을 넘기면 드로어가 **조용히 행을 버린다.** 늘린 값에서
  **실제 append된 행 수**를 단언하라. 표 값만 보면 안 된다.
- ★**GRT-022**: 카드 치수를 바꾸면 그린 자리와 클릭 자리가 갈라진다.
  `get_card_rects` / `get_card_index_at`에 같은 값이 흐르는지 확인하고
  **반증은 카드 상단 모서리**로 재라.
- 기존 씰 `_verify_worst_case_description_stays_inside_card`를 락스텝
  갱신하라. **그 씰이 현재 통과 중이라면 "잘린 상태"를 정상으로 잠그고 있다.**
  기준을 "카드 안에 들어간다"에서 **"버려진 행이 0이다"**로 바꿔라.

### S3. 수치 강조

- 설명 안의 수치·배율·시간에 **강조색**을 주어라. 본문은 현행 색을 유지한다.
- 강조 규칙을 **단일 소유자**에 두고 시작 카드와 보상 카드가 함께 쓰게 하라.
  두 화면이 따로 구현하면 다음 화면에서 또 갈린다.
- ⚠ **다국어를 깨지 마라.** 숫자 위치가 언어마다 다르므로 문자열을 파싱해
  자르는 방식이면 로케일별로 검증하라. 카탈로그에 마크업을 넣는 방식이면
  **모든 로케일에 동시 적용**해야 한다.
- 색은 기존 팔레트에서 고르라. 새 색을 발명하지 마라.

### S4. 흡수 연출 방향

- 목표 지점을 **하단 중앙**으로 바꿔라. 카드가 플레이어 쪽으로 들어오는
  느낌이어야 한다.
- 시작 카드와 보상 카드 **양쪽에 적용**한다.
- 현행 `TEMP_TOWER_REWARD_ABSORB_LIFT_PX := 30.0`의 들어올림 단계는 유지해도
  좋다. 바뀌는 것은 비행 목적지다.
- 지속 시간(`TEMP_START_CARD_ABSORB_DURATION_SEC := 0.78`)이 새 경로에
  적절한지 판정하라. 거리가 길어지면 조정이 필요할 수 있다.
- ★**연출 난수는 게임플레이 RNG를 소비하면 안 된다.** 독립
  `RandomNumberGenerator`를 쓰라.

### S5. 초식 툴팁 연동

- 인게임 초식 구슬 툴팁의 **기존 소유자를 재사용**하라.
  `smasher_skill_orb_tooltip_renderer.gd`와
  `skill_orb_tooltip_effect_preview_renderer.gd`가 시작점이다.
  **새 툴팁을 만들지 마라.** 두 벌이 되면 다음 개정에서 갈린다.
- 카드 선택 화면에서 **초식 카드 호버 시** 별도 패널로 띄운다.
  시작 카드와 보상 카드 **양쪽**이다.
- 카드 위에 겹쳐 다른 카드를 가리지 않게 배치하라. 화면 가장자리에서
  잘리지 않는지 확인하라.
- ★**GRT-044**: 전체화면 오버레이는 context의 game size로 폴백하면 실제
  뷰포트의 일부만 덮는다. 트리 안에서는 `canvas.get_viewport_rect().size`를
  우선 쓰라.
- 초식이 아닌 카드(무공, 무공합일 등)에는 뜨지 않아야 한다. 부정 레그를 둬라.

- 내부 식별자와 저장 키를 바꾸지 마라.

- 로그 백업 선행. 표준 래퍼 `-AllowDuringPlay`. 푸시 금지.
