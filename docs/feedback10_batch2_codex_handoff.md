# Z4 — 정전기장 4초 → 10초 + 서브 한정

## 사용자 확정

> 상승무공 **정전기장이 4초 지속에서 10초 지속으로** 수정.
> **서브일 때만 정전기장이 뜨고 서브 타임이 끝나면 사라짐.**

## ★관제탑 확정 위치

`godot/scripts/characters/perk_fusion_byproduct_runtime.gd`

```gdscript
const STATIC_FIELD_ID := "static_field"
const STATIC_FIELD_DURATION_SEC := 4.0      # ★:21 — 이 값을 10.0 으로
...
result["static_field"] = { ..., "duration_sec": STATIC_FIELD_DURATION_SEC }   # :221~223
```

문구는 `perk_fusion_localization.gd:161`
`"static_field": "실점 뒤 4초 동안 보스 이동 속도 -30%"`.

## 요구

1. 지속 **4.0 → 10.0**. 리터럴 하드코딩 금지, 위 상수만 고쳐라.
2. ★**서브 한정 게이팅이 두 번째 요구다.** 현재는 "실점 뒤" 발동이다.
   **서브 대기 중에만 존재하고 서브가 끝나면 사라지는지** 확인하고,
   아니면 그렇게 만들어라. **어느 상태가 "서브 타임"인지 생산 경로에서
   특정하고 보고하라.**
3. **문구를 전 지원 언어에 동기화하라.** `perk_fusion_localization.gd` 는
   KO/EN 외 언어 블록도 있다. 4초 표기가 남으면 안 된다.
   ⚠**한국어 카피에 엠대시(—)를 쓰지 마라.**
4. ⚠**FX 생명주기**: 서브 종료 시 사라져야 하므로 분리된 FX 호스트가 있으면
   정리 경로가 필요하다. Y7(`8204cdc56`)·Z2(`40185bb97`) 가 같은 유형을
   닫았다. **해당하는지 확인하고 보고하라.**

## 씰

지속 10초 단언 + 서브 종료 시 소멸 단언. 4초로 되돌리면 RED 가 되는지 반증.

# Z5 — 개광결이 축뢰심법에 적용되지 않는다

## 사용자 보고

> **개광결이 축뢰심법에 적용되지 않고 있음.**

## ★관제탑이 확인한 것 (재조사 금지)

- **축뢰심법의 퍽 id 는 `combo_amplifier_chip`** 이다
  (`runtime_perk_catalog.gd:429` 이름, id 는 그 블록 키).
- **`PROGRESSIONS` 에 등록돼 있다** — `runtime_perk_progression.gd:124`.
  레인 4개가 전부 정의돼 있다.
  `drive_speed_bonus` / `drive_curve_bonus` / `smash_speed_bonus` /
  `initial_boost_decay_reduction`.
- **`has_polish_amplifiable_lane` 목록에도 `true` 로 있다**(`:37`).
- 명시적 `polish_amplifiable: false` 가 없고 기본값이 `true` 다
  (`is_polish_amplifiable_lane` `:323~327`).

★**즉 카탈로그·진행표상으로는 증폭 대상이 맞다.** 등록 누락이 아니다.

## 그러므로 — 소비 지점을 의심하라

**증폭된 값을 실제로 읽는 곳이 원본 값을 읽고 있을 가능성이 높다.**

1. 벽력타/천뢰격의 공속·커브·부스트 감쇄를 계산하는 **런타임 소비 지점**을
   찾아라. 그 지점이 개광결 증폭을 거친 값을 쓰는지, 카탈로그 원본을 쓰는지
   확인하라.
2. `perk_conversion_values.gd:98~101` 주석이 개광결 계약을 설명한다.
   "모든 무공의 수치 효과"를 fail-open 으로 증폭한다고 돼 있다.
   **그 fail-open 경로를 이 퍽이 통과하는지 실측하라.**
3. ⚠**GRT-041(퍽 표시 Projection-분기 후처리 탈락)** 을 읽어라.
   라이브는 항상 projection 경로다. **표시만 맞고 실효과가 안 붙는** 유형이
   이미 등록돼 있다. **표시 실패인지 적용 실패인지 먼저 가르고 보고하라.**

## 씰

개광결 보유 시 축뢰심법 4레인의 **실효값**이 증폭되는지 단언하라.
⚠**툴팁 문자열만 확인하는 씰을 만들지 마라.** 그게 지금 통과하고 있을 수 있다.

# Z6 — 보스 스킬카드가 중간중간 멈춘다

## 사용자 보고

> 보스 스킬카드가 부드럽게 이어지는 게 아니라, **부드럽게 이어지면서
> 중간중간 부드럽게 멈추면서 이어짐을 반복**하고 있음.

## 조사 지침

관제탑이 위치를 특정하지 못했다. **네가 진범을 증명하라.**

의심 축 셋을 준다. **하나씩 격리해서 증상이 사라지는 것만 진범으로 인정하라.**

1. **트윈/애니메이션 재시작** — 카드 레일이 매 프레임 트윈을 새로 만들거나
   상태 변화마다 리셋하면 "멈췄다 이어짐"이 반복된다.
2. **프레임 시간원 혼용** — `delta` 와 벽시계, 또는 물리/프로세스 시간원이
   섞이면 catch-up 프레임에서 튄다.
3. **드로우 예산 게이팅** — 예산 초과 프레임에 갱신을 건너뛰면 끊긴다.
   GRT-043(HUD 상시-가시성 승격 × 프리미엄 절차 드로우)를 읽어라.

⚠**증명 방법**: 연속 프레임의 카드 위치·진행률을 **수치로 로그**하고
멈추는 구간의 값 변화를 보라. **정지 캡처 1장은 증거가 아니다.**
**10프레임 이상 연속 캡처**를 수리 전·후로 내라.

## 참고

메모리에 보스 스킬카드 셔플 모션 v2 작업이 **미커밋 WIP** 로 남아 있다는
기록이 있다. **본 트리 미커밋 변경이 이 증상의 원인이거나 이미 수리를
담고 있을 수 있다.** 착수 전 `git status` 로 관련 파일의 더티 여부를 확인하고
보고하라. ⚠**본 트리 WIP 를 건드리지 마라.** 확인만 하라.

# Z7 — "boss serve preparing..." 리디자인 + 한글화

## 사용자 보고

> 서브일 때 **`boss serve preparing...`** 이게 **링피아 스타일** 같다.
> **환격전에 맞게 리디자인**하고 **한국어일 땐 한글로**.

## ★관제탑 확정 위치

`godot/scripts/hud/serve_wait_indicator_renderer.gd` `_draw_boss_serve` (`:181`)

```gdscript
var info_text := "Preparing..."
...
	info_text = "Ready"
_draw_text_centered(canvas, ..., info_text, INFO_FONT_SIZE, info_color)
```

★**영문이 하드코딩돼 있고 다국어 키가 전혀 없다.** `serve_label` 은 인자로
받지만 `info_text` 는 리터럴이다.

## 요구

1. **다국어 키로 빼라.** 지원 언어 전체에 넣어라.
   한국어 문구는 환격전 신화무협 어조에 맞게 정하고 제안하라.
   (예시일 뿐 강제 아님: `기를 모으는 중…` / `준비 완료`)
   ⚠**한국어 카피에 엠대시(—) 금지.** 멈춤은 마침표나 쉼표로.
2. **`serve_label` 도 같이 확인하라.** 호출부에서 무엇이 들어오는지 보고,
   영문 잔재가 있으면 함께 처리하라.
3. ★**시각 리디자인.** 사용자는 "링피아 스타일"을 지적했다. 현재는 흰 텍스트
   두 줄이다. 환격전 톤(먹색·금색·한지·전통)에 맞게 다듬어라.
   ⚠**절차 드로우로 닫힌 둘레(링·외곽선·점선)를 남발하지 마라.** 싸구려로
   보인다. 채움 다겹·광대·빛점으로 만들어라.
   ⚠**가독성이 우선이다.** 서브 대기는 짧은 순간이라 즉시 읽혀야 한다.
4. ⚠**신규 PNG 를 만들면 `.import` 사이드카를 반드시 동반하라.** 격리
   워크트리는 에디터가 없어 사이드카가 생기지 않는다. **못 만들면 보고에
   명시하라.** 조용히 PNG 만 커밋하면 익스포트에서 텍스처가 빈다(X3 실사고).
