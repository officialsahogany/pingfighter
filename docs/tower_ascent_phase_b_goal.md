## 1. 범위 (이 페이즈에서 하는 것)

정본 절 번호 기준. **각 항목은 반드시 독립 로컬 커밋으로 남긴다** (의존성
순서로 구현하되 커밋 경계는 번호 단위). **푸시 금지.**

1. **지도 생성기 코어** (§3.1, §5): 고정 그래프 검증판을 대체할 실 생성기.
   **시드 결정성 계약**: 지도 시드는 게임플레이 RNG와 분리된 전용
   `RandomNumberGenerator` 인스턴스가 소유하고, (동일 시드 + 동일 생성기 버전)
   = 바이트 동일 그래프를 보장한다. 생성기 버전 상수를 두고 스냅샷에 기록한다.
   차분 시드 테스트로 지도 생성이 게임플레이 RNG를 전진시키지 않음을 증명한다.
2. **스냅샷 통합·복구** (§5): 그래프 직렬화 방식(전체 그래프 vs 시드+결정론
   파생)을 **구현에서 명시적으로 선택해 보고서에 문서화**하고, 직렬화 → 복구
   → 동일 그래프 왕복을 스모크로 봉인한다. **재시도(보석 재도전) 시 지도는
   불변**이다 — 이미 생성된 런 지도·노드 상태는 재도전으로 재굴림되지 않는다
   (재굴림 대상은 페이즈 A가 확정한 전투 내부 예산뿐).
3. **12층 층 구조와 행 배치 규칙** (§3.3, §3.4): 층 전환 경계, **층 경계 =
   수문장 보스 행(회피 불가)**, 다음 행 후보 2택 유지, 노드 타입 슬롯
   배치(전투·광폭화·상점·수련장·파계승·수호의 샘터·휴식). 층당 행 수·노드 출현
   가중은 튜닝 상수로 두되, **예산 불변식**(9층 런 전투 노드 수가 튜닝 범위
   안에 있음)을 생성 결과에 대해 스모크로 단언한다.
4. **12층 보스 풀 레지스트리 + 껍데기 슬롯 등록**: §3.3 표의 층별 풀을
   데이터로 등록한다. **껍데기 보스의 등록 범위 = 슬롯 등록 + 기존 보스
   대역(stand-in) 매핑까지만.** 신규 명칭·아트·킷 발명 금지 — 대역 지정은 튜닝
   표의 데이터로만 하고, 미포팅 4종(두더지왕·아라크네·테디베어·엘리스)과 신규
   설계 3종(9층·4천왕·12층)도 동일하게 슬롯 + 대역으로 채운다. 실체 교체는
   콘텐츠 트랙 소관.
5. **회피 규칙** (§3.3): 선택지에서 지나친 보스는 그 런에서 재등장하지 않는다.
   회피(소멸) 보스 목록은 `tower_ascent_run_state` 스냅샷에 저장하고, 이후 행
   생성·후보 제시가 이를 존중함을 스모크로 단언한다.
6. **광폭화 노드 마킹** (§3.5): 지도 표기용 확정 광폭화 노드 + 일반 보스
   노드의 소확률 광폭화 롤(기회당 1회, 지도 생성 시 확정)과, 페이즈 A 상자
   계약의 위험(risk) 파라미터 연동까지. **광폭화 보스의 실제 전투 효과(스킬
   강화·덩치 증가) 포팅은 비범위**다 — 마킹과 보상 연동만.
7. **지도 렌더러 데이터 주도 전환**: 슬라이스의 고정 검증판 렌더를 실 생성
   그래프 표시(전도 공개, 다음 행 2택만 활성, 이동 연출)로 교체한다. §4 화풍
   적용은 아트 트랙 소관이므로 현 placeholder 스타일 유지 — 데이터 주도
   구조만. 가시 작업이므로 windowed/Vulkan 픽셀 캡처 QA 포함.

## 3. 발명 금지 + 명명된 튜닝 상수 규칙

- 정본에 없는 수치(층당 행 수, 노드 출현 가중, 광폭화 확률, 껍데기 대역 매핑
  등)는 **발명해서 흩뿌리지 말고**
  `godot/scripts/tower_ascent/tower_ascent_tuning.gd` 단일 튜닝 표에
  명명 상수 + 임시값으로 둔다. 페이즈 A의 15개 상수와 같은 표를 공유하며,
  같은 의미의 중복 상수를 만들지 않는다.
- 임시값을 넣은 상수는 **전부** 보고서의 튜닝 표 섹션에 (상수명, 임시값,
  근거 한 줄)로 목록화한다. 목록에 없는 발명값이 코드에 남으면 페이즈 실패다.
- 정본과 코드 현실의 충돌을 발견하면 그 항목은 구현을 멈추고 보고서
  "설계 충돌" 섹션에 기록한다.

## 4. 검증·커밋 규율

- 항목별 분리 커밋(§1 번호 단위 **필수**). 커밋마다: 포커스 스모크(+역방향/부정
  레그), 변경 파일 경고 스캔(`-Paths`), 헤드리스 로드, `git diff --check`.
- **플래그 OFF 무손상 레그 필수**: 각 커밋에 OFF 경로가 기존 동작을 보존함을
  단언하는 스모크 포함. **기존 일반 전투 흐름(스테이지 진행·결과화면 래더)의
  회귀 검증**을 페이즈 A의 OFF smoke와 관련 소비자 회귀로 유지한다.
- **결정론 필수 레그**: 동일 시드 2회 생성 = 동일 그래프, 상이 시드 = 상이
  그래프, 스냅샷 왕복 동일성, 게임플레이 RNG 비오염(차분 시드), 재도전 후
  지도 불변.
- 공유 파일은 선행 WIP 헝크 제외 + **인덱스 트리 격리 스테이징 트리 스모크
  증명** 후 커밋 (페이즈 A 방식 그대로).
- ⚠ **`stage_clear_result_reward_plan_builder.gd`를 수정하게 되면, 페이즈 A
  교정 커밋(`07c5ba932`)과 동시 진행 중인 7점제 score-rule WIP의 같은 취지
  헝크를 반드시 대조**하고, 대조 결과를 보고서에 기록한다.
- 플레이 중 검증 신정책(`-AllowDuringPlay`·BelowNormal·finally 복구·고유 로그)
  준수. 검증 전 Godot 로그 디렉터리 백업.
- 전체 스캔 베이스라인 RED(선재 WIP 소속)는 분리 보고, 이번 범위 수리 금지.

6. 설계 충돌·미결·미검증 구분 목록 (fixed / deferred / blocked / unverified)
7. `stage_clear_result_reward_plan_builder.gd` 대조 결과 (수정했을 경우)
