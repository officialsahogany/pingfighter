## 1. ★바위낙하는 청린귀 전용

> 스테이지2에서 플레이어 6점 획득 시 바위낙하 이벤트가 일어나는 건
> **청린귀 전용**이다. **지굴왕과 거미각시에서는 일어나면 안 된다.**

### Fable이 확인한 것 `[확인]`

지진은 `stage2_boss_skill_state.gd`(기본 청린귀)가 소유한다.
`_activate_quake_from_cooldown` / `_update_quake_schedule` 이다.

변형 skill state 는 `update()` 에서 지굴왕·거미각시 상태로 위임하고
`super.update()` 를 부르지 않는다. **그러므로 그 경로로는 안 나와야 한다.**

★**그런데 실제로 나온다.** 다른 경로가 있다는 뜻이다.

- **6점 트리거를 먼저 찾아라.** Fable 검색으로는
  `stage2_boss_skill_state.gd`·`stage2_quake_coordinator.gd`·
  `stage2_pillar_background.gd` 어디에도 점수 기반 조건이 안 잡혔다.
  ⚠ **단일 검색어로 판정하지 마라.** 점수 상수가 파생값일 수 있다
  (GRT-054). 승리 점수에서 유도되는지 확인하라.
- 배경(`stage2_pillar_background`)이 스스로 도는지, 별도 코디네이터가
  도는지 파일:줄로 지명하라.
- 원인을 확정한 뒤 **변형에서만 막아라.** 청린귀는 그대로다.

### 씰

- 지굴왕·거미각시에서 **6점 도달 후에도 바위낙하가 발동하지 않는지**
  단언하라. 플래그가 아니라 실제 낙하 payload 수다.
- ★**청린귀 무손상** 부정 레그를 둬라. 이것이 핵심이다.
- 물바주포 등 형제 스킬 무손상도 확인하라.

## 2. 활주구슬 카드 비용 무혼 2 → 3

- 보상 픽 비용은 `tower_reward_pick_offer_builder.gd:90` 부근에서
  `kind` 별로 갈린다. **활주구슬이 어느 kind 인지 먼저 확인하라.**
- ★**해당 카드만 3으로 올려라.** 같은 kind 의 다른 카드까지 올리면 안 된다.
  kind 단위로만 갈리면 **별도 분기가 필요하다.** 판단하고 근거를 적어라.
- ★**기획서 §3.10 단가 통일 조항과 어긋난다.** v1.10 이 "노드와 픽의 무혼
  단가는 동일"로 확정했다. **이번 상향은 그 예외다.** 기획서에 예외로
  기록하고 이유를 적어라. 안 하면 다음 사람이 되돌린다.
- 씰: 활주구슬 비용이 3 인지, 다른 카드가 종전 값인지 각각 단언하라.

## 3. 경로 바람 이펙트를 날씨와 동일하게

> 풍향계가 나타날 때, 즉 바람이 불 때 **실제 날씨의 미풍·강풍 이벤트처럼
> 바람 이펙트를 동일하게 연출**한다.

- ★**날씨 바람 이펙트의 소유자를 먼저 지명하라.** 파일:줄과 파티클·셰이더
  구조를 표로 남겨라.
- 미풍과 강풍의 **단계 구분이 어떻게 되는지** 확인하고, 경로 바람의 세기
  단계(약·중·강)와 어떻게 대응시킬지 정하라.
- ★**날씨 이펙트 소유자를 복제하지 말고 재사용하라.** 복제하면 다음
  개정에서 갈린다.
- ★**§6 판정은 그대로다**(`7d47f516a`). 경로 바람은 조준 범위만 편향하고
  비행 중 힘을 주지 않는다. **이번 작업은 연출만이다.** 물리를 건드리지 마라.
- ★**GRT-045**: 스크린 공간 FX 호스트는 플레이필드 클립이 필요하다.
  경로 화면에서 letterbox 로 새지 않는지 비헤드리스 픽셀로 확인하라.
- ★**무풍이면 이펙트도 0** 이어야 한다. 드로 비용을 확인하라(GRT-043).

### 씰

- 바람 세기별로 **이펙트 payload 수가 다른지** 단언하라.
- **무풍에서 payload 0** 부정 레그를 둬라.
- **날씨 이벤트 바람 무손상** 부정 레그를 둬라. 공용 소유자를 건드린다.

## 4. 노드 지도가 전체화면이 아니다

> 캐릭터 이동(카메라 줌인 등) 때 지도가 전체화면이 아니다.
> **필러 배경 끝까지 지도로 꽉 차야 한다.**

### Fable이 확인한 것 `[확인]`

`tower_ascent_flow_renderer.gd`

```gdscript
const PLAYFIELD_SIZE := Vector2(760.0, 750.0)
const MAP_RECT := Rect2(34.0, 24.0, 692.0, 702.0)
```

★**지도가 플레이필드 안의 692x702 사각형에 갇혀 있다.** 사방에 여백이 있고
플레이필드 자체도 필러 안쪽이다.

- ★**"필러 배경 끝까지"가 무엇을 뜻하는지 판정하라.**
  플레이필드 전체(760x750)인지, 필러를 포함한 화면 전체인지 갈린다.
  **화면 전체면 게임 좌표를 벗어나므로 스크린 공간 렌더가 필요하다.**
  판단하고 근거를 적어라. 판정이 갈리면 중단하고 물어라.
- ★**`draw_fullscreen_map` 이 이미 있다**(`:223`). 그것과 인게임 지도의
  관계를 먼저 확인하라. 두 경로가 갈려 있을 수 있다.
- ★**승인된 방여도 밴드는 692x320 이다.** 지도 폭이 바뀌면 밴드 배치가
  달라진다. `f10de9fb4` 의 "가로로 늘리지 않는다" 계약을 지켜라.
  넓어진 폭은 **가로 타일이나 종이 여백**으로 채운다. 늘리지 마라.
- ★**노드 좌표가 `MAP_RECT` 기준이다.** 지도를 넓히면 노드·경로·편액이
  전부 따라와야 한다. 전수 확인하라.
- ★**카메라 클램프**를 다시 확인하라. 콘텐츠가 커지면 오프셋 범위가 바뀐다.

### 씰

- 지도 렌더 rect 가 새 계약과 일치하는지 단언하라.
- **선택 가능한 후보가 전부 화면 안에 있는지** 단언하라. r6 에서 줌 확대가
  이것 때문에 취소됐다. 같은 함정이다.
- 밴드가 가로로 늘어나지 않았는지 단언하라.
- 클램프 경계 부정 레그를 둬라.
