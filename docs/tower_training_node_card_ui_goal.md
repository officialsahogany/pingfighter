## 0. Fable이 확인한 현행 `[확인]`

- 6장 개념은 **이미 있다**. `tower_ascent_node_modal_state.gd:13`
  `SIX_CARD_NODE_KINDS := ["training", "fallen_monk"]`.
- 그런데 렌더가 **글자 행**이다. `tower_ascent_flow_renderer.gd:1625`
  `_draw_modal_action_row`가 채운 사각형 위에 텍스트만 그린다.
- 오퍼는 `tower_ascent_training_offer_builder.gd`가 만들고
  `stat_choices`(체질 수련)와 `mugong_choices`(무공 서가) 두 갈래다.
- 방문당 사용 상한은 `tower_ascent_tuning.gd:140`
  `TEMP_PHASE_C_TRAINING_USES_PER_VISIT := 2`다.

## 1. ★착수 전 확인할 결정 하나

사용자 문구 "중복 투자가 가능함"의 범위가 두 가지로 읽힌다.

- **해석 A**: 방문당 2회 예산 안에서 **같은 카드를 두 번** 살 수 있다.
  즉 서로 다른 카드 둘을 강제로 고르지 않아도 된다.
- **해석 B**: 상한 없이 계속 투자할 수 있다.

**Fable 권고는 A다.** 방문당 2회 상한은 사용자가 별도로 확정한 값이고
(`TEMP_PHASE_C_TRAINING_USES_PER_VISIT := 2`), 무혼 비용도 그 전제로 잡혀 있다.
상한을 없애면 경제가 통째로 흔들린다.

**현행이 이미 A인지 먼저 확인하라.** 같은 카드를 두 번 살 수 있는지 코드로
판정하고, 이미 되면 UI 문제만 남는다. 안 되면 그것이 4번의 실제 결함이다.

판정 결과를 보고서 맨 앞에 적어라. 해석이 갈리면 중단하고 물어라.

## 3. 계약

### S1. 현행 판정 ★먼저

- 수련장과 파계승이 각각 몇 장을 내는지, `stat_choices`와 `mugong_choices`가
  어떻게 6장으로 합쳐지는지 확인하라.
- **같은 카드를 두 번 살 수 있는지** 코드 경로로 판정하라. §1의 A/B 판정이다.
- 파계승도 `SIX_CARD_NODE_KINDS`에 있다. **이번 작업이 파계승에도 적용되는지**
  확인하고, 다르면 왜 다른지 적어라.

### S2. 3x2 카드 그리드

- 글자 행 대신 **카드 형태**로 그린다. 기준은 **보상 픽 카드**다.
  `runtime_perk_overlay_renderer.gd`의 카드 드로어를 재사용할 수 있는지 먼저
  검토하라. **새 카드 드로어를 만들기 전에 재사용 가능성을 판정**하고 근거를
  보고서에 적어라. 두 벌이 되면 다음 개정에서 갈린다.
- 아이콘·이름·성급·설명이 카드에 들어간다. 보상 픽 카드와 같은 문법이다.
- ★**GRT-021**: 설명이 길면 드로어가 조용히 행을 버린다. 최장 설명에서
  **실제 append된 행 수**를 단언하라.
- ★**GRT-022**: 글자 행에서 카드 그리드로 바꾸면 히트박스가 통째로 달라진다.
  `action_rects` 소비자를 전수 확인하고 **반증은 카드 상단 모서리**로 재라.
  중심점으로 재면 밀림이 통과한다.
- 모달 크기(`MODAL_RECT := Rect2(78.0, 112.0, 604.0, 548.0)`)에 3x2가 들어가는지
  확인하라. 넘치면 모달을 키우거나 카드를 줄이되 **플레이필드를 침범하지 마라.**

### S3. 중복 투자 표시

- **남은 사용 횟수**를 화면에 보여라. 지금 몇 번 남았는지 모르면 중복 투자를
  계획할 수 없다.
- 이미 투자한 카드는 **투자 횟수나 결과 레벨**이 카드에 보여야 한다.
  두 번 눌렀는데 티가 안 나면 눌린 건지 모른다.
- 예산이 소진되면 카드가 비활성으로 바뀌고 그 이유가 읽혀야 한다.

### S4. 씰

- 수련장·파계승 모달이 **6장을 3x2로 배치**하는지 단언하라. 행/열 수와 rect
  좌표로 본다.
- **같은 카드 두 번 구매**가 가능한지(§1 판정 결과대로) 단언하라.
- **방문당 상한 2회**가 지켜지는지, 초과 시 거부되는지 부정 레그를 둬라.
- 카드 rect와 히트테스트 rect가 **같은 값**인지 단언하라(GRT-022).

## 4. 규율

- 슬라이스마다 헝크 분리 커밋 1개. 각 슬라이스는 **단독으로 씰 GREEN**이어야 한다.
- 신규·개정 씰은 두 리터럴 목록에 동시 등재. **실패하는 씰을 넣지 마라.**
- ⚠ `tower_ascent_flow_renderer.gd`는 지도·모달·경로 서브가 공유한다.
  최근 여러 작업이 착지했으니 **최신 HEAD 기준으로 시작**하라.
- 한국어 카피에 엠대시(—) 금지. 신규 문구는 다국어 카탈로그 전 로케일 등재.
- 내부 식별자와 저장 키는 호환 식별자다. 바꾸지 마라.
- 통과 판정은 배치 종단선 `All Godot smoke tests passed.` + `SCRIPT ERROR` 0건.
- 로그 백업 선행. 표준 래퍼 `-AllowDuringPlay`. 푸시 금지.
