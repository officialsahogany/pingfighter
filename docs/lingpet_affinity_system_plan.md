# 링펫 친밀도(교감) 시스템 기획서

상태: 기획 v4.1 (2026-06-11) — v1(§1~§11) 구현·봉인 완료. **v2 확장
설계(§12) 결정 4건 전부 확정**: 15레벨 밴드 셔플 덱 + 승리 커밋 bond
(펫별 원장·50% 출전 게이트) + 런 만렙 "하트 공명" + 영구 호칭 순수
명예. 슬라이스 분해 = §12-7, 구현 착수 가능. 이하 v1 확정 사항:
(1) 영속성 = A-1 + A-3 동시 출시 (잔향 저장값은 펫별 최고 친밀도 레벨만,
헤드스타트 `floor(최고/3)` 최대 +4 고정), (2) §5 압축 트랙 + 50/75/100
프론트로드 승인 — 단 §3-1 수치는 밸런스 최종이 아니라 **GAIN_TABLE 기반
첫 플레이테스트 기본값**이며, 디버그 수입 로그가 §3-2 앵커(0/2/4/7/9/11)
이탈을 보이면 즉시 조정, (3) 플레이어 표기는 전면 "교감", "친밀도"는
A-3 도감/영구 잔향 표기 전용, (4) 만렙(12) 연출은 v1에서 비일시정지
연출 + 칭호 + 하트 틴트로 확정 — 라운드 경계 컷인은 A-2 영구 컬렉션/
도감 시점의 "친밀도 만렙 기념"으로 이연. **오픈 질문 0건, 구현 착수
가능.** 구현 순서는 §11 슬라이스 분해 참조. 표기 운영 주의: 문서 내부
설계 용어로는 "친밀도 Lv"를 계속 쓰지만, 구현 시 HUD/연출/툴팁의
플레이어 노출 문자열만 "교감"으로 고정하면 된다.
구현 분담: 본 문서 = 디자인 노트(시그널 계약 + 슬라이스 + 함정 브리프).
GDScript 배선은 사용자 주도, Claude는 슬라이스 리뷰 담당 (기존 분담 관례).

## 1. 한 줄 정의

링펫과 함께 싸우고(직접 타격) 아껴줄수록(교감 클릭) **교감수치**가 쌓이고,
요구치를 채울 때마다 **친밀도 레벨**이 올라 링펫의 액티브·패시브
**스킬 레벨과 스탯이 성장**하는 펫별 진행 시스템.

핵심 가치: 현재 실 게임 흐름에서 링펫 스킬 레벨은 **1 고정**이다
(임의 레벨을 쓰는 유일한 경로 = F7 디버그 피커 →
`lingpet_loadout_state.set_pet_loadout`, 호출처 검증 완료). 친밀도는
카탈로그의 `*_by_level` 5단계 테이블(`ring_dash_chance_pct_by_level`,
`stun_duration_seconds_by_level` [0.8..1.6], `beam_homing_chance_pct_by_level`
[35..95] 등)을 **처음으로 라이브에서 소비하게 만드는 성장 축**이다.

## 2. 데이터 모델

펫별(per pet_id) 데이터:

| 필드 | 타입 | 범위 | 의미 |
|---|---|---|---|
| `affinity_points` | float | 0 ~ (현재 레벨 요구치-1) | 현재 레벨 내 교감수치 |
| `affinity_level` | int | 0 ~ 12 | 친밀도 레벨 (0 = 갓 부화) |
| `hatch_bonus_granted` | bool | - | 런 내 부화 계약 보너스 1회 게이트 |

- 레벨업 요구치 (첫 체감 프론트로드): **Lv1 = 50, Lv2 = 75, Lv3+ = 100**
  (만렙 12까지 총 1,125). §4-A 영구화(A-2) 전환 시 `100 + 20×레벨` 점증안.
- 보유 주체: 새 모듈 `lingpet_affinity_state.gd` (RefCounted,
  `{pet_id: {...}}` + dirty 플래그 + 보상 트랙 계산, 순수 로직).
- **전투 캡 카운터(클릭 라운드/전투 캡 등)는 펫별이 아니라 전투 전역**
  (§3-3 #5). affinity_state의 펫별 dict와 분리해서 보관.
- **기존 `lingpet_companion_body_hit_state`의 `contact_count` /
  `gauge_trigger_count` 재활용 금지** — 둘 다 부화/펫 교체/입양 시
  `reset_all()`로 0이 되는 전투 스코프 카운터다
  (`lingpet_egg_runtime.gd:715-727` 경유 다수 호출처). 또한
  `gauge_trigger_count`는 게이지 만충 시 증가를 건너뛰어 타구 수를
  과소집계한다.

## 3. 교감수치 획득 규칙

### 3-1. 획득원과 기본 수치

| # | 이벤트 | 수치 | 캡 / 게이트 |
|---|---|---|---|
| 1 | **플레이어 득점** 라운드 커밋 (활성 펫) | +5 | 스타일 무관 기본 수입 — 비행 펫 수입 격차 보정. **2026-06-12 개정: 실점 커밋은 미지급** (+N 팝업 도입으로 "실점에 +5"가 가시화되자 어색하다는 사용자 결정; 승리 시 플레이어 점수는 고정이므로 "빨리 이기면 손해" 방지 명분도 유지됨) |
| 2 | 링펫 직접 타구 (몸으로 공 반격) | +8 | **라운드당 처음 4회 풀값, 이후 +2** (스톨 파밍 차단). 0.42s 히트 쿨다운·edge-trigger는 보조 게이트일 뿐 리미터로 신뢰 금지 |
| 3 | 수비 성공 보너스 (#2가 방어 인터셉트 중이거나 링크포트 블록일 때 추가) | +5 | 라운드당 2회. #2에 태그로 가산(별도 이벤트 아님 — 이중 지급 금지) |
| 4 | 교감 클릭 (SD 링펫 좌클릭 → 교감 라투디 시작) | +5 | **라운드당 2회, 전투당 5회 (전역 카운터)**. 라투디 시작 엣지 + 가시 상태에서만 |
| 5 | 알 부화 계약 | +25 | **런 내 pet_id당 1회** (affinity_state 보관 — reset_all 스코프 금지). 첫 레벨업(50)을 부화 직후 1~2라운드 안에 체감시키는 훅 |
| 6 | 전투 승리 | +20 | 활성 슬롯 펫. 단 **해당 전투 라운드의 50% 이상 출전한 펫만** (막판 펫 교체 몰아주기 차단) |

대략 수입: 순찰 펫 ≈ 25~40/라운드, 비행 펫 ≈ 15~25/라운드 →
전투(5~7라운드)당 ≈ 150~250 / 100~175. 6스테이지 런 기준 순찰 ≈ 트랙
완주~13레벨, 비행 ≈ 9~11레벨(액티브 만렙은 affinity 8 = 약 825라 도달
가능). 스타일 간 수입 격차 목표: **±25% 이내** (§8 패리티 스모크로 봉인).

### 3-2. 보스 밸런스 앵커 (튜닝 계약)

스테이지 진입 시 기대 친밀도 레벨: **스테이지 1/2/3/4/5/6 = 0/2/4/7/9/11.**
스테이지 5~6 보스(홍련, 테트리서) 난이도는 액티브 Lv4~5를 가정하고 점검.
이 곡선에서 ±2레벨을 벗어나는 수입이 관측되면 §3-1 수치를 조정한다
(트랙이 주입하는 전투력: 스턴 0.8→1.6s, 유도 35→95%, 쿨 -12% 등 — 런 종반
스킬 처리량 약 2.2배. 무앵커 튜닝 금지).

튜닝 운영 전제: §3-1 수치는 전부 `lingpet_affinity_state`의 단일 상수
테이블(예: `GAIN_TABLE`)에 모아 한 곳에서 교체 가능하게 하고, §3-2
앵커는 첫 플레이테스트 전까지 가설로 취급한다. 디버그 빌드에서
전투당 친밀도 수입 합계를 로그(BattlePerf 라벨류)로 남겨 곡선-실측
비교가 가능해야 "순찰 펫 트랙 초과 완주" 같은 과성장도 수치 근거로
조인다.

### 3-3. 게이트 / 어뷰즈 방지 (전부 필수)

1. **클릭 스팸**: `try_begin_companion_click_reaction`의 "이미 재생 중" 분기
   (`lingpet_egg_runtime.gd:1521-1523`)는 클릭을 소비하고 보이스만 재생한다.
   교감수치는 **inactive→active `start()` 엣지에서만** 지급 (1524 분기).
   재생 종료 후 즉시 재클릭 루프(~4초당 1회 AFK 파밍)는 라운드/전투 캡으로
   차단. (CLAUDE.md per-opportunity 잠금 패턴의 클릭판)
2. **비가시 클릭**: 클릭 판정(±70×±60px 존)은 가시성 검사를 안 하므로
   링크포트 은신/출격 은신 중에도 라투디가 시작될 수 있다. 교감 지급은
   `motion_visible`(+ 링대시 visual hidden 아님)일 때만.
3. **이중 지급 금지**: 방어 인터셉트와 링크포트 블록은 별도 이벤트가
   아니라 같은 `resolve_ball_hit`로 들어온다. 지급은 resolve 시 1회,
   보너스는 resolve 시점에 `defense_intercept_active` / 포지션 오버라이드
   플래그를 읽어 태그로만 가산. `ring_dash _trigger_count`는 대시 **시작**
   카운트(성공 블록 보장 아님)이므로 지급 근거로 쓰지 않는다.
4. **스톨 파밍**: 타구 보상은 라운드당 4회 풀값 후 +2 감쇠 (#2). 일부러
   공을 안 받고 펫에게 흘리는 플레이가 정직한 플레이 대비 이득이 되지
   않게. 전투당 소프트캡(풀값 ~250, 초과분 50%)은 듀스 장기전 더블 수입
   방지용 옵션.
5. **펫 교체 캡 리셋**: 클릭 라운드/전투 캡 카운터는 **전투 전역 소유**
   (라운드/전투 라이프사이클이 소유, pet_id 무관, 펫 교체·재부화에도
   생존). affinity_state의 펫별 dict나 reset_all 스코프 상태에 두면 펫
   교체마다 +25씩 재장전되는 구멍이 생긴다. 부화 보너스(#5)도 런 내
   pet_id당 1회 게이트 필수(교체-재부화 루프 차단).
6. **스킬 소유 공 접촉은 제외**: 소울클론(자체 hit_state 인스턴스, gain
   0), 드래곤윙 섀도 디플렉트, 드래곤 브레스, 유령소환, 인형의 저주의
   직접 `ball_vel` 기록은 초크포인트를 우회한다 — 친밀도 대상 아님(의도).
   획득 컷인 해제 클릭의 보이스 재생(`begin_acquire_cutin_dismiss`)도
   교감 아님. bomb_surprise/개틀링 전개 중엔 바디히트 자체가 억제됨.
7. **"진짜 라운드 종료" 기준 = 점수 커밋 지점**: 라운드 완료 +5와 승리
   +20은 `match_score_event_controller.handle_score_event`에서
   `score_state.score_for(scoring_side)`가 **실행된 이후**(커밋, 38행
   구간)에만 지급한다. 오딘 데스 시퀀스 / 파울휘슬 점수 무효화 / 부활 /
   오딘 부활은 전부 커밋 **이전에 early-return**하므로(13-31행) 이 기준
   하나로 "취소된 실점에 교감 지급" 구멍이 구조적으로 막힌다. 승리
   판정은 같은 지점의 `score_result.match_finished == true and
   scoring_side == "player"` (윤회 스테이지 홀드처럼 커밋에 못 간 매치
   포인트는 자동 제외). 커밋이 1점당 1회뿐이므로 승리 중복 지급도 없음.
   **2026-06-12 개정**: 라운드 완료 +5는 `scoring_side == "player"`인
   커밋에만 지급한다(실점 커밋 미지급). 게이트는
   `lingpet_egg_runtime.handle_score_event` 안에 있고, 출전 50% 승리
   게이트의 원장도 같은 플레이어 득점 커밋 기준으로 함께 좁혀진다(분모·
   분자가 동일 기준이라 비율 의미는 보존). 봉인:
   `lingpet_egg_runtime_smoke._verify_affinity_score_event_and_battle_reset`
   의 실점 0pt / 득점 +5 케이스.

## 4. 핵심 설계 결정 (구현 전 확정 필요)

### A. 영속성: 런 스코프(A-1)로 시작, "유대의 잔향" 하이브리드(A-3)가 권장 로드맵

조사로 확정된 사실: **링펫 세이브 전체가 의도된 휘발성 런 상태다.**
`lingpet_save_store.save_snapshot`은 의미 있는 진행이 있으면 파일을
삭제하고(`_is_volatile_run_snapshot`, save_store.gd:39-41/136-146),
`restore_runtime`은 전투 진입 시 새 알로 리셋한다(75-89). 스모크 봉인
(lingpet_egg_runtime_smoke.gd:2394/2406/2424). 즉 현재는 링펫 **소유
자체가 영구가 아니므로**, 소유보다 먼저 친밀도만 영구화하는 것은 모순.

- **A-1 (확정, v1 동시 출시): 런 스코프.** 교감은 런 안에서 성장·소멸.
  affinity_state는 런타임 인스턴스에 살고, 스냅샷 동승은 §6의 저장 행
  참조(주의사항 있음). 휘발성 정책·스모크 불변.
- **A-3 (확정, v1 동시 출시): 유대의 잔향 하이브리드.** 라이브 시스템은
  A-1 그대로 두고, **펫별 "역대 최고 친밀도 레벨"만** 별도 영구 저장소
  (`user://lingpet_affinity.cfg` + 신규 `lingpet_affinity_store.gd`)에
  기록. 다음 런에서 그 펫 부화 시 시작 친밀도 = `floor(최고기록/3)`
  (**최대 +4 고정**). 저장값은 최고 레벨 int 하나뿐 — points/캡 카운터
  등 런 상태는 절대 영구화하지 않는다. 매 런 같은 12계단을 처음부터
  다시 미는 단조로움(고정 트랙 + 런 스코프의 약점)을 로그라이트식 메타
  진행으로 완화하고, 가챠/영구 컬렉션 전환 시 풀 영구화(A-2)로 자연
  승격된다. (구현 부담 대비 플레이어 신뢰 이득 — 코덱스 리뷰 권고로
  동시 출시 확정)
- **A-2 (최종형): 영구 친밀도.** 컬렉션 영구화와 동시 결정. **반드시
  별도 파일** — `clear_snapshot`이 `lingpet_save.cfg` **파일 전체를
  삭제**하므로(DirAccess.remove_absolute, save_store.gd:53-59) 같은
  파일에 영구 섹션 공존 불가. 점증 요구치로 전환.

`lingpet_affinity_state`를 저장 인터페이스 뒤에 두면 A-1 → A-3 → A-2가
스토어 스위치 수준으로 전환된다.

**플레이어 명칭 정책 (필수)**: "친밀도"라는 단어는 영구 성장 기대를
만들므로, A-1 단독 출시 시 런 소멸이 배신감으로 읽힌다. 명칭을 2층으로
분리한다 — **런 내 수치 = "교감"** (UI 라벨 "교감 Lv.N", 게이지 명
"이번 출전 교감"), **영구 잔향(A-3) = "친밀도"** (펫 도감/패널의 영구
표기). A-1 단독으로 나가는 동안 UI에는 "교감"만 노출하고 "친밀도"
브랜딩은 잔향 스토어가 생길 때 함께 공개한다. A-3를 v1에 동시 출시하면
이 긴장 자체가 사라지므로 그쪽이 더 안전한 선택 (§9-1).

### B. 스탯 보상은 모션 스타일로 라우팅 (F7 슬라이더와 동일 규칙)

방어율은 순찰 전용, 출현율은 비행 전용이며 게이트가 보너스보다 위에서
실행되어야 한다(`_get_current_defense_rate` / `_get_current_appearance_rate`,
lingpet_egg_runtime.gd:985-1005). 비행 펫의 카탈로그 속도는 거의 사용되지
않는다(출격은 SORTIE_* 하드코딩 상수, 자유비행은 카탈로그 속도 명시적
미사용 + 드리프트 상수 64). 보상 2종 라우팅:

| 보상 종류 | 순찰 펫 | 비행 펫 (sortie/free) |
|---|---|---|
| 기동 강화 | 순찰 속도 +5% (min·max·default 균일 — `patrol_speed_bonus_pct` 패시브 선례) | 출현율 +5%p (은신 대기 단축) |
| 수비/지원 강화 | 방어율 +4%p (0..1 클램프 주의) | 게이지 획득량 +4 (additive, 프로파일 선례 있음) |

- 순찰 속도에서 default만 올리면 HUD 숫자만 바뀐다 — 실제 이동은 매
  방향전환마다 [min, max] 균일 샘플(`_next_speed`,
  lingpet_companion_motion_state.gd:970-976). min·max 동반 필수.
- 속도 보상은 방어 인터셉트(상수 180 캡)에 영향 없음 — 툴팁 문구를
  "순찰 이동 속도"로 스코프(표기-체감 일치 규칙).
- 잘못된 스탯(비행 펫에 방어율)은 UI만 오도하는 죽은 데이터 — 금지.
- 비행 게이지 보상은 기존 special_gauge 지급(+40) + 공명 증폭 패시브
  pct(레벨도 친밀도로 오름)와 **3중 스택**이다 — 패시브 Lv5 시점 수치
  1회 점검 필수 (§7-11).

### C. 스킬 레벨 보상 = "기본 레벨 + 친밀도 증가분" 합성, 캐시 무효화는 의무

유효 레벨 = `clamp(저장된 기본 레벨 + 친밀도 증가분, 1, 5)`.
합성 지점은 `_apply_current_loadout`(lingpet_egg_runtime.gd:1020-1053)에서
`_current_profile.set_loadout`으로 레벨을 넘기기 직전.

- 평탄화 패시브 dict(`ring_dash_chance_pct` 등 base 키 소비)와
  launch_context의 `active_skill_level` int **양쪽 소비 형태가 자동으로
  같이 오른다** (launch_context만 패치하면 패시브가 디싱크).
- 부화는 저장된 로드아웃이 없을 때만 `pick_skill_loadout`으로 새로
  만들고(레벨 1 하드코딩), 있으면 보존한다(`ensure_pet_loadout`
  randomize_missing) — 어느 쪽이든 증가분은 그 위에 합성되므로 안전.
- **레벨업 시 `_invalidate_current_loadout_cache()` 호출 + 프로파일
  내부 캐시 키(`_build_active/passive_skill_cache_key`)에 친밀도 합류는
  둘 다 의무다.** ⚠ v1의 "`_build_loadout_key`에 친밀도를 포함시키는
  것으로 갈음" 대안은 **동작하지 않는다**: `_apply_current_loadout`은
  `_applied_loadout_key != ""`이면 키를 **재계산하기 전에**(1026-1027
  early-return이 1029 키 빌드보다 먼저) 반환하므로, 키 내용만 바뀐
  변경은 영원히 관측되지 않는다. 무효화가 유일한 작동 레버.
- SKILL_LEVEL_MAX=5 클램프는 카탈로그/로드아웃/프로파일/스킬 모듈 로컬
  (doll_curse·ghost_summon `clampi(...,1,5)`) 다층 존재 — 5 초과 설계
  금지(트랙이 정확히 5에서 끝나도록 §5에서 보장).
- **F7 피커와의 표시 정책**: F7은 기본 레벨을 쓰고 표시하는 별도
  서피스다. 기본 3 + 친밀도 +2 = 5 클램프 같은 합성 상황에서 "피커는
  기본 레벨, 패널·툴팁은 합성 레벨" 원칙을 명시하고 §6 레벨 표시
  서피스 목록으로 일괄 감사.

  말고 다음 보상 1개만 보여준다.

## 7. 함정 브리프 (배선 시 체크리스트)

1. **오너 스키마**: 새 owner 키는 `DEFAULT_VALUES` 선언 없이는 침묵
   no-op → 패널이 폴백 값으로 "맞아 보이는" 채 동결. 스모크는 반드시
   스키마 게이트 오너(실제 BattleSceneState 위임)로
   (`character_info_live_stats_smoke._verify_defense_override_reaches_panel_through_schema_gated_owner` 클론).
2. **클릭 스팸 3종**: 재생 중 재클릭(엣지에서만 지급) / 종료 후 즉시
   재클릭 AFK 루프(라운드·전투 캡) / 은신 중 클릭(가시성 게이트).
3. **캐시 2층 + early-return**: 친밀도 레벨업 시
   `_invalidate_current_loadout_cache()` 의무(§4-C — 키 변경만으론
   1026 early-return에 막힘) + 프로파일 내부 스킬 dict 캐시 키 합류.
4. **클램프 다층**: 스킬 Lv 1..5 (4층), 방어율·출현율 0..1. 트랙 설계로
   캡 초과 자체가 없게.
5. **휘발성 세이브**: 영구 데이터를 기존 스냅샷에 싣지 말 것.
   `clear_snapshot`은 파일 전체 삭제. 휘발성 정책 스모크 3건은 의식적
   결정 없이 우회 금지. A-1 스냅샷 동승의 실효는 소비자 확인 후(§6).
6. **`_normalize_loadout` 화이트리스트**: 로드아웃 dict에 필드를 넣는
   선택을 하면 화이트리스트(loadout_state.gd:226-234) 추가 필수 —
   아니면 라운드트립마다 침묵 소실. (권장: 로드아웃이 아닌 별도
   affinity dict 보관)
7. **라운드 클린업 owner == null**: 라운드 종료 경로의 친밀도 처리(라운드
   완료 +5, 캡 리셋)는 owner 없이 동작하는 형태로 (Boss-Paddle trap #4).
8. **핫패스**: 친밀도 게터가 프레임 경로(`_update_companion_motion` /
   `sync_owner`)에 들어가면 공유 참조/캐시만. PETS 딥카피 금지. 신규
   연출 텍스처는 프리웜 등록(§6 연출 행).
9. **속도 보상 스코프**: default만 올리면 HUD만 변함. 인터셉트 180 캡
   불변. 비행 펫 카탈로그 속도 미사용. 툴팁 문구로 스코프 명시.
10. **수치 표기-체감 일치 + 결과 단언**: 친밀도로 오른 방어율/출현율/
    스킬 레벨은 **게임플레이 결과**(실제 블록, 은신 대기 단축, 스킬 거동
    변화)로 스모크에서 단언. arming 플래그·표시 숫자만 단언 금지.
11. **게이지 3중 스택**: 비행 수비/지원 보상(+4/+8 additive) × 공명 증폭
    패시브 pct(친밀도로 레벨업) × 기존 +40 — 패시브 Lv5 시점 합산 수치
    1회 점검.
12. **Maribo 윈드업 모션 프리즈**: 멀티프레임 컴패니언 스모크는 오토캐스트
    윈드업이 `freeze_motion`으로 순찰/인터셉트를 얼리므로, 먼저 액티브가
    실제 발사되게(레인 밖에 활성 공 주차) 만들어 40s 쿨다운을 채운 뒤
    측정 (lingpet_egg_runtime_smoke.gd:2589-2614 셋업 미러).
13. **공 수동 전진 스케일**: 공을 손으로 전진시키는 스모크는
    `ball_vel * delta * 60` (fps_scale 미러, 스모크 2610-2614 `step_drop`
    패턴). 생짜 `ball_vel`/스텝은 3배 느린 하강으로 위양성.

## 8. 스모크 계획

신규 `lingpet_affinity_smoke.gd` + 기존 스모크 확장:

1. **상태 단위**: 지급/레벨업(50/75/100 요구치)/트랙 보상 산출/12 만렙
   정지/클램프.
2. **클릭 스팸 회귀**: 라투디 재생 중 연속 클릭 N회 → 지급 1회. 종료 후
   재클릭 → 캡 내에서만. 은신 중 클릭 → 0.
3. **경제 익스플로잇 회귀**: (a) 한 라운드 10회 타구 → 정확히 4×8+6×2
   지급(스톨 캡), (b) 전투 중 펫 교체 → 클릭/전투 캡 카운터 불변 + 부화
   보너스 재지급 없음, (c) 막판 교체 펫 → 승리 보너스 0 (출전 50% 게이트),
   (d) 순찰 vs 비행 스크립트 전투 수입 ±25% 패리티 밴드.
4. **이중 지급 회귀**: 인터셉트 활성 블록 1회 → 기본+태그 정확히 1세트
   (태그는 resolve 직전 캡처 — resolve가 하강을 끝낸 뒤 상태를 읽으면
   태그가 유실되는 회귀를 고정).
4b. **점수 커밋 게이트 회귀**: 파울휘슬 무효화 / 부활 / 오딘 데스·부활
   경로(커밋 전 early-return)에서는 라운드 완료 +5가 지급되지 않고,
   정상 커밋에서 1회 지급. `match_finished` 커밋 1회에 승리 +20도
   정확히 1회 (윤회 스테이지 홀드는 0회).
5. **스킬 레벨 합성**: 친밀도 Lv1 부여 → launch_context
   `active_skill_level` == 2 **그리고** 평탄화 패시브 dict의 by_level
   값 갱신(양쪽 소비 형태 단언). **스테일 캐시 회귀는 실제
   `_apply_current_loadout` 경로로**: 무효화 없이 레벨업 → 구레벨 유지
   (실패 재현) → 무효화 호출 → 신레벨 반영.
6. **스탯 라우팅 + 결과 단언**: 순찰 펫 → min/max 동반 상승 + **친밀도
   부스트 방어율이 가까운 unblockable 하강 공을 실제로 튕김**
   (`_verify_maribo_defense_actually_blocks_reachable_ball` 하니스 클론,
   far 카운터케이스 포함, §7-12 윈드업 셋업 + §7-13 fps_scale 준수).
   비행 펫 → **은신 대기 실측 단축** + 게이지 상승, 방어율 0 유지.
7. **패널 도달**: 스키마 게이트 오너로 "교감" 행·게이지가 라이브 값과
   일치(전투 중 상승 후 다이버전트 케이스), 캐시 해시 갱신, 스킬 아이콘
   부제 "Lv.%d"가 합성 레벨과 일치, **세로 스택 레이아웃에서 6행 전부
   가시** (침묵 드랍 회귀).
8. **영속성**: (A-1) 스냅샷 라운드트립 보존. (A-3/A-2) 휘발성
   `clear_snapshot`이 affinity 파일을 건드리지 않음 + 잔향 헤드스타트
   계산.

## 12. v2 확장 설계 — 밴드 셔플 보상 덱 + 영구 유대 호칭 (2026-06-11 합의)

v1 봉인 이후 확장. 합의 경로: 사용자 제안 → Claude 1차 설계 → 코덱스
리뷰 must-fix 반영. 구현 전 §12-6 잔여 결정 4건 확정 필요.

### 12-1. 보상 트랙 → 밴드 셔플 덱

완전 랜덤 금지(첫 체감·스킬 만렙 도달·보스 앵커 3중 보장 파괴),
단순 전체 셔플도 기각(앵커 분산 과대). 채택안 = **밴드 셔플**:

- **Lv.1 고정**: 항상 액티브 스킬 +1 (첫 체감 보장).
- **밴드 내 셔플**: Lv.2~5 초반 덱 / Lv.6~10 중반 덱 / Lv.11+ 후반 덱.
  밴드별 카드 구성은 고정, 순서만 런·펫 단위 셔플 → 보스 앵커 분산이
  밴드 폭 이내로 제한되고 "다음 보상" UI(덱 top 공개)는 그대로 동작.
- **덱 생성은 모션 스타일 인지**: 비행 펫 덱에는 방어 카드를 아예 넣지
  않는다(죽은 스탯 금지) — 그 슬롯은 게이지/기동 카드로 구성.
- **Dead-draw 규칙 (필수)**: 덱 생성 시 유효 증가가 가능한 스킬 카드만
  포함하고, 지급 시점에 클램프(스킬 Lv.5 등)에 막히는 카드는 스탯
  카드로 즉시 대체. 조용한 증발 금지.
- **결정성**: 셔플 시드는 런 상태에 저장(스냅샷 동승), 테스트 시드
  주입 API 필수. 비결정 소스 금지.
- **구현 영향(핵심)**: 현 `REWARD_TRACK` / `get_cumulative_rewards_for_level`
  은 정적이라 덱화 시 펫·런 컨텍스트가 필요하다. 권장 전환: 카드 지급
  즉시 펫 데이터에 누적 카운트(active/passive/mobility/support/gauge
  stacks)를 기록하고, cumulative rewards는 레벨 계산이 아니라 **지급
  이력 읽기**로 전환. 프로파일 캐시 키도 affinity_level 단일 int에서
  지급 카운트 시그니처로 교체.

### 12-2. 카드 종류·스택 캡 (플레이테스트 기본값)

| 카드 | 효과 | 덱 매수 (순찰 / 비행) | 캡 |
|---|---|---|---|
| 액티브 +1 | 스킬 Lv (쿨감·시전단축 동반) | 4 / 4 (Lv.10 내 전부 등장 보장) | Lv.5 |
| 패시브 +1 | 패시브 Lv | 4 / 4 | Lv.5 |
| 기동 | 순찰 속도 +5% / 출현율 +5%p | 3 / 3 | 속도 **+30% 시작 캡**(상향은 플레이테스트 후) / 출현율 1.0 |
| 방어 | 방어율 +4%p | 2 / **0** | **0.80 클램프** (1.0 금지 — 로컬 가드 스코프상 "100%" 표기는 배신감 유발. 표기명 "방어 예측 성공률" 검토) |
| 게이지 | 링펫 **직접 타구** 게이지 +5 (`hit_gauge_gain` 직접 가산 — 플레이어 타구 보너스와 별개) | 2 / 4 | **최대 4장(+20)**. 3중 스택(기본40+공명증폭%+카드) 합산 점검 의무 |

트랙 길이 = 덱 총 매수 = **15레벨 권장**(요구치 합 ~1,425 — 상위권
런 완주 가능선). 출현율 툴팁 문구 의무: "항상 출현"이 아니라 "은신
대기가 최소치에 가까워집니다"(FAST floor 의미).

### 12-3. 영구 유대 호칭 — 별도 bond 축 (레벨 누적 금지)

⚠ **"런에서 올린 레벨을 영구 누적" 방식은 기각** — 짧은 런을 반복해
Lv.1~2만 뽑는 쇼트런 파밍 루프가 열려 v1 anti-inflation 철학과 충돌.

- 스토어 스키마 v2: `[meta] schema_version=2` / `[best_levels]`
  (기존 그대로, **헤드스타트 전용 유지**) / `[bond_points]` 신규 분리.
  v1 파일 마이그레이션: best_levels 보존, bond 0 초기화, 버전 스탬프
  (battle_view_layout 마이그레이션 패턴).
- **적립 규칙 (확정, 2026-06-11)**: 전투 중 레벨업을 **펫별 pending
  원장**(battle-cap 스코프 `battle_level_ups_by_pet`)에 적립해 두고,
  **플레이어 승리 커밋 시점에만** 정산한다 — 정산 대상은 그 전투
  라운드의 **50% 이상 출전한 펫만**(v1 승리 +20과 동일한 출전 원장
  재사용, active-only 아님: 교체 운용한 보조 펫도 게이트만 통과하면
  자기 레벨업분을 적립). pending 폐기 시점: (i) 보스 측
  `match_finished` 커밋(패배), (ii) 스테이지 전환 리셋(정산 **후**에
  실행되도록 순서 고정), (iii) 런 종료(인스턴스 소멸). 패배/런 포기/
  쇼트런은 pending이 저장소에 닿지 못하고 버려진다 — 쇼트런 파밍
  구조적 차단.
- 호칭 (bond 누적 레벨, 비중첩 구간, 캡 25): **1~5 어색함 / 6~10
  가까워짐 / 11~15 친함 / 16~20 단짝 / 21~25 영혼의 단짝.**
- 호칭은 영구 축이므로 표기는 **"친밀도"** (명칭 2층 정책 그대로).
  도감·획득 컷인·패널 영구 표기에 사용.
- **명칭 충돌 해소**: 런 만렙 보상 칭호 "영혼의 단짝"은 영구 호칭
  최상위로 이관하고, 런 만렙 보상명은 런 전용 명칭으로 교체
  (후보: 하트 공명 / 완전 교감 / 최고 교감).
- 호칭 구간별 영구 보너스(헤드스타트 상한 +1 등)는 영구 전투력
  크리프 = 보스 앵커 영향이므로 **별도 결정 항목**(§12-6).

### 12-4. 스모크 계획 v2 (추가분)

1. 밴드 셔플 결정성: 같은 시드 → 같은 덱, Lv.1 = 액티브, 액티브 4장
   Lv.10 내 전부, 밴드 경계 위반 0.
2. Dead-draw: 스킬 만렙 상태에서 스킬 카드 지급 시 스탯 카드 대체,
   비행 덱 방어 카드 0장.
3. 캡: 방어 0.80 클램프, 게이지 4장 초과 불가, 속도 +30% 경계.
4. bond 승리 게이트: 패배 전투 미적립, 쇼트런(부화만 하고 리셋) 적립
   0, 승리 전투만 그 전투분 적립, 호칭 경계값(5/6, 20/21).
5. 스토어 마이그레이션: v1 파일 로드 → best 보존 + bond 0 + v2 스탬프.
6. 지급 이력 기반 cumulative rewards가 프로파일 캐시 키와 함께 갱신
   (v1 스테일 캐시 회귀 형태 유지).

### 12-5. 트랙 길이 15 전제의 앵커 재계산

기대 친밀도 곡선(0/2/4/7/9/11)은 15레벨 기준 재산정 필요 — 디버그
수입 로그로 v1 실측을 먼저 받고 갱신한다(§3-2 운영 전제 유지).

### 12-6. 결정 기록 (2026-06-11 확정 — 재론 금지)

1. **트랙 길이 = 15 확정.** §12-2 덱 구성이 그대로 합계 15
   (순찰: 스킬8+기동3+방어2+게이지2 / 비행: 스킬8+기동3+게이지4).
   수입 실측 후 조정은 **카드 수가 아니라 요구치 곡선으로** 한다.
2. **bond 적립 = 승리 게이트 + 펫별 원장 + 펫별 50% 출전 게이트**
   (§12-3 확정 규칙). pending은 최종 승리 커밋에서만 저장소 반영.
3. **런 만렙(15) 보상명 = "하트 공명"** (하트 틴트 연출과 결속).
   "영혼의 단짝"은 영구 친밀도 최상위 호칭(21~25)으로 이관.
4. **호칭 영구 보너스 = v2에서는 없음.** 순수 명예/도감/패널 표기까지만.
   영구 전투력 보너스는 A-2 영구 컬렉션/가챠 영구화 때 재론.
