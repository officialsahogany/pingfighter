# 지시문 Y6 — 지도 줌인·이동 중 그림이 꿀렁거리는 현상

- **발행**: 관제탑 2026-08-27. 기준선 = 본 트리 **`97d7daafc`**.
  **격리 워크트리 + 격리 브랜치.** 본 트리 편집·통합·푸시 금지.

## 사용자 보고

> 노드 경로를 공 발사로 선택한 뒤 노드 지도 화면에서 **지도가 줌인되면서
> 플레이어 캐릭터가 이동할 때** 지도 주변이 **꿀렁거리거나 꿈틀거리는 등
> 그림이 튀거나 왜곡되는 현상**이 있다.

## ★이 지시문은 원인을 단정하지 않는다

관제탑이 코드에서 **후보 5개**를 좁혔다. **어느 것이 진범인지 먼저 증명하고
보고하라.** 증명 없이 여러 개를 한꺼번에 고치지 마라. 고치면 무엇이 효과가
있었는지 영원히 모른다.

---

## 후보 1 — 텍셀 스냅 없음 (관제탑 1순위)

`tower_ascent_flow_renderer.gd`

```gdscript
func _camera_world_to_screen(camera_model: Dictionary, point: Vector2) -> Vector2:
	return _screen_point(point, _camera_render_zoom(camera_model), offset)
```

`_screen_point` 은 `point * zoom + offset` **순수 실수**다. 스냅·반올림이
전혀 없다.

줌이 연속적으로 변하는 동안 지도 비트맵의 target/source rect 가 매 프레임
**다른 소수부**에 떨어진다. 선형 필터링이면 프레임마다 다른 서브텍셀 혼합이
나와 **그려진 그림이 물결치듯 보인다.** "줌인되면서"라는 조건과 정확히 맞다.

## 후보 2 — 드로우 프리미티브 조건부 전환 (관제탑 2순위)

`tower_ascent_map_cloud_layer.gd:701` `_draw_texture_rect_region_vertical_alpha`

```gdscript
if is_equal_approx(safe_top_alpha, safe_bottom_alpha):
	canvas.draw_texture_rect_region(...)      # ← 경로 A
	return
...
canvas.draw_polygon(points, colors, uvs, texture)   # ← 경로 B
```

**알파 값에 따라 서로 다른 렌더 프리미티브를 쓴다.** 리빌 페이드 중 상단·하단
알파가 수렴하는 순간 **경로 B → A 로 갈아탄다.** 두 경로는 래스터화가 동일
하지 않다(정점 색 보간 + 아핀 UV vs 엔진 rect 경로). 전환 프레임에 **눈에
띄는 팝**이 난다.

⚠이 함수 자체의 UV 는 `source_size` 로 정규화돼 있어 GRT-033 은 아니다.
문제는 **분기 자체**다.

## 후보 3 — `draw_polygon` 쿼드 삼각분할 (GRT-006)

경로 B 는 4점 쿼드를 `draw_polygon` 으로 그린다. 카메라 변형으로 쿼드가
축정렬을 벗어나거나 near-degenerate 가 되면 **삼각분할 대각선 선택이 프레임
마다 뒤집힐 수 있다.** 대각선을 경계로 이미지가 접히듯 꿈틀거린다.

`docs/godot_runtime_traps.md#grt-006` 참조.

## 후보 4 — 구름 시차 wrap 경계

`wrapped_cloud_center_x` (`:394`). 여의두문 구름 2겹 시차가 wrap 하는 지점
에서 튈 수 있다. **지도 본체가 아니라 구름만 떠는 것인지** 눈으로 갈라라.

## 후보 5 — 전역 물리 보간 (GRT-039)

지도 오버레이가 전역 물리 보간의 영향을 받으면 카메라/워커 위치가 스폰·이동
프레임에 글라이드한다. `docs/godot_runtime_traps.md#grt-039` 참조.

## ★증명 방법 — "좋아 보인다"는 증거가 아니다

정지 캡처 한 장으로는 꿀렁거림이 안 보인다. **수치 추적을 만들어라.**

1. **프레임별 수치 로그**: 줌인 구간(공 발사 직후 ~ 카메라 정착) 동안 매
   프레임의
   - `render_zoom_multiplier`
   - 카메라 `offset`
   - 지도 배경 draw 의 `target_rect` / `source_rect` **소수부**
   - `_draw_texture_rect_region_vertical_alpha` 가 **어느 경로(A/B)를 탔는지**
   를 찍어라. **경로가 프레임 중간에 바뀌면 후보 2 가 확정된다.**
2. **연속 프레임 캡처**: 같은 구간을 최소 **10프레임 연속** 캡처해 나란히
   비교하라. 정지 1장 금지.
3. **격리 반증**: 후보를 하나씩 **끄고** 증상이 사라지는지 보라.
   - 후보 1 → 스크린 좌표를 `round()` 로 스냅
   - 후보 2 → 알파가 같아도 강제로 경로 B 만 쓰게
   - 후보 4 → 구름 레이어를 잠시 꺼서
   **증상이 사라진 것만 진범이다.** 확정 후 임시 토글은 원상복구하라.

## 수리 시 지켜야 할 것

1. **리빌 페이드가 깨지면 안 된다.** 세로 알파 그라디언트(층 공개 연출)는
   기능이다. 스냅을 넣더라도 페이드가 계단으로 보이면 안 된다.
2. **드로우 콜 예산.** `estimate_draw_calls` / `estimate_visible_draw_calls`
   가 이미 있다. **경로를 하나로 통일하면서 드로우 콜이 늘면 보고하라.**
   GRT-043 (상시-가시성 승격 × 프리미엄 절차 드로우) 대상이다.
3. **스냅을 넣는다면 어디에 넣는지가 중요하다.** 월드→스크린 변환 전체를
   반올림하면 **노드 아이콘과 경로 점이 서로 어긋날 수 있다.** 배경 비트맵
   에만 적용할지, 카메라 오프셋 자체를 스냅할지 판정하고 근거를 보고하라.
4. **줌 배율이 비정수일 때** 텍셀 스냅은 완전 해결이 아니다. 한계가 있으면
   솔직히 보고하라.
5. `docs/plaza_2d_map_r0_r1_qa_contract.md` 등 기존 지도 QA 계약이 있으면
   따르라.
