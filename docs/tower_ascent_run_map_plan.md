# 탑 등정 런 지도 개편 기획서 (v1.1)

- Status: 방향 v1 확정 + 구현 계약 보강 v1.1 (2026-08-16, 코덱스 읽기 전용 리뷰
  P1×5 · P2×4 전건 반영) · 코드 미착수 · 구현 주체 = Codex
- 이 문서가 본 개편의 설계 정본이다. 런타임 계약(리셋·프리웜·오디오·GRT)은
  기존 오너 체크리스트가 계속 이긴다. 이 문서는 "무엇을 만들 것인가"를 소유한다.
- 레퍼런스 문법: Slay the Spire(전도 공개 분기 지도·엘리트 표시·경로 손익),
  Peglin(런 구조·크루시블 난이도 축), Hades(패배 결산의 영속 소득 명시).
- 차별화 핵심: 노드 선택을 메뉴 클릭이 아니라 **공 발사**로 수행한다.

## 1. 목적

기존 "스테이지 클리어 → 상자 → 결과화면 → 광장 → 다음 스테이지" 선형 루프를
런 기반 등정 지도 루프로 개편한다.

- 스테이지 사이 무결정 구간(결과화면, 광장 왕복)을 제거하고 결정 밀도를 올린다.
- 무작위성을 계획 재료로 바꾼다. 경로 선택 = 손익 계산.
- 반복 플레이 동기를 만든다. 해금, 기록(최고 도달 층), 리그(광폭화 스케일).

## 2. 핵심 루프

```
스토리 프롤로그 (아라울의 첫 승부)
→ 1밴드 풀 보스 1종과 전투 (7점제)
→ 승리: 상자 1개 드랍 (3종 중 1)
→ 지도: 다음 행 후보 2개에 공 발사 → 닿은 노드로 캐릭터 이동
→ 노드 수행 (전투 / 상점 / 수련장 / 파계승 / 휴식 …)
→ 반복하며 고도 상승 → 밴드 전환 ("~진입" 연출)
→ 최상층 보스 → 런 클리어 결산

패배: 기회의 보석 1개 소모 → 동일 노드 재도전
      잔량 0에서 패배 → 런 종료 결산 (전량 손실 + 영속 소득 병기)
```

## 3. 확정 설계

### 3.1 지도 구조

- 단일 탑, 1페이즈. 아래에서 위로 오르는 등정 구도.
- 데이터 구조는 처음부터 `phases: []` 배열로 잡고 1원소 특수 케이스로 시작한다.
  후속 페이즈 분할(로스터 확장 + 최상층 전용 보스 확보 시)의 마이그레이션 비용을 0으로.
- 전도 공개(StS식): 지도 전체와 노드 아이콘을 처음부터 보여준다.
  활성(공을 맞출 수 있는 대상)은 다음 행의 후보 2개뿐.
- 목업 이미지는 사용자 제공분을 레포로 반입해 이 문서 옆에 둔다 (반입 전).

### 3.2 공 발사 선택 계약

- 노드 종료 후 다음 행 후보 2개가 표적화된다.
- 발사 횟수 무제한. **노드에 닿은 경우에만 그 노드로 확정**된다. 빗나감 = 무효.
  물리 튕김이 원치 않는 선택을 만드는 것은 금지 (조준선 표시, 사실상 결정적 선택).
- 연출은 물리, 결정은 확정. 튕김의 재미는 선택이 아니라 보너스에 배치한다.
- (옵션) 지도 장식 오브젝트 타격 시 소량 재화. 선택 확정과는 완전 분리.
  **파밍 방지 계약 (필수)**: 장식별 지급은 **런 1회**. 지급된 장식 id는
  `claimed_decoration_ids`로 런 스냅샷에 저장한다. 지도 방문(노드 사이 발사
  세션)당 지급 총량 상한을 별도로 둔다. 발사 무제한 + 반복 지급 조합은 무한
  파밍이므로 금지.

### 3.3 밴드 = 보스 풀 묶음 (전투 배경은 보스를 따른다)

- 고도 구간(밴드)마다 보스 풀을 정의한다. 전투 배경은 밴드가 아니라 **그 보스의
  원 스테이지 배경**을 쓴다 (배경 아트 8종 전부 재사용).
- 밴드 전환: 지도 타일·공기 톤이 바뀌고 "~진입" 배너가 뜬다.
- **현행 로스터 제약 (코덱스 리뷰 확인)**: 스테이지당 3종 풀은 S1(달지·각시탈·
  포도대장)뿐이고, S2~S8은 스테이지당 1종이다 (도감 정본
  `docs/hwangyeokjeon_codex_design.md` §2.3 보스 키 표: 청린귀 / 환묘 연묘 /
  퐁크 / 홍련 / 테트리서 / 아카무 리고 / 미노타우로스). 두더지왕·아라크네 등은
  현 Godot 로스터에 없다.
- 따라서 **v1 밴드는 현행 로스터를 묶음으로 구성**한다 (제안 파티션, 확정 대기):

  | 밴드 | 풀 | 수문장(경계 확정 전투) |
  |---|---|---|
  | 1밴드 | S1 3종 (달지·각시탈·포도대장) | 풀 중 미조우 1종 |
  | 2밴드 | 청린귀 · 환묘 연묘 | 풀 중 1종 |
  | 3밴드 | 퐁크 · 홍련 | 풀 중 1종 |
  | 4밴드 | 테트리서 · 아카무 리고 | 풀 중 1종 |
  | 최상층 | 미노타우로스 | 최종 보스 |

- 스테이지당 3종 풀(예: S2에 두더지왕·아라크네 추가)은 **선행 의존성이 아니라
  병행 콘텐츠 트랙**이다. 신규 보스가 포팅되면 해당 밴드 풀에 추가만 한다.
- **밴드 경계 = 수문장 보스 행 (회피 불가 확정 전투).** 밴드당 최소 전투를 보장하고
  중간 절정 리듬을 만든다.
- **회피 규칙: 선택지에서 지나친 보스는 그 런에서 재등장하지 않는다.**
  회피 = 그 보스의 상자를 영구 포기. 라우팅을 손익 계산으로 만드는 핵심 규칙.
  회피(소멸) 보스 목록은 런 스냅샷에 저장한다.

### 3.4 전투 포맷과 시간 예산

- **전 노드 7점제 듀스 유지.** 실측 판당 3~4분, 듀스 5분 (사용자 제공).
- 티어 구분은 포맷이 아니라 모디파이어와 보상으로 한다. 별도 단축 포맷 없음.
- 런 예산 정의 (코덱스 리뷰 반영): **36~40분 = 무패 클리어 기준 설계 중앙값**
  (전투 약 7판 + 비전투 노드). 기회의 보석 재도전 최대 3판을 포함한 패배 포함
  상한은 약 50~55분. 행 수 상수로 조정 가능.

### 3.5 광폭화 = 정예 티어 + 리그 축

- 원본 핑파이터의 광폭화 보스(스킬 강화 + 덩치 증가, 10% 출현, 신화리그 100%)를
  포팅한다. 패리티 레퍼런스 = 원본. 덩치 증가는 수비 면적이라는 실 게임플레이 변수.
- 지도에 표기되는 확정 광폭화 노드(보상 상향) + 일반 보스 노드의 소확률 광폭화(양념).
- 리그(승천 축) 상승 시 소확률이 상향된다. 신화리그 = 100% 패리티 유지.

### 3.6 승리 보상: 상자 계약

- **수량은 항상 1** (점수 무관 통일). 현행 점수 비례 수량(압승 3 / 일반 2 /
  듀스 1, `stage_clear_result_reward_plan_builder.gd`)은 **은퇴**한다.
  은퇴 시 승리 점수 파생 임계값 소비자를 GRT-054 요령으로 전수 감사할 것.
- 위험 프리미엄은 수량이 아니라 **등급 가중**으로만: 정예·광폭화·수문장 = 상위
  상자 가중 상향, 밴드 상승 = 가중 상승. (+1 드랍은 채택하지 않는다. v1.0의
  "1상자 통일"과 "+1" 병기는 모순이었음 — 코덱스 리뷰 반영.)
- **3종 논리 타입과 현행 구현의 매핑** (코덱스 리뷰 반영 — 현행은 `normal` /
  `guaranteed_mythic`(3%) 2종 + 비전초식은 별도 kind가 아니라 적격 보스·미보유
  시 기존 상자에 `boss_vision_offer_id`를 마킹하는 **치환**이다,
  `victory_loot_phase_state.gd:456`):

  | 신규 kind | 내용 | 적격 조건 | 폴백 |
  |---|---|---|---|
  | `chest_normal` (일반상자) | 재화·무혼·액티브 아이템·소형 보상 테이블. 현행 `guaranteed_mythic` 3%는 독립 kind에서 **일반상자 내부 잭팟 결과로 흡수** | 항상 | 없음 |
  | `chest_supreme_art` (절세무공상자) | 상급 무공 획득 | 항상 | 없음 |
  | `chest_secret_chosik` (비전초식상자) | 비전초식 획득. 현행 치환 로직(적격 보스 + 미보유)을 독립 kind로 승격 | 적격 보스 처치 + 해당 초식 미보유 | 미적격·전부 보유 시 `chest_supreme_art` → `chest_normal` 순 다운시프트 |

- 상자(공짜·무작위 도박 경로)와 파계승(무혼 소비·선택 경로)은 보완 관계로 유지.

### 3.7 무혼 경제: 전투는 모으는 곳, 노드는 결정하는 곳

- 전투 중 무혼 = **축적 전용**. 전투 중 선택 모달 금지. 수집 미니게임(수비 위치
  이탈 리스크)은 유지한다.
- 노드 소비처:
  - **파계승**: 무혼으로 초식 획득(2~3택 제시), 초식 제거·스왑(획득보다 고가,
    기존 초식 슬롯 스왑 시스템 재사용). 광장 아카데미(초식 습득·교환)의 기능 후계.
  - **수련장**: 무혼으로 능력치 수련.
- 기존 전투 내 초식 오퍼 개방 게이트(35%)는 **은퇴 대상**이다. 재튜닝하지 않는다.

### 3.8 기회의 보석 = 런의 목숨

- 런 시작 시 3개 고정. **런 스코프 자원** (영속 재고화 금지, 런 종료 시 잔량 소멸).
- **규칙 정의 (명확화)**: 보석은 재도전 비용이다. 패배 시 잔량 ≥ 1이면 1개
  소모 후 동일 노드 재도전. **잔량 0에서 패배하면 런 종료.** 즉 런당 재도전
  최대 3회, 패배 허용 최대 4회.
- 회복은 희소하게: 휴식 노드 회복, 상점 고가 판매. 상한 3.
- **구현 계약 (P1 — 현행 구조 재사용 금지)**: 현행 패배 흐름은
  `battle_defeat_flow_resolver.gd:117`이 registry의 보석 스토어를 읽고
  `plaza_save_store.consume_chance_gem()`(`plaza_save_store.gd:177`)이 **소비
  즉시 영속 `save()`** 한다. 이를 그대로 재사용하면 새 런이 이전 런 잔량을
  물려받는다. 보석 소유권은 메타 세이브가 아니라 **`run_state.chance_gems`**
  가 갖고, 저장은 이어하기용 런 스냅샷에만 한다. 기존 plaza 스토어 필드는
  마이그레이션 후 은퇴.
- 검토 항목: 보석 1개를 소모하고 해당 노드를 무보상 우회하는 후퇴 선택지
  (매치업 벽에서 런 강제 종료를 피하는 안전판).

### 3.9 노드 해소 트랜잭션 (결과화면 제거의 대체 경계)

- 현행 결과화면 종료는 미지급 보상 지급 + 스테이지 진척 반영 + 씬 전환을 묶는
  트랜잭션 경계다 (`stage_clear_result_finish_action_data.gd:40`
  `finish_next_stage` = `grant_pending_rewards` → `apply_stage_clear_progress`
  → reset). 결과화면을 제거하면 이 경계가 사라지므로, 신규 flow owner가
  동등한 경계를 소유해야 한다 (P1).
- **노드 해소 파이프라인 (멱등 계약)**:
  1. 전투 승리 판정 → 전리품 확정 (`node_resolution_id` 발급)
  2. 보상 1회 지급 (같은 `node_resolution_id`로 재실행해도 중복 지급 없음)
  3. 노드 완료를 런 스냅샷에 커밋
  4. 지도 진입 (다음 행 활성화)
- 크래시·강제종료 후 재개 시 pending 보상은 `node_resolution_id` 기준으로
  지급 여부를 판별한다. 보상 복제와 소실 둘 다 금지.
- 런 종료(클리어·패배)에만 결산 화면. 패배 결산은 잃은 것(런 빌드) 아래에
  **영속 소득을 반드시 병기**: 해금 재화, 도감 신규 등록, 수호령 친밀도, 기록
  갱신. "모든 걸 잃는다"와 "매 런이 남는다"의 공존이 재시작 동기다 (Hades 문법).

### 3.10 해금 (영속층)

- **풀 확장형**: 해금된 무공·초식·아이템이 등장 풀(상자·파계승·스폰·상점)에 추가된다.
- **구현 계약 (P2 — `unlocked_items`는 Godot 훅이 아님)**: 그 이름은 동결된
  Python 레거시 전용이며 Godot 런타임에 존재하지 않는다 (레거시 경로 수정
  금지). **Godot용 해금 스토어를 신설**하고(plaza/lingpet save store 관례를
  따르는 독립 스토어), 필드 스폰·상자·상점·가챠·파계승 오퍼 등 **모든 획득
  소비자가 동일한 단일 필터 함수를 관통**하도록 설계한다.
- 도감 = 해금 진척의 전시장.
- 노드 종류 해금도 카드로 열어둔다 (예: 파계승은 N층 최초 도달 시 해금).

### 3.11 액티브 아이템: 현행 유지

- 현행 수명 규칙이 이미 런 단위 보유다. 스테이지 전환 시 유지
  (`godot/scripts/core/match_reset_controller.gd`의 의도적 skip 계약),
  풀 리셋 시 전량 소거. **"풀 리셋 = 런 종료"로 매핑만 한다.**
- 전투 중 스폰 유지 (픽업은 모달이 없어 흐름을 끊지 않는다).
  획득처: 필드 스폰 + 상점 노드 + 일반상자.
- 포지션 = StS의 포션: 슬롯에 담아 런 내내 보유, "지금 쓸까 광폭화까지 아낄까"의
  런 단위 자원 결정.

### 3.12 귀속표 (완결)

| 런에서 잃는 것 | 영속으로 남는 것 |
|---|---|
| 무공·초식 빌드, 무혼, 액티브 아이템, 상자 내용물, 기회의 보석 잔량 | 해금(풀 확장), 도감, 수호령 로스터·친밀도, 해금 재화, 기록(최고 층·클리어 횟수·리그) |

### 3.13 광장 시설 이관표 (제안 · 확정 대기)

현행 광장 7시설 (`plaza_building_menu_catalog.gd`) 의 존치·이관·은퇴를 시설별로
확정해야 한다 (P2). 아래는 제안이며 시설별 최종 결정은 사용자 확정 사항이다.

| 시설 | 현행 기능 | 제안 |
|---|---|---|
| 상점 (모라) | 골드로 아이템 매매 | **런 노드 이관** (상점 노드) |
| 은행 (도윤) | 예금·출금·이자 | **은퇴 후보** (골드가 런 재화화되면 존재 이유 상실. 해금 재화 도입 시 재검토) |
| 가챠샵 (루미) | 액티브 캡슐 뽑기 | **상점 노드에 흡수** (뽑기 상품) |
| 수호령 상점 (링링) | 공명 알 뽑기·수호령 관리 | **메타 허브 이관** (영속층 — 결산·메인 메뉴 측 진입) |
| 대장간 (강철) | 아이템 강화 | **런 노드 후보** (§6 강화 거취 결정과 연동) |
| 선술집 (하랑) | 퀘스트 | **해금 시스템에 흡수** (도전과제·해금 트랙, 메타) |
| 아카데미 (서율) | 초식 습득·교환 | **파계승 노드로 이관** (기능 후계, 아카데미 은퇴) |

- AP·퀘스트 진행 등 광장 세이브의 기존 필드는 이관표 확정 후 마이그레이션
  계획을 별도 수립한다.
- 광장 UI 자산(교감·부화·강화 UI 등)은 폐기가 아니라 노드 모달·메타 허브에서 재사용.

## 4. 지도 아트 방향 (확정, 2026-08-16)

- 컨셉: **프롤로그(아라울의 첫 승부) 화풍의 연장.** 한지 바탕, 먹선, 주홍·금 팔레트.
  프롤로그 → 지도 → 로딩 방여도가 한 시각 언어로 묶인다.
- 노드 아이콘 = **인장(낙관) 모티프**: 전투=병기 인장, 상점=엽전, 휴식=찻잔,
  파계승=목탁 또는 파계 인장, 광폭화=붉은 귀면 등. 한지 위 붉은 도장은 가독성과
  화풍을 동시에 만족한다.
- 경로 = 붓선 점선. 밴드 전환 = 먹 농담과 지질(종이 톤) 변화로 고도감 표현.
- ⚠ 기술 주의: 이 화풍은 고휘도(아이보리) 바탕이다. ADD 계열 발광 FX는 밝은
  바탕에서 죽는다 (GRT-047의 역변종, 프롤로그 V4 팔레트 반전에서 실측된 사안).
  노드 강조·광폭화 오라·현재 위치 표시는 먹번짐 애니메이션, 멀티플라이/스크린
  계열, 또는 국소 다크 비네트 위 발광으로 설계할 것.

## 5. 구현 가이드 (Codex 핸드오프)

- **기존 플로우 무손상 개발**: 신규 flow owner 모듈을 기능 플래그 뒤에 만들고,
  광장 R3에서 검증된 원자적 전환 방식으로 프로덕션 승격한다. 결과화면·광장 진입
  루트 제거는 승격 커밋에서 원자적으로 수행한다.
- `scenes/main.gd`는 오케스트레이션 전용 유지. 신규 오너 모듈의 소유권은
  아키텍처 문서와 모듈 원장에 기록한다.
- **런 스냅샷 (이어하기) 계약 — 필수 필드 (P1 보강)**:
  - `run_id`, 스냅샷 스키마 버전, 지도 생성기 버전
  - 지도: 전체 그래프 직렬화 **또는** 시드 + 결정론적 파생 규칙(생성기 버전
    고정 전제). 어느 쪽인지 구현에서 명시적으로 선택·문서화
  - 진행: 현재 노드, 완료 노드 목록(`node_resolution_id` 포함), 회피(소멸)
    보스 목록, pending 보상
  - 경제: 무혼, `run_state.chance_gems`, 생성된 상점 재고, 구매 기록,
    `claimed_decoration_ids`
  - 빌드: 무공·초식·액티브 아이템·신화 상태 (현행 런타임 상태의 직렬화 경계 신설)
  - RNG: 게임플레이 RNG 상태 (연출 난수와 분리 계약 준수)
  - **저장 가능 시점 = 노드 커밋 완료 후 안정 경계로 제한** (전투 중·보상 지급
    중 저장 금지)
- 세이브는 `user://` 정책과 `config/name="pingfighter"` 호환 계약을 준수한다.
- 지도 씬은 기존 런타임 계약 준수: 게임 좌표 오버레이 클리핑, 스폰 프레임
  리포지션 글라이드(GRT-039), 모달 개폐 계약(GRT-058), 프리웜(콜드 진입 측정).
- 표준 게이트: 포커스 스모크(역방향 레그 포함), 헤드리스 로드, 워닝 스캔,
  `git diff --check`, 가시 작업 픽셀 QA. 플레이 가드 계약 준수.
