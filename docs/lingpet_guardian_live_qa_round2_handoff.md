## 1. 원인 클래스 (3번째 재발 — 전수 열거로 종결할 것)

수납 투영 분리(dc2b84466)가 게임플레이 억제를 위해 비활성화한 owner 표면
(companion_active·스킬/패시브·owner 보너스 키)을 **TAB 표시 행들이 그대로
소비**한다. 1차(수납 시 "알 없음" 패널)·2차(지속시간 스트립)는 9dddb9ab4로
복원됐지만 교감 미터·능력치 섹션이 누락됐다.

## 2. 계약

- **수납 = 게임플레이 비활성이지 정보 은폐가 아니다.** TAB 정보창의 모든
  표시 행은 수납 중에도 소환 중과 **동일한 실값**을 보여야 하며, 차이는
  상태 라벨("수납 중")뿐이다.
- **이번에는 부분 수정 금지** — 수납 억제 키를 소비하는 TAB 표시 표면을
  **전수 열거**하고(교감 Lv/포인트/다음 보상 라벨, 능력치 섹션의 상태·
  방어율·게이지·이속 행, 스킬 슬롯/레벨 표시, 기타 owner 스냅샷 소비 행),
  각 표면이 실값 채널을 읽도록 재지향하라. 열거 결과를 보고서에 목록으로
  첨부 (누락 재발 방지).
- 구현 방향: 표시용 스냅샷 빌더/merge가 수납 시에도 실값을 운반 (게임플레이
  억제는 runtime 소비자 측 fold로 이미 처리됨 — 표시 채널과 억제 채널 분리).
- 교감 행은 §9-4 삭제 예정 표면이므로 실값 표시 최소 수정만 (구조 개편 금지).
