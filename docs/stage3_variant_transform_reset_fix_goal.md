## 0. Fable이 확정한 원인 `[확인]`

`godot/scripts/stages/stage3/stage3_variant_boss_renderer.gd:420-423`

```gdscript
func _draw_ellipse(canvas: CanvasItem, center: Vector2, radii: Vector2, color: Color) -> void:
	canvas.draw_set_transform(center, 0.0, Vector2(maxf(0.001, radii.x), maxf(0.001, radii.y)))
	canvas.draw_circle(Vector2.ZERO, 1.0, color)
	canvas.draw_set_transform(Vector2.ZERO, 0.0, Vector2.ONE)   # ★ 여기
```

**마지막 줄이 캔버스 변환을 아이덴티티로 리셋한다.**

플레이필드는 `battle_scene_drawer.gd:144-153`
`_draw_transformed_playfield_scene()`이 걸어둔 `draw_set_transform` 안에서
그려진다. `_draw_ellipse`가 그 안에서 호출되어 아이덴티티로 되돌리면
**그 이후의 모든 플레이필드 드로가 원시 게임 좌표(0~760, 0~750)로 나간다.**

실 뷰포트가 2020x1246 이므로 원시 좌표는 화면 좌상단의 작은 영역에 찍힌다.
사용자가 본 "좌측 상단의 작은 창"이 정확히 그것이다. 그 안의 보스와 공은
별도 창이 아니라 **변환을 잃은 플레이필드 자신**이다.

⚠ 이 트랩은 저장소에 이미 기록돼 있다. **`draw_set_transform` 을 쓴 뒤
`Vector2.ZERO, 0.0, Vector2.ONE` 으로 되돌리면 안 된다.** 상위가 걸어둔
변환을 지우기 때문이다. 사용자 표현대로 과거에 여러 번 났던 사고다.

**스테이지 2의 같은 계열 렌더러(`stage2_variant_boss_renderer.gd`)는
`draw_set_transform` 을 아예 쓰지 않는다.** 그쪽이 안전한 형태다.

## 1. 계약

### S1. 리셋 제거

- `_draw_ellipse`가 상위 변환을 **보존**하게 하라. 방법은 판단해서 정하되
  근거를 적어라.
  - **권고**: `draw_set_transform` 을 쓰지 말고 타원을 폴리곤으로 그린다.
    스테이지 2 렌더러가 그 형태이며 상위 변환과 무관하게 안전하다.
    ★**GRT-006**: 애니메이션 오프셋에서 만든 점 집합은 삼각분할 가능성을
    보장해야 한다. `Geometry2D.triangulate_polygon` 으로 지켜라.
  - 대안: 진입 전 변환을 읽어 저장하고 종료 시 그 값으로 복원한다.
    다만 Godot 은 현재 draw 변환을 읽는 공개 API 가 없으므로 **호출부에서
    변환을 넘겨받아야** 한다. 이 경로를 택하면 모든 호출부를 고쳐야 한다.
- ★**GRT-055**: `draw_line` 에는 라인 캡이 없다. 원형 실루엣을 선으로
  흉내 내지 마라.

### S2. 같은 형태 전수 조사 ★

이 사고가 반복되는 이유는 **한 곳을 고쳐도 형제가 남기 때문**이다.

- 저장소 전체에서 `draw_set_transform(Vector2.ZERO, 0.0, Vector2.ONE)` 을
  검색하고, 각각이 **상위 변환 안에서 호출되는지** 판정하라.
- 플레이필드 변환 안에서 호출되는 것은 전부 같은 결함이다.
- UI·오버레이처럼 **자기 자신이 최상위 변환 소유자**인 경우는 정상이다.
  구분해서 표로 남겨라.
- 판정한 목록과 근거를 보고서에 남겨라. 이번에 고칠 것과 안전한 것을 갈라라.

### S3. 씰 ★이 목표의 핵심

**같은 사고가 반복되고 있다. 씰이 유일한 방어선이다.**

- 스테이지 3 변형 보스를 그린 **뒤에도 캔버스 변환이 유지되는지** 단언하라.
  드로 전후의 변환을 비교하는 방식이 필요하다.
- ★**픽셀로 판정하라.** 구조 단언만으로는 부족하다. 비헤드리스 캡처에서
  **플레이필드 밖(좌상단 필러 영역)에 보스·공 픽셀이 0인지** 세라.
  GRT-045 의 판정 방식과 같다.
- **리셋을 되살리면 RED 가 나는** 반증 레그를 남겨라. 이것이 회귀 차단의
  본체다.
- 가능하면 **스테이지 공통 씰**로 만들어라. 스테이지마다 따로 만들면
  다음 스테이지에서 또 빠진다.
