## 0. ★긴급 개정 (2026-08-19, 작업 중 반영 — 최종본)

**카드 구성이 확정됐다. 총 3장, 초식 1~2장 + 나머지는 무공, 무공은 2성 지급.**
정본 §3.17도 개정됐다(커밋 기준 최신). 이 절이 감사 문서의 "초식 1 + 무공 2"
서술보다 우선한다. **S1(오퍼 빌더)과 S3(레이아웃)만 영향받고 S0·S2·S4·S5의
계약은 불변이다.** 장수가 3장으로 유지되므로 레이아웃 예산 재검토도 불필요하다.

| 초식 후보 | 구성 |
|---|---|
| 2장 이상 | 초식 2 + 무공 1 |
| 1장 | 초식 1 + 무공 2 |
| 0장 | 무공 3 |
| 총 후보 3장 미만 | 화면을 열지 않고 건너뛴다 |

초식이 2장 이상 가능해도 **1장만 뽑는 경우가 있어야 한다**(무작위). 항상 2장이면
"1~2장" 계약이 아니라 "2장 고정"이 된다. 비율은 `TEMP_*` 상수로 둔다.

### 0-a. 무공 2성 지급 ★검증 필수

**무공 카드는 선택 시 2성(레벨 2)으로 시작한다.** 근거는 저울이다. 초식은 새
액티브 스킬 하나가 통째로 생기는데 1성 무공은 그에 맞서지 못해 선택이 성립하지
않는다.

⚠ **현행 지급 경로가 레벨 2를 직접 줄 수 있는지 가정하지 말고 검증하라.**
`runtime_perk_state.apply_choice`는 `_choice_apply_flow`에 위임하며 한 번에 한
레벨을 올리는 구조로 보인다. 두 번 호출로 2성을 만들면 **획득 연출과 천사의 축복
훅이 두 번 발화**할 수 있다(`apply_choice`가 `previous_raw_level`과 적용 후
레벨을 비교해 `_angel_blessing_runtime_state.on_accepted_choice`를 부른다).
레벨 지정 지급 경로가 없으면 신설하되, 기존 소비자의 동작을 바꾸지 않는 방식으로
한다. 부작용 이중 발화 여부를 **부정 레그로 봉인**하라.

또한 `max_level`이 2 미만인 무공이 있으면 그 카드는 후보에서 제외하거나 상한으로
클램프한다. 어느 쪽인지 실측 후 결정하고 보고한다.

### 0-b. 씰 필수 레그

**대장장이(또는 옵티머스) 레그를 반드시 넣어** 무공 3장 구성이 실제로 동작하는지
단언한다. 스매셔만으로 검증하면 이 경로가 통째로 미검증으로 남는다.
2성 지급도 **적용 후 실제 레벨이 2인지**를 단언한다(플래그가 아니라 값).

## 1. 무엇을 만드는가

캐릭터 선택 직후, 스토리 프롤로그 **앞**에 카드 화면이 한 번 뜬다.
**총 3장**(§0 구성표) 중 **1장만** 고르면 즉시 적용된 채 프롤로그와 1층 전투로
들어간다. 초식은 **해당 캐릭터 고유 초식**이며 비전초식은 제외된다(기존 술어가
자동 배제하므로 추가 작업 없음). **무공은 2성으로 지급된다.**
배경은 **검은색**, **무료**(가격 표시 없음), 재추첨 없음. 해금 필터는 다른 획득
경로와 동일하다. 탑 플래그 ON에서만 뜬다.

## 2. 착지 순서 (감사 §1 그대로, 고정)

| 순서 | 슬라이스 | 요지 |
|---|---|---|
| S0 | 후보 술어 공용화 + **파계승 해금 필터 누락 수리** | 아래 §3 참조 |
| S1 | 오퍼 빌더 + 상태 모듈 (헤드리스 전용, 화면 배선 없음) | 순수 로직 |
| S2 | 삽입 6곳 락스텝 배선 (검은 화면 + 자리표시) | 한 헝크 |
| S3 | 렌더 계층 (카드·검은 배경·가격 제거·7언어) | 픽셀 QA 집중 |
| S4 | 잔존 계약 (run_progress 등재 + 첫 prepare 관통) | 실 셸 씰 |
| S5 | 라이브 QA + 콜드 진입 실측 | 3캐릭터 |

각 슬라이스는 **단독으로 씰 GREEN이고, 다음 슬라이스 없이도 프로덕션이 오늘과
동일하게 동작**해야 한다. S2를 쪼개면 화면이 로딩에 덮이거나 입력이 전투로 새는
반쪽 랜딩이 된다(GRT-031).

## 3. S0에 동반 수리가 붙는 이유 (별건 아님)

실사에서 **파계승 무공 브랜치의 해금 필터 누락**이 드러났다. 초식 브랜치는
필터를 통과하는데 무공 브랜치는 통과하지 않아, 해금되지 않은 무공이 파계승
오퍼에 뜰 수 있다. 정본 §3.10의 "모든 획득 소비자가 동일한 단일 필터를
관통한다"의 위반이다.

시작 카드가 같은 후보 술어를 재사용하므로, 술어를 공용 모듈로 추출하는 **같은
헝크에서** 이 누락을 수리한다. 별건으로 미루면 두 소비자가 서로 다른 필터를 쓰는
상태가 굳는다. 파계승 기존 씰로 단독 검증되며, 시작 카드 없이도 GREEN이다.

## 4. 반드시 지킬 것

- 감사 **§5 함정 예방을 구현 전에 전부 읽고 적용**한다. 특히 다음 다섯.
  - **`get_choices()` 경로를 쓰지 마라.** 초식 등장이 35% 굴림에 걸려 "초식
    1장 확정"이 성립하지 않고, 전역 게임플레이 RNG를 소모한다.
  - **후보 수집은 `get_all_perk_data()`를 정확히 1회** 호출한다.
    `get_perk_data(id)` 반복 호출은 매번 전 카탈로그 병합과 딥카피를 한다
    (GRT-032).
  - **보상 픽의 4장 상수와 크기 검증을 공유하지 마라.** 별도 모듈로 분리한다.
  - **폴백은 all-or-nothing 복제 금지.** 보상 픽은 재고 부족 시 화면이 안 뜨고
    파계승은 오퍼를 통째로 버리는데, 시작 카드에서 그것은 곧 진행 차단이다.
    감사 §2.2의 폴백 매트릭스를 그대로 따른다.
  - **무장 토큰과 결과 원장을 분리**한다. 무장은 `GameSelectionState` transient
    토큰(디버그 직행·온라인·재진입에서 자동으로 뜨지 않게), 결과는
    `TowerAscentRunState` run_progress(첫 승리의 리셋을 넘어 살아남게).
    한쪽에 몰면 반드시 한쪽이 깨진다.
- **런은 카드 시점에 이미 시작되어 있다**(부트 프리웜 스텝 11). 시작되지 않은
  것은 런이 아니라 지도·노드다. 따라서 `run_id`가 이미 있으므로 결정론 시드를
  `Time.get_ticks_msec()`로 새로 만들지 마라.
- **카드 화면에서 스테이지 BGM은 아직 시작되지 않았다.** 메뉴 BGM이 흐르는 것이
  오늘의 실제 상태이며 의도와도 맞다. BGM을 새로 손대지 마라.
- 신규·개정 씰은 `.github/workflows/godot-ci.yml`과
  `godot/tools/run_pre_push_checks.ps1` **두 리터럴 목록에 동시 등재**한다.
- 통과 판정은 배치 종단선 `All Godot smoke tests passed.` + `SCRIPT ERROR`
  0건이다.
- **신규 에셋을 넣는다면 통합 후 본 트리 재임포트 완료까지가 완료 조건**이다.
  R4에서 신규 PNG를 `const preload`로 물었다가 임포트 캐시가 없어 의존 스크립트
  8개가 연쇄 컴파일 불능이 되고 탑 전체가 정지한 사고가 있었다. 이번 슬라이스는
  신규 에셋 0장이 기본값이다.
- 카피는 한국어 기본 + `LanguageSettings` 7언어 등재, 엠대시 금지.
- 로그 백업 선행. 표준 래퍼 `-AllowDuringPlay`. 커밋 분리·푸시 금지.

## 5. 확답 없음

감사 §6의 Q1·Q2는 아래로 확정됐다(감사 문서 §1에 근거 기재).

- **Q1 → A안.** 풀 = 절세무공과 특수 카테고리를 제외한 무공 + 캐릭터 전용 초식.
  정본 §3.17 문구도 "절세무공을 제외한 무공·초식"으로 이미 정정했다.
- **Q2 → (a).** 초식 후보 0장이면 무공 3장으로 대체. 총 후보 3장 미달에서만
  화면을 열지 않고 건너뛴다.

감사가 확답 없이 판정한 나머지(패배 후 재진입 시 재등장, 메뉴 BGM 유지,
스킵 없음, 이어하기 미지원)도 그대로 채택한다.

## 6. 검증

- 슬라이스별 씰(감사 §4 그대로). 신규 `tower_start_card_smoke.gd` + S2 배선 씰은
  **실 `BattleSceneShell`** 로 구동한다. dict FakeOwner 레그만으로는 이 계열
  결함이 통과한다(이번 세션에서 두 번 실증됐다).
- **부정 레그 필수**: 플래그 OFF에서 카드가 뜨지 않는다, 디버그 스테이지 직행에서
  뜨지 않는다, 총 후보 3장 미달이면 화면을 건너뛰고 프롤로그·랜딩이 정상
  시작된다, 첫 승리 `prepare_vertical_slice_combat`를 관통해도 선택 결과가
  살아 있다.
- `-Paths` 경고 + 헤드리스 + `git diff --check`.
- **Vulkan 캡처 3장 이상**: 카드 3장이 뜬 검은 화면, 1장 선택 직후, 프롤로그가
  정상 이어지는 프레임. **실 해상도(2020x1246)** 로 찍는다.
- **콜드 진입 실측**: 카드 진입 프레임 소요를 계측해 보고한다. 프롤로그 프리웜과
  경쟁하지 않는지 확인한다(GRT-042).
- 프롤로그 있는 경로(한미량)와 없는 경로 양쪽을 라이브로 확인한다.
- 판정 불가 지점이 나오면 중단·보고.

**완료 선언 조건**: S0~S5 구현·검증 + 게이트 blocked/unverified 0건 +
보고서 완성. 슬라이스별 중간 보고 허용.
