## ★1. 재고 4 → 8 은 UI 가 아니라 밸런스 변경이다

현재 `tower_ascent_shop_inventory.gd:24~25`

```gdscript
const REGULAR_STOCK_COUNT := 3
const PREMIUM_STOCK_COUNT := 1
```

= **4개**. 레퍼런스는 8개다.

⚠`:44~49` 는 후보가 모자라면 **상점을 아예 열지 않는다.**

```gdscript
if regular_candidates.size() < REGULAR_STOCK_COUNT:
    return {"accepted": false, "reason": "insufficient_regular_candidates", "stock": []}
```

### 착수 전 필수 측정 (이것부터 하고 보고하라)

`build_candidate_shelves` 가 돌려주는 `regular` / `premium` 후보 풀 크기를
**해금 상태별로** 재라. 최소한

- 런 시작 직후(해금 최소)
- 중반(대표 해금 조합)
- 전 해금

세 지점에서 `regular.size()` 와 `premium.size()` 를 찍어라.

**풀이 8개를 감당하지 못하는 구간이 하나라도 있으면 멈추고 보고하라.**
임의로 `REGULAR_STOCK_COUNT` 만 올려 `insufficient_*` 로 상점이 사라지게
만들지 마라. 그 경우 관제탑이 개수를 재결정한다.

감당 가능하면 8개로 간다. 배분(regular/premium 비율)은 네가 제안하고
근거를 보고하라. **금화 경제 영향도 함께 보고하라** — 한 방문에서 살 수
있는 총액이 두 배가 된다.

⚠**`INVENTORY_VERSION := "tower_shop_inventory_v2"` 를 올려라.** 시드 해시에
들어가므로 올리지 않으면 기존 저장 시드와 재고가 어긋난다.

## ★2. 제거 요청 항목은 현재 존재하지 않는다

사용자는 다음 제거를 요청했으나 **관제탑 grep 결과 전부 0건**이다.

- 상점 갱신 시간 / 남은 시간 / 새로고침 버튼 / 새로고침 비용 / 자동 상품 변경
- `"소지 아이템은 최대 3개까지 보관할 수 있습니다."` 계열 문구

**존재 여부를 네가 다시 확인하라.** 없으면 **"없어서 제거 대상 없음"으로
보고하라.** 있지도 않은 것을 "제거 완료"로 보고하지 마라. 그건 공허 작업이다
(GRT-040 유형).

만약 실제로 있으면 경로를 보고하고 제거하라.

## 3. 화면 구성 (레퍼런스 기준)

```
좌상단  [←] 상점            상단  🪙 금화   🔥 무혼
────────────────────────────────────────────────
상점 상품
┌──────────────────────────────────────────────┐
│ [카드][카드][카드][카드][카드][카드][카드][카드] │  가로 1열 8개
└──────────────────────────────────────────────┘
                  ─ 구분선 ─
                   소지 아이템
        [슬롯][슬롯][슬롯]   ← 동적 개수
                              우하단 [상점 나가기]
```

### 상품 카드 구성

아이콘 · 이름 · 한 줄 설명 · **하단에 금화 아이콘 + 가격**.
카드 크기와 간격은 전부 동일하게. 하나의 큰 패널 안에 넣는다.

### 재화 표시

**금화**(금색 동전)와 **무혼**(불꽃) **정확히 2종**. 보석·수정·다이아 금지.

⚠**구매는 금화만 쓴다. 모든 가격 표기는 금화 아이콘만.**
무혼은 잔액 표시 전용이다. 기존 무혼 소비 경로가 상점에 있으면
**바꾸지 말고 보고하라** — 관제탑이 판정한다.

## ★4. 소지 아이템 슬롯은 하드코딩 금지

기본 3칸이지만 **증가하는 시스템**이다. 상한 출처는

```gdscript
# stage1_active_item_hud_scene_drawer.gd:55~65 와 동일한 계약
runtime_perk_state.get_active_item_slot_capacity(3)
mythic_item_runtime.get_active_item_slot_capacity(capacity)
# 둘 중 큰 값
```

`character_info_overlay_owner_state.gd:149` 의
`active_item_slot_capacity(runtime_perk_state, mythic_item_runtime, base_count)`
가 이미 그 합성을 한다. **재구현하지 말고 기존 계약을 재사용하라.**

**요구**: 슬롯 UI 개수는 그 capacity 로 생성한다. `3` 을 상수로 박지 마라.
capacity 가 4·5·6 이어도 레이아웃이 깨지지 않아야 한다.
간격 자동 조절 / 컨테이너 / 가로 스크롤 중 현 구조에 맞는 것을 골라라.

**씰 요구**: capacity 를 3·5·8 로 바꿔 각각 슬롯 UI 개수가 따라오고
패널을 넘치지 않는지 단언하라. 3 고정으로 되돌리면 RED 가 되게 반증하라.
