# 수호령강화 후속 핸드오프 (Codex 실행용) — 빈 채널 오퍼 버그 + 결과 명시(스킬명·아이콘)

작성 2026-07-29. 정본 = `docs/lingpet_guardian_duration_redesign_plan.md` §5.
가드레일·씰 실행 규정은 기존 슬라이스와 동일(reset/stash 금지·로컬 커밋만·
불가침 유지·에디터 유휴 시 씰·RED 시 단독 2회 재실행).
커밋 순서: **① 버그 수정 → ② 결과 명시 데이터 → ③ 패널 표시·아이콘**.

## ① 빈 스킬 채널에 "스킬 +1"이 뜨는 버그 (최우선, 재현 완료)

### 재현 (Claude 실행 확인, 2026-07-29)

후보 생성기를 직접 구동한 결과:

- **A. 빈 로드아웃으로만 컨텍스트 설정** → 후보 =
  `duration, defense, gauge, mobility` (스킬 +1 정상 제외) ✅
- **B. 스킬 있는 컨텍스트로 한 번 설정 후, 빈 로드아웃으로 재설정** → 후보에
  `active_skill/slot1`, `passive_skill/slot1` **잔존**,
  `active_unlocked=true`, `passive_unlocked=true` ❌

### 원인

`lingpet_guardian_run_state._seed_present_skill()`이 **단방향 시드**다.
스킬 ID가 채워져 들어오면 `*_unlocked = true`로 세우지만, **빈 문자열이면
그냥 `return`할 뿐 false로 되돌리지 않는다.** 사전 필터
`lingpet_enhancement_buff_store._can_apply_skill_bonus()`는 이 플래그만
신뢰하므로, 한 번 켜지면 실제 채널이 비어도 "+1"이 계속 후보에 남는다.

트리거 경로: 부화는 `randomize_missing=true` →
`LingpetCatalog.pick_skill_loadout()`(레벨 0 = 빈 채널 가능)이지만, 다른
호출부들은 `randomize_missing=false` → `build_default_loadout()`으로
**스킬 ID를 항상 채워 반환**한다(레벨 1 고정). 이 경로가 먼저 돌면 플래그가
켜진 채 남는다. `_apply_current_loadout(owner, true, false, ...)` 호출부를
전수 확인해 실제 라이브 순서를 보고서에 명시할 것.

### 수정 계약

- **부화 롤 유래 시드**와 **강화로 획득한 해금**을 구분하라. 후자는 절대
  되돌리면 안 된다(플레이어가 지불해 얻은 것). 전자만 현재 로드아웃 실태에
  동기화한다. 구현 자유이나 최소 요구: 시드 출처를 구분할 수 있는 표식
  (예: `seeded_from_loadout` 계열) 또는 필터가 **현재 로드아웃의 실제 스킬
  보유를 함께 확인**하는 fail-closed 방식.
- 빈 채널 펫에게 올바르게 떠야 하는 카드는 **"추가 해금"**이다 — 필터 수정
  후 unlock 후보가 정상 등장하는지 함께 단언.
- 후보 0 → 카드 미등장, 재검증 실패 체인·+15초 폴백은 기존 계약 불변.

### 씰

`guardian_enhance_offer_engine_smoke` 확장(또는 신규):
- 빈 채널 펫: skill+1 후보 **부재** + unlock 후보 **존재**
- **기본 로드아웃 경유 후에도 동일**(위 시나리오 B를 그대로 레그로 — 현재
  씰이 이 순서를 안 밟아 놓쳤다)
- 강화로 획득한 해금은 이후 로드아웃 재설정에도 **유지**(되돌림 금지 반증)
- 반증 1회: 필터 수정을 in-place로 끊어 RED 확인 후 원복

## ② 결과 명시 — 어떤 스킬이 해금/레벨업됐는지 (데이터)

현재 결과 문구는 `lingpet_guardian_enhance_applier._build_feedback()`이
후보 라벨만 찍어 `"%s 획득"` (예: "패시브 스킬 +1 획득") — **어떤 스킬인지
알 수 없다.** 적용 결과에 대상 스킬 정보를 실어야 한다.

- 적용 결과 payload에 추가: 대상 스킬 **id / 표시명 / 이전 레벨 → 이후
  레벨 / 아이콘 경로**. 해금이면 해금된 스킬의 id·표시명·아이콘.
- 문구 예시(문안은 재량, 7언어 동기 필수):
  - 레벨업: `밀크 발사 Lv.2 → Lv.3`
  - 해금: `공명 증폭 해금`
  - 스탯형(이속/방어/기력/지속시간)은 기존 라벨 유지하되 **증가량 수치**를
    함께 표기 권장 (예: `방어율 +8%`) — 상수에서 읽어 하드코딩 금지.
- **랜덤 롤 시점에 확정된 대상**을 그대로 실어야 한다. 슬롯 해석(1/2번째)이
  적용 직전 재검증으로 바뀔 수 있으므로 **최종 적용 결과 기준**으로 만들 것
  (제시 시점 값을 캐시해 표시하면 불일치 발생).

## ③ 결과 패널에 스킬 아이콘 표시

- 컴팩트 패널(`lingpet_guardian_enhance_cutin_state` / 오버레이 호스트)의
  결과 배너에 **해당 스킬 아이콘을 함께 표시**한다. 레이아웃: 아이콘 + 텍스트
  가로 조합(아이콘은 배너 높이에 맞춘 소형), 기존 SD·리액션 연출과 충돌 금지.
- 아이콘 소스: `lingpet_catalog`의 `icon_texture_path` — 카탈로그 33개 경로
  **전부 디스크 실존 확인 완료**(Claude 검증, MISSING 0건). 공용 패시브 풀도
  아이콘 보유.
- 스탯형 보상(이속/방어/기력/지속시간)은 전용 스킬 아이콘이 없다 —
  **절차 심볼 또는 기존 스탯 아이콘으로 폴백**하고, 없으면 아이콘 없이
  텍스트만(레이아웃이 무너지지 않게). 예약-에셋 트랩 금지: 존재하지 않는
  경로를 per-frame draw에 넣지 말 것.
- 로드는 프리웜/캐시 경로 사용(모달 첫 프레임 히치 금지 — hot-path lazy-init
  트랩).

### 씰 + QA

- 결과 payload 씰: 레벨업 시 이전/이후 레벨·스킬 id·아이콘 경로가 실려 오고,
  해금 시 해금 스킬이 명시되며, **적용 최종 결과와 표시가 일치**(재검증으로
  대체된 경우 대체 결과가 표시됨).
- 아이콘 경로 실존 단언(카탈로그 전수 또는 표시 대상).
- **Vulkan 픽셀 QA 2장**: 스킬 레벨업 결과 패널(아이콘+`Lv.2 → Lv.3`) /
  해금 결과 패널. 캡처 경로 보고 첨부.
