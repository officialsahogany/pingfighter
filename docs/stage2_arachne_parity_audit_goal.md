## 0. 사용자 제보 — 최우선 조사 대상

사용자가 라이브에서 아라크네의 거미줄 스킬 두 종을 구분해 지목했다.

1. **플레이어 쪽으로 쏘는 거미줄** — 닿으면 이동속도가 느려진다.
2. **실점 위기의 거미줄** — 아라크네가 공을 막지 못할 위치(공과 멀리 있을 때)
   공을 향해 쏴서 묶는다.

사용자 체감은 **2번이 보이지 않는다**는 것이다.

**Fable 사전 확인 결과, 둘 다 코드에는 있다.**
`web_trap`(장판, 플레이어 감속 0.40)과 `web_rescue`(구출)이며,
`web_rescue`는 `_can_activate_web_rescue` → `_activate_web_rescue` →
`_update_web_rescue`가 update에서 실제로 호출되고 HUD 카드에도
"거미줄 구출"로 등록되어 있다
(`godot/scripts/stages/stage2/stage2_arachne_boss_state.gd:116-127, 176, 329-350`).

**따라서 의심 지점은 발동 조건이다.** 현행은 이렇다.

```
게이지 50 이상 + 쿨다운 25초 + ball_active
+ ball_pos.y < 25.0 + ball_vel.y < 0.0
```

두 가지를 원본과 반드시 대조하라.

- **거리 판정이 없다.** 사용자가 말한 "공과 멀리 있을 때"에 해당하는
  보스-공 거리 조건이 현행 코드에 **존재하지 않는다.** 막을 수 있는 위치에
  있어도 y 조건만 맞으면 발동한다. 원본에 거리 또는 도달 가능성 판정이
  있는지 확인하라.
- **y 25는 화면 최상단이다.** 보스 패들을 이미 지나쳐 실점이 사실상 확정된
  뒤에야 발동한다는 뜻이다. 원본의 트리거 y와 부호 규약(원본 좌표계가
  Godot과 같은 방향인지)을 확인하라.

원본과 다르면 **어떤 상황에서 발동하지 않는지**를 구체적으로 적어라.
"조건이 다르다"가 아니라 "이런 공에는 안 나간다"로 쓴다.

## 2. 조사 항목

### 2-1. 거미줄 스킬 두 종 ★최우선

§0의 두 스킬을 원본과 1:1 대조하라.

- 각각의 발동 조건, 비용, 쿨다운, 지속, 단계(shoot/hold/pull/strike 등)
- **거미줄 구출의 트리거 판정 정본**: 거리인가 y좌표인가 예측 도달 지점인가
- 묶인 공이 어떻게 되는가(정지·감속·끌어당김·되돌림). 현행은 보스를 공 쪽으로
  `lerp`로 당기는데(`:372`) 원본도 보스를 움직이는지, 아니면 공을 당기는지
- 장판의 플레이어 감속 0.40과 반경 50이 원본과 같은가
- 원본에만 있고 포팅본에 없는 스킬, 반대의 경우

### 2-2. 나머지 스킬과 AI 파리티

- 특수 게이지 증감, 분노(rage) 상태, 황금 거미줄 별
- 이동 AI와 특수 상태
- ⚠ **정의만 있고 아무도 부르지 않는 함수는 미포팅으로 분류한다**(GRT-053).
  두더지왕 감사에서 회전발톱 반환값을 호출부가 버리는 결함이 나왔고,
  아카무에서는 오오라 충돌 함수의 프로덕션 호출자가 0건이었다.
  **반환값을 만들지만 소비자가 버리는 형태**를 특히 주의해서 찾아라.
  대조 기준은 `paddle_bounce_boss_post_hit_handler.gd`의 달지 채찍 처리다.

### 2-3. 연출·오디오

### 2-4. 에셋 현황

- 지금 무엇으로 그려지는가(절차 도형인지 재사용인지). 실제 드로 경로를 지명하라.

### 2-5. HUD·탑 통합·씰 실태

- **HUD 키 계약을 반드시 확인하라.** 두더지왕은 `_build_skill()`이
  `active`/`cooldown_progress`를 내보내는데 공용 렌더러는
  `status`/`ready`/`progress`를 읽어 세 카드가 영구히 충전 0%였다.
  아라크네도 같은 `_build_skill()` 형태(`:596`)이므로 **같은 결함일 가능성이
  높다.** 렌더러가 읽는 키와 대조해 확정하라.
- 탑 2층에서 실제 전투 진입이 되는가. 비전초식이 등재되어 있는가.
- 승리·패배 화면이 아라크네 정체성을 보이는가, 아니면 청린귀 자산이 나오는가
  (두더지왕은 청린귀가 나왔다).
- `stage2_arachne_boss_port_smoke.gd`가 무엇을 실제로 단언하는가.
  **공허 GREEN이 있는지 확인하라.**
- **씰은 표준 래퍼로 실제 실행하라**(`-AllowDuringPlay`, 로그 백업 선행,
  고유 로그 경로). 두더지왕 감사는 실행하지 않아 씰 실태가 정적 분석에
  그쳤다. 이번에는 실행 결과를 문구별로 적어라. **로그와 캐시 생성은
  허용된다.** 금지되는 것은 저장소 코드 수정과 커밋이다.

## 3. 규율

- **읽기 전용.** 게임 코드·테스트·자산·설정 수정 금지. 보고서 1개만 작성한다.
- ★**grep 0건을 "없음"의 증거로 쓰지 마라.** 서로 다른 검색어 3개 이상과 다른
  디렉터리로 교차 확인하고, 확인 못 하면 uncertain으로 표시하라.
  한글 표시명·내부 id·영문 로마자가 서로 다른 경우가 많다.
- 수치는 코드 상수에서 직접 인용하라. **시간 환산은 `/60.0` 규약을 정본으로
  한다**(두더지왕 수정 지시문에서 확정. 아라크네도 이미 같은 규약을 쓴다).
- 경로는 저장소 루트 기준 상대경로 + 줄번호로 지명하라.
- 추측과 확인을 구분하라. 원본을 못 찾으면 어디를 어떻게 찾았는지 적어라.
- 심각도는 **관측 가능한 실패로 지명하라.** "원본과 다르다"가 아니라
  "그래서 플레이어가 무엇을 겪는가"를 적는다. 기록된 설계 결정이 있는지
  먼저 확인하라(GRT-053).
