## 사용자 보고

무공 1개 보유(슬롯 1/6) 상태에서

- **1번 카드 호버** → 기존 무공 오른쪽 빈 슬롯(2번째)에 하이라이트. **정상.**
- **2·3번 카드 호버** → **기존 무공 카드가 2번째 칸이나 다른 칸으로 이동**
  하면서 1번째나 다른 빈 슬롯을 하이라이트. **어색하다.**

### 사용자 확정 요구

> 항상 현재 무공 슬롯의 **내 무공들 바로 오른쪽 빈 공간**에 하이라이트.
> **현재 무공 슬롯에서 내 무공들의 위치는 그대로여야 한다.**

## ★진범 (관제탑 확정 — 재조사 금지)

`godot/scripts/hud/runtime_perk_overlay_renderer.gd`

호버 프리뷰가 합성 착지 셀을 목록에 끼워 넣은 뒤 **전체를 재정렬한다.**

```gdscript
preview_acquired.sort_custom(sort_tower_reward_hover_perks)   # :4256 부근
```

```gdscript
static func sort_tower_reward_hover_perks(a: Dictionary, b: Dictionary) -> bool:
	var a_level := int(a.get("level", 0))
	var b_level := int(b.get("level", 0))
	if a_level != b_level:
		return a_level > b_level
	var a_id := str(a.get("_sort_id", a.get("id", "")))
	var b_id := str(b.get("_sort_id", b.get("id", "")))
	if a_id != b_id:
		return a_id < b_id          # ★여기다 — 스킬 id 알파벳 순
	return int(a.get("_slot_cell_index", 0)) < int(b.get("_slot_cell_index", 0))
```

레벨이 같으면(신규 착지 셀은 보통 Lv.1) **스킬 id 알파벳 비교**로 갈린다.
착지 셀의 id 가 기존 무공 id 보다 앞서면 **앞칸을 차지하고 기존 무공이
뒤로 밀린다.** 카드마다 결과가 달라지는 이유가 이것이다. 1번 카드는 우연히
뒤로 정렬돼 정상으로 보였을 뿐이다.

★**비호버 경로는 정렬하지 않는다.** `character_info_overlay_perk_presenter.gd`
의 `build_slot_grid_entries` 는 들어온 순서를 그대로 두고 빈 칸만 채운다.
**정렬은 호버 경로에만 있다.**

---

## ★이것은 버그가 아니라 설계 결정 뒤집기다

`sort_tower_reward_hover_perks` 위 주석이 의도를 명시한다.

> Preserve and compare the pre-transform identity so
> **hover order matches the real post-purchase order.**

W4 는 "구매 후 실제 배치를 미리 보여준다"를 의도했다. 사용자는 그것을
**거부하고 위치 고정을 택했다.** 그러니

- "버그를 고친다"고 접근하지 마라. **설계를 바꾸는 것이다.**
- 주석과 그것을 봉인한 씰을 **함께 다시 써라.** 남겨두면 다음 사람이
  되돌린다.

### ★착수 전 판정해서 보고할 것

**실제 구매 후 순서가 정말 레벨+알파벳 정렬인가?**
`build_slot_grid_entries` 가 정렬하지 않으므로, 실제 순서는 `acquired` 가
쌓이는 순서다. 그렇다면 위 주석의 전제가 **틀렸을 수 있다.**

- 구매 직후 `acquired` 의 실제 순서를 확인하라.
- 정렬되지 않는다면 → 호버 정렬은 처음부터 실제와 어긋나 있었다.
  그 사실을 보고하라. 사용자 요구가 오히려 **불일치를 없앤다.**
- 정렬된다면 → 호버(위치 고정)와 구매 후(재정렬)가 갈라진다.
  **그 부작용을 보고하라.** 사용자는 그래도 위치 고정을 원한다고 이미
  확정했으므로 요구대로 구현하되, 구매 직후 카드가 재배치되는 체감을
  보고에 명시하라.

## 요구

1. **기존 획득 항목의 표시 위치를 호버 중에 바꾸지 마라.**
   비호버 경로가 쓰는 순서 그대로 둔다.
2. **합성 착지 셀은 기존 항목들 뒤, 첫 빈 슬롯에 놓는다.**
   = 내 무공들 바로 오른쪽.
3. 착지 셀이 여러 개인 경우(다중 착지)에도 **기존 항목 뒤로 연속 배치**한다.
4. 슬롯이 가득 찬 경우(예: 6/6) 동작을 **판정해서 보고하라.** 놓을 빈 칸이
   없다. 현재 어떻게 처리되는지 확인하고, 바꿔야 하면 관제탑 판정을 기다려라.
5. **동일 스킬 레벨업 착지**(기존 셀이 승급하는 경우)는 위치를 옮기지 말고
   **그 자리에서** 표시하라. 현재 `_slot_cell_index` 로 매칭하는 경로가 있다.

⚠**`sort_tower_reward_hover_perks` 를 그냥 지우지 마라.** 융합 셀 식별
(`_sort_id` 로 pre-transform identity 비교) 같은 다른 역할이 붙어 있을 수
있다. 무엇이 남아야 하는지 판정하고 보고하라.
