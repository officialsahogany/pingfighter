### 2-1. 기하가 강제하는 구도 (재구성 브리프의 핵심)

패들 앵커는 고정값이다: `PLAYER_Y = 700`, 패들 높이 `50`, 라이더 rect 는
`y = player_pos.y + paddle.y - draw + 12` 이므로 **라이더 rect 하단 = 762** 로
draw_size 와 무관하게 상수다(§B-5 리프트 0 이라 부양분도 없다).

소켓은 그 762 에 찍힌다. 따라서:

```
마운트 최하단 = 762 + (소켓 아래 불투명 높이)
```

⚠️ **정직한 한계**: 필드 바닥은 750 이고 라이더 rect 하단 762 는 이미 12px 아래다
(현행 플레이어 스프라이트도 동일한 +12 오버행으로 출하 중이다). 그래서 "bbox 가
750 안" 은 소켓을 라이더 앵커에 묶어두는 한 **수학적으로 불가능**하다. 달성 가능한
최선이자 이 브리프의 목표는:

> **소켓 아래 불투명 픽셀 = 0** → 마운트 최하단 = 762 = **현행 플레이어 스프라이트
> 하단과 같은 선**. 즉 탑승이 새로 만드는 바닥 침범은 0 이다.

좌표 대역을 못박는다:

| 구간 | 의미 |
|---|---|
| y ≤ 750 | 필드 내부 |
| 751 ~ 762 | **기존 오버행 대역** — 현행 플레이어 스프라이트가 이미 쓰는 구간(허용) |
| y > 762 | **신규 침범** — 어떤 마운트 픽셀도 여기 있으면 안 된다(G9) |

⚠️ "y > 750 = 0" 이 진짜 목표라면 그것은 **아트로 달성할 수 없다** — 라이더 rect
하단이 상수 762 이므로 런타임 앵커를 −12px 바꾸는 변경(§B-1 개정)이 필요하다.
이 브리프는 앵커 유지를 전제하므로 목표를 y > 762 = 0 으로 둔다.

이것이 "꼬리를 위·옆으로 감아라"의 수치적 정의다: **안장이 실루엣의 최하단**이어야
하고, 꼬리·뒷다리·엉덩이 어느 것도 안장선 아래로 내려가면 안 된다.

### 5-1. 소켓 검출 정의 (G3/G4 의 전제)

PNG 에는 소켓 좌표가 없다. 아래 규칙으로 **감청 안장 패드에서 기계적으로 추출**한다:

```
navy     = 불투명 ∧ (b > r+25) ∧ (b > g+10) ∧ (b < 200) ∧ (r < 160)
pad      = navy 의 4-이웃 **최대 연결성분**,  면적 ≥ 불투명 픽셀의 1.5%
assembly = (pad ∪ gold) 중 **pad 를 포함하는** 연결성분   ← 안장 어셈블리
socket   = ( pad bbox 가로 중앙 ,  **assembly** bbox 하단 y + 1 )
```

★ **v2 정정(2026-08-14, 생성 4회 실패 후)**: 초판은 socket_y 를 감청 패드 하단으로
잡았다. 그런데 안장은 감청 패드를 **금 U 프레임이 아래에서 감싸는** 구조이고
(레퍼런스에서 패드 하단 325 → 어셈블리 하단 362, **+37px**), 그 프레임은 §3
정체성 락 항목이라 지울 수 없다. 즉 패드-단독 정의는 "패드가 실루엣 최하단"을
요구해 **G3 를 구조적으로 불가능**하게 만들었다 — imagegen 4회가 전부 같은 지점
에서 떨어진 원인이 모델 결함이 아니라 **게이트 정의 결함**이었다.

⇒ socket 의 y 는 **어셈블리 하단**으로 잡는다. 라이더 rect 하단이 안장 최하단에
맞고, 실제 엉덩이선(패드 하단)과의 차이 `seat_offset` 은 **N 시트 저작 오프셋**으로
흡수한다(런타임 계약 변경 없음 — 레이아웃 키는 그대로 6개다).

`seat_offset = assembly 하단 − pad 하단` 은 검증기가 후보마다 출력한다. N 착석
시트는 캐릭터 엉덩이선을 **셀 하단에서 `seat_offset × D/512` px 위**에 두고
저작한다 — D=210 확정값 기준 **운영 9.43359375px**, **512 저작 좌표 51.38298px**.

독립 교차검증: 빈안장/탑승 차분으로 잡은 라이더 하단(로브 밑단)은 패드 하단과
**dy 4.0** 으로 일치한다 — 즉 "엉덩이선 = 패드 하단"이라는 물리적 해석은 유지된다.

**폴백**: 감아 올린 꼬리가 안장을 가려 pad 최대성분이 1.5% 미만이면 자동 검출은
**무효**다. 그 경우 소켓은 자동 게이트가 아니라 **수동 승인값**으로 강등하고,
`*_manifest.json` 에 좌표·근거 캡처를 남긴 뒤 사람이 승인한다(자동 판정 사칭 금지).

| G9 | 합성 실렌더 | **출하 draw_size(카탈로그에서 읽는다)·라이더 94** 로 좌·중·우 3지점 A/B 차분: ① **y > 762 마운트 픽셀 0개** ② **좌우 오버행 ≤3px** ③ 안장 오차 ≤2px. 음성 대조군 **D=240 은 벽에서 반드시 횡 게이트를 밟아야** 한다(크기 단위 집계 — 중앙은 어떤 크기든 0). 실행기 `godot/tools/baekrin_mount_base_g9_capture.gd` |

### 5-3. G7 — 꼬리 길이 (마스크 제출 필수)

흰 몸체와 흰 꼬리는 색으로 분리되지 않는다. 따라서 **꼬리 마스크를 산출물로 제출**
한다: 셀과 **동일 해상도**의 1채널 PNG, 꼬리만 255. 범위는 **꼬리가 몸 실루엣을
떠나는 엉덩이 접합부부터 끝 장식(금고리·청자 보석)까지**.

판정 = 마스크 ∧ 불투명의 최대 연결성분에 대한 **4-이웃 측지 지름**(BFS 2회).
레퍼런스 상수 **208px** 은 같은 스크립트로 레퍼런스 셀의 `불투명 ∧ y ≥ 379`
(= 누끼 y ≥ 1010, 뒷다리를 제외하고 꼬리만 남는 절단선) 최대성분에서 실측했다.
마스크 미제출 시 G7 은 SKIP 이 아니라 **FAIL** 이다.

### 5-4. G8 — 재질 팔레트 (CIEDE2000, 2축 판정)

마스크 술어(고정):

```
porcelain_white : V≥190 ∧ S≤0.16
gold            : S≥0.30 ∧ r>g+18 ∧ g>b+25 ∧ V≥110
celadon_jade    : 0.14≤S<0.45 ∧ g≥r ∧ g≥b−6 ∧ 120≤V≤235
navy_saddle     : 5-1 의 pad (최대 연결성분)
```

⚠️ **"표본 dE 중앙값 ≤ 2.5" 같은 단일 문턱은 쓰지 않는다** — 백자 크랙과 금속
하이라이트는 재질 **내부** 산포가 원래 크고(자기중앙 p95 dE 8.9~23.5), 그 문턱은
레퍼런스 자신도 탈락시킨다(자기검정으로 확인). 두 축으로 나눈다:

| 축 | 통계량 | 상한 | 레퍼런스 값(셀 512) |
|---|---|---|---|
| ① 중심 이동 | dE2000(후보 재질 중앙 Lab, 레퍼런스 중앙 Lab) | ≤ 2.5 | 백자 (90.9, 1.2, 3.5) · 금 (63.7, 14.4, 51.3) · 청자 (73.2, −9.9, 20.2) · 감청 (32.6, −1.7, −17.6) |
| ② 산포 변화 | \|후보 p95 − 레퍼런스 p95\| (각 재질 자기중앙 기준) | ≤ 3.0 | 8.95 / 23.49 / 11.53 / 12.11 |
| ③ 점유율 | \|후보 비율 − 레퍼런스 비율\| / 레퍼런스 비율 | ≤ 0.60 | 52.02% / 25.11% / 0.35% / 2.91% |

**전역 색보정은 금지**한다(원화 팔레트가 정본). 허용되는 색 변경은 누끼 스필 제거
(§1 파라미터)뿐이다. 재질 마스크가 불투명의 0.1% 미만이면 그 재질은 소실/색역
이탈로 보고 즉시 FAIL.

### 5-4b. G6 상한 완화 0.72 → 0.75 (2026-08-14, Claude 판단)

초판 0.72(운영 260px)는 **직선 꼬리** 원화만 보고 정한 권고값이었다. 꼬리를 위·옆
으로 감으면 폭이 구조적으로 늘어 실측 후보가 0.703~0.771 로 나왔다. 상한의 근거
였던 "벽에서 화면 밖으로 나간다"는 어차피 패들(155px)보다 넓은 마운트면 전부
발생하므로 260 vs 270 은 의미 차이가 없다. ⚠️ 후보를 본 **뒤** 문턱을 올린 것이라
게이트 쇼핑으로 읽힐 수 있다 — 명시적으로 Claude 판단이며, 되돌리라면 되돌린다.

### 5-5. 검증기 자기검정 (2026-08-13)

레퍼런스 셀(직선 꼬리)로 돌리면 **G3 만 FAIL, 나머지 전부 PASS** 다. G3 실패는
정상이다 — 꼬리가 안장선 아래로 내려가 있는 것이 바로 재구성의 이유다. 즉 이
게이트는 "레퍼런스도 통과하는 무의미한 게이트"가 아니고, 반대로 "레퍼런스조차
탈락시키는 과도한 게이트"도 아니다.

⚠️ 파이프라인 순서 함정(자기검정에서 발견): 마젠타 스트립을 **리샘플 전에만**
돌리면 LANCZOS 축소가 링잉으로 마젠타 픽셀을 되살린다(512 셀에서 115px 재발).
**셀 리샘플 후에 한 번 더** 돌려야 G2 가 0 이 된다.
