# 지시문 Y5 — 층 경로 모양을 시드마다 다양하게

- **발행**: 관제탑 2026-08-27. 기준선 = 본 트리 **`88eb714fa`**.
  **격리 워크트리 + 격리 브랜치.** 본 트리 편집·통합·푸시 금지.

## 사용자 보고

> 1층 경로 형태, 그리고 2·3·4층 이상의 경로 형태가 정해져 있다.
> **지금은 2·3·4층 모양이 전부 똑같다.** 런마다, 즉 **시드마다 모양이 좀 더
> 다양했으면** 좋겠다. 지금은 너무 인위적으로 다 똑같다.

## ★진범 (관제탑 확정 — 재조사 금지)

`tower_ascent_map_generator.gd:1437`

```gdscript
func _choose_route_lane_count(
	_rng: RandomNumberGenerator,      # ★언더스코어 = 의도적 미사용
	floor_number: int,
	previous_lane_count: int,
	active_clear_floor: int
) -> int:
	if floor_number == active_clear_floor + 1:
		return 1
	if previous_lane_count <= 1:
		return ROUTE_CANDIDATE_COUNT                                  # 2
	return mini(MAP_LANE_COUNT_MAX, previous_lane_count * MAX_NODE_OUTGOING_EDGES)
```

`_choose_gatekeeper_lane_count` 도 `_rng` 를 받고 무조건 `1` 을 돌려준다.

★**레인 수는 직전 행의 순수 함수다. RNG 가 전달되지만 두 함수 모두 쓰지
않는다.** 그래서 모든 층이

```
관문 1 → 2 → 4 → 관문 1 → 2 → 4 → ...        (2~8층, 선택 행 2개)
관문 1 → 2 → 관문 1                            (9층 이상, 선택 행 1개)
```

로 **구조적으로 동일**하다. 시드가 안 먹는 버그가 아니라 **애초에 시드를
쓰지 않는다.** 시드는 노드 종류(상점·수련·휴식…) 배치에만 관여한다.

## 요구

**층 경로의 실루엣이 시드마다 달라지게 하라.**

`_choose_route_lane_count` 에 이미 `rng` 가 전달되고 있으므로 배선은 쉽다.
**어려운 것은 제약 안에서 설계하는 것이다.**

### ★절대 깨면 안 되는 것

1. **층 관문은 단일 레인 초크포인트.** `_choose_gatekeeper_lane_count` 는
   항상 1이다(피드백2 8항). 관문을 우회해 보스 없이 층을 넘는 경로가
   생기면 안 된다. **이 함수는 건드리지 마라.**
2. **`MAX_NODE_OUTGOING_EDGES = 2`** — 한 노드의 나가는 간선 상한. 레인 수는
   한 행에 최대 2배까지만 늘 수 있다.
3. **보스 간격 규칙** — 두 보스 행 사이에 완전 NPC 행이 최소 하나.
   관문이 보스이므로 층당 최소 1개의 완전 NPC 행이 필요하다.
   상세는 `_count_boss_spacing_violations`.
4. **`_has_floor_one_boss_avoidance_path`** 성립.
5. **1층 구조는 그대로.** Y1(`b42d17928`)이 방금 3스텝으로 확정했다.
   `FLOOR_ONE_EXPANSION_ROW_ROLES` 경로를 건드리지 마라.
   ⚠사용자는 1층 모양이 아니라 **2층 이상이 서로 똑같은 것**을 지적했다.
6. **결정성** — 같은 시드는 같은 지도를 낳아야 한다. 프레젠테이션용 RNG 를
   쓰지 말고 지도 생성 RNG 를 써라. **같은 시드 2회 생성 → 그래프 해시 동일**
   을 씰로 증명하라.
7. **2층 이상 층당 행 수**(`_optional_row_count_for_floor`)는 **길이**를 정한다.
   길이를 바꾸면 체감 길이가 흔들린다. 행 수를 시드로 흔들려면
   **관제탑 판정을 먼저 받아라.** 기본은 행 수 고정, 실루엣만 변화다.

### ★★최우선 제약 — 지도 렌더 예산이 이미 한계다

`tower_ascent_floor_one_expansion_contract_smoke` 진단선(현재 착지본):

```
fit_all_budget  path=1506 clouds=25 total=1531 limit=1536 margin=5
                base_dot_gap=21.465 final_dot_gap=44.094 max_final_dot_gap=44.378
```

**1,536 중 여유가 5다.** `final_dot_gap` 도 상한 44.378 에 거의 붙어 있어
**생성기가 이미 점 간격을 최대로 벌려 겨우 맞추고 있다.**

⚠**경로가 길어지거나 간선이 늘면 즉시 초과한다.** 레인을 4로 유지하면서
교차를 늘리는 식의 "화려한" 변화는 위험하다.

**필수**: 변경 전후로 **동일 2,000 시드**에 대해
- 최종 생성 성공률
- `fit_all_budget` 의 `total` / `margin` **최솟값**
- `final_dot_gap` 최댓값과 상한 초과 시드 수
- 후보 재시도 평균/최대

를 재고 **표로 보고하라.** **margin 이 0 이하로 가는 시드가 하나라도 있으면
멈추고 보고하라.** 점 간격 상한을 올려 덮지 마라.

★**레인을 줄이는 방향은 예산에 유리하다.** 예컨대 세 번째 행을 4가 아니라
3으로 뽑는 시드를 섞으면 노드와 경로가 줄어 여유가 생긴다. 늘리는 쪽보다
**줄이는 쪽을 섞어 다양성을 만드는 편이 안전하다.**

## ★다양성은 눈으로 판정하지 마라 — 측정하라

"모양이 달라 보인다"는 근거가 아니다. **정량 지표를 정의하고 전후를 비교하라.**

권장 지표(네가 더 나은 것을 제안해도 된다):
- 층별 레인 수열(예: `1-2-4`)을 문자열로 만들어 **2,000 시드 × 12층에서
  나타나는 고유 수열 개수와 분포**
- 한 런 안에서 **서로 다른 수열을 가진 층의 비율**
- 가장 흔한 수열의 점유율(현재는 100%일 것이다)

**변경 전 값이 "고유 1종·점유율 100%"임을 먼저 찍어 baseline 으로 보고하고,
변경 후 값을 같은 방식으로 보고하라.**

⚠**다양성이 지나쳐 특정 층이 극단적으로 좁거나 넓어지지 않는지**도 보고하라.
한 레인만 있는 행이 연속되면 선택지가 사라진다.
