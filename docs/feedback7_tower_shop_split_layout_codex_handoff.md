## ★가장 큰 함정 — 폭이 아니라 콘텐츠다

**탑 상점엔 판매 경로가 아예 없다**(`tower_ascent` 전체에서 sell 0건).
그리고 **재고가 6칸뿐**이다. 원본의 5열×6행(30셀) 좌/우 패널을 그대로
옮기면 **좌측은 읽기 전용이고 우측은 24칸이 빈다.**

**관제탑 판정**: 사용자는 "좌측에 내 아이템, 우측에 파는 아이템"만 요청했고
**판매 기능은 요청하지 않았다.** 따라서:
- **좌측 = 보유 아이템 열람 전용**(판매 없음). 라벨도 "판매"가 아니라
  "보유 중"으로. 원본 문구를 그대로 베끼지 마라.
- **그리드는 실제 개수에 맞춰 줄여라.** 5열 30셀 고정이 아니라, 재고 6칸과
  보유 개수에 맞는 열수/행수를 산출하라. 빈 칸이 화면의 80%를 차지하면
  개편의 의미가 없다.
- 판매 기능 추가는 **이번 스코프 밖**이다. 필요해 보이면 보고만 하라.

## 작업

### A. 지오메트리 — 새로 그리지 마라

`PlazaInteriorLayout`이 이미 원본 수치(패널 280×320, 셀 42, 갭 6, 5열,
시작 오프셋 14/38)를 760×750 캔버스에 갖고 있다. 둘 중 택일:

- (a) `PlazaInteriorLayout` 상수를 탑에서 직접 참조 → 공유 계약이 생기므로
  `plaza_trade_*` 씰을 집중 CI에 함께 등재해야 락스텝이 유지된다.
- (b) ★**권장** — `tower_ascent_node_modal_state.gd`에 `SHOP_TRADE_*`
  상수를 신설해 **값만 복제**. 결합이 없다. 탑 모달은
  `content_scale`/offset 스케일링을 쓰는데 플라자는 단순 scale이라
  **스케일 계약이 다르다.** 드리프트 위험은 주석으로 상호 참조를 남겨 막아라.

### B. 레이아웃 플래그

`LAYOUT_FLAG_SHOP_COMPACT`를 **폐기하지 말고**
`LAYOUT_FLAG_SHOP_TRADE_PANELS`(가칭)를 신설해
`build_screen_layout()` 캐시 dict에 `shop_player_panel_rect` /
`shop_stock_panel_rect` / 셀 상수를 담고, `_build_layout_flags()`가 shop일 때
켜도록 하라.

★**셀 rect 산출 함수는 반드시 한 곳**에서 나와야 한다
(`get_shop_cell_rect(panel_rect, visible_index)`). 그리기·히트테스트·
프리웜이 **모두 그것을 호출**해야 한다 — **GRT-022**(그린 자리와 클릭 자리가
갈라진다). 반증은 **카드 중심점이 아니라 상단 모서리**로 재라.

### C. 히트테스트 분리

- 우측 재고 셀 = 기존 액션 인덱스에 매핑(구매 유지).
- 좌측 보유 셀 = 액션이 아니므로 `get_action_rects()`에 **넣지 말고**
  별도 `get_owned_cell_index_at(position, view_size)`를 만들되 **같은
  layout dict**를 먹여라.
- `_action_index_at_position`의 **역순 순회 규칙**과 충돌하지 않게 두 영역이
  겹치지 않음을 씰로 고정하라.

### D. 호버 탭

- 카드 내부 `build_tower_node_hover_detail_layout` 경로는 42px 셀에서
  무의미해지므로 **우회**하고, `character_info_overlay._draw_dual_item_tooltip`
  / `_set_hover_data`를 써라.
- `render_context` 주입은 **호버 중일 때만**(수련장 전례 그대로, **GRT-043**).
- 툴팁 좌 박스 = 이름/등급/설명, 우 박스 = 가격·매진·잔액부족 사유
  (현행 `_build_shop_actions`의 `cost_text`/`unavailable_reason` 이관).
