# 탑 보스 배선 복구 /goal 지시문 (2026-08-18) — 보상 픽의 선행 작업

- **정본**: `docs/tower_ascent_run_map_plan.md` v1.9 §3.3 미배선 경고 · §3.9
  해소 id · 감사 정본 `docs/tower_reward_pick_preflight_audit.md` §0·§P1-A·§P1-B.
- **왜 먼저인가**: 지도에서 고른 보스가 실제 전투 상대가 되지 않는다. 경로
  선택·회피 규칙·광폭화 노드·비전초식 확정 등장이 전부 이 배선 위에 서 있어,
  배선 없이 보상 픽을 얹으면 "그 보스의 비전초식"이라는 계약이 성립하지 않는다.
- **완료 보고**: `docs/tower_boss_routing_report.md`. 푸시 금지.

## 1. 확인된 현상 (Fable 코드 실사, 재확인 후 착수할 것)

1. `tower_ascent_flow_ending_progress.gd:332` `_complete_map_transition()`은
   도착 노드가 비전투면 노드 모달을 열고, **전투 노드면 `_finish_vertical_slice()`
   로 탑 플로우를 종료**한다. 도착 노드의 보스 정보는 전투 씬에 전달되지 않는다.
2. `boss_slot_id`는 `godot/scripts/tower_ascent/` 밖 소비자가 0건이다.
3. 탑 플로우는 `current_stage`를 읽기만 한다
   (`tower_ascent_flow_map_progress.gd:30`). 되쓰는 경로가 없다.
4. `_finish_vertical_slice()`가 `_map_seed = 0`으로 되돌린다(`:327`). 같은 런
   두 번째 전투부터 시드 0 지도가 생성된다.
5. `prepare_vertical_slice_combat`는 매번 노드 id를 페이즈 엔트리로 되돌린 뒤
   해소 id를 조립하므로, 한 런의 모든 전투가 같은 `combat_victory` id를 발급한다
   (`map_progress.gd:42-44`, `:187`). 지금 안 터지는 이유는 해소 id 집합이
   매 승리 `_reset_runtime_state()`로 비워지기 때문이다
   (`flow_state.gd:174-196`).
6. 캐리오버 allowlist는 `skipped_boss_ids` 하나뿐이다(`map_progress.gd:10-12`).

## 2. 작업 항목 (각각 독립 커밋)

1. **도착 노드 보스를 전투에 반영**: 도착한 전투 노드의 보스 정체(`boss_slot_id`
   또는 그 매핑 결과)를 전투 씬이 읽는 단일 경로를 만든다. 기존 보스 선택
   경로(스테이지 보스 결정 오너)를 찾아 그 입력을 탑에서 주입하는 방식이
   기본안이며, 새 병렬 경로를 만들지 않는다. 임시(껍데기) 보스 슬롯은 기존
   폴백 규칙을 따르되 폴백이 조용하지 않게 로그를 남긴다.
2. **해소 id 유일 축 신설**: 승리 회차(승리 시퀀스 카운터) 또는 도착 노드 id를
   포함해 런 안에서 유일하게 만든다. 같은 런 두 번째 전투가 첫 전투와 다른 id를
   받는지 부정 레그로 봉인한다.
3. **런 진행 필드 캐리오버 정리**: 매 승리 초기화되면 안 되는 진행 상태의
   목록을 정의하고 `existing_progress` allowlist와 `run_state.begin()` progress
   인자에 등재한다. 씰은 `prepare_vertical_slice_combat`를 **두 번 관통**해야
   유효하다 (단일 인스턴스 직접 호출은 false-GREEN).
4. **지도 시드 소유권**: `_finish_vertical_slice()`의 `_map_seed = 0` 대입을
   제거하거나 시드 소유권을 런 상태로 올린다. 같은 런의 두 번째 전투가 시드 0
   지도를 만들지 않는지 봉인한다.
5. **회피 규칙 실동작 확인**: 배선 후, 지나친 보스가 실제로 그 런에서 다시
   전투 상대로 나오지 않는지 부정 레그로 봉인한다.
6. **별건 라이브 결함 동반 수정**: 탑 노드 모달의 히트테스트 좌표계가 렌더와
   어긋나 **마우스로 항목을 선택할 수 없다**(키보드는 정상). 감사에서 겹침 0으로
   실측된 사안이다. 원인을 진단해 수정하고, 반증은 항목 중심점이 아니라 **상단
   모서리**로 잰다 (GRT-022).

## 3. 규율

- 로그 백업 선행. 표준 래퍼 `-AllowDuringPlay`. 커밋 분리·푸시 금지.
- 플래그 OFF 레거시 무손상 부정 레그 필수.
- 검증: 배선 씰(지도 선택 보스 = 실제 전투 보스, 회피 보스 미등장, 유일 id,
  캐리오버 2회 관통, 시드 비영점) + 타워 회귀 세트 + `-Paths` 경고 + 헤드리스 +
  Vulkan 캡처 2장 이상(서로 다른 보스를 고른 두 경로의 실제 전투 화면) +
  `run_tower_mode.ps1` 실플레이 재현.
- 신규 씰은 `.github/workflows/godot-ci.yml`과
  `godot/tools/run_pre_push_checks.ps1` **두 리터럴 목록에 동시 등재**한다.
  현재 탑 계열 스모크는 focused 목록에 0건이라 등재하지 않으면 회귀가 그대로
  통과한다.
- 각 어서션은 "이것이 실패하려면 코드가 어떻게 망가져야 하는가"에 답할 수
  있어야 한다. 답이 "파일이 안 열려야 한다"면 그 레그는 공허하다.
- 판정 불가 지점이 나오면 중단·보고.

**완료 선언 조건**: §2의 6항목 구현·검증 + 게이트 blocked/unverified 0건 +
보고서 완성.
